# 🧩 Problem #2958 - Length of Longest Subarray With at Most K Frequency

**Difficulty:** Medium  
**Topics:** `Sliding Window`, `Hash Map`     
**Link:** https://leetcode.com/problems/length-of-longest-subarray-with-at-most-k-frequency/.   

---

## 💡 Intuition

We need the **longest contiguous subarray** where every number appears at most `k` times.

The key observation is:

> We can continuously **expand the window** until adding an element makes the window invalid. Then we **contract the window** until it becomes valid again.

This gives us a very natural sliding-window process:

```text
Expand window
      ↓
Condition fails
      ↓
Contract window
      ↓
Condition becomes valid
      ↓
Expand again
```

We maintain the frequency of every number currently inside the window.

## 🚀 Evolution of Thought Process

### Brute Force

We could generate every subarray:

```text
[0...0]
[0...1]
[0...2]
...

[1...1]
[1...2]
...
```

There are

```text
O(n²)
```

possible subarrays.

For every subarray, we would need to count frequencies.

Too expensive for:

```text
n = 10⁵
```

---

### Observation

We are looking for a **contiguous** range.

Therefore, instead of rebuilding every subarray from scratch, maintain a window:

```text
[left ........ right]
```

Expand it while it is valid.

When it becomes invalid, contract it.

```text
Expand
   ↓
Invalid
   ↓
Contract
   ↓
Valid
   ↓
Expand
```

## 🔍 Key Observation

Suppose the current window is valid:

```text
[1,2,3,1,2]
```

and:

```text
k = 2
```

Frequencies:

```text
1 → 2
2 → 2
3 → 1
```

Everything is valid.

Now expand:

```text
[1,2,3,1,2,3]
```

Still valid:

```text
1 → 2
2 → 2
3 → 2
```

Expand again:

```text
[1,2,3,1,2,3,1]
```

Now:

```text
1 → 3 ❌
```

The window is invalid.

So we contract from the left until:

```text
frequency[1] <= 2
```

The important idea is:

> We don't need to restart the search. We only move the left boundary forward.

## 🧠 The Sliding Window Strategy

Maintain:

```text
leftIndex
rightIndex
frequency map
longestGoodSubArray
```

### Phase 1 — Expand

Move `rightIndex` forward.

For every new number:

```text
frequency[number]++
```

If its frequency becomes:

```text
> k
```

the window becomes invalid.

Remember which number caused the overflow.

---

### Phase 2 — Contract

Move `leftIndex` forward.

For every removed number:

```text
frequency[number]--
```

Continue until the overflowing number becomes valid again.

Then the window is valid and we can continue expanding.

---

## 🧠 Why Only the New Number Can Cause the Violation

This is an important optimization.

Before expanding the window, we know:

```text
Current window is valid.
```

When we add:

```text
nums[rightIndex]
```

only one frequency changes.

Therefore, the only possible violation is:

```text
frequency[nums[rightIndex]] > k
```

We don't need to scan every number in the window.

## ✅ Solution

This implementation deliberately keeps the **expand → fail → contract** structure.

```ts
function maxSubarrayLength(nums: number[], k: number): number {
    let longestGoodSubArray = 0;

    let leftIndex = 0;
    let rightIndex = 0;

    const frequency = new Map<number, number>();

    // Expand the window until adding an element
    // makes the frequency condition invalid.
    while (rightIndex < nums.length) {

        let overFlowNum: number | null = null;

        // -------------------------
        // EXPAND WINDOW
        // -------------------------
        while (rightIndex < nums.length) {
            const num = nums[rightIndex];

            const count = (frequency.get(num) ?? 0) + 1;
            frequency.set(num, count);

            rightIndex++;

            // The newly added number violated
            // the frequency constraint.
            if (count > k) {
                overFlowNum = num;
                break;
            }

            const windowSize = rightIndex - leftIndex;

            longestGoodSubArray = Math.max(
                longestGoodSubArray,
                windowSize
            );
        }

        // -------------------------
        // CONTRACT WINDOW
        // -------------------------
        if (overFlowNum !== null) {
            while (leftIndex < rightIndex) {
                const num = nums[leftIndex];

                const count = frequency.get(num)! - 1;
                frequency.set(num, count);

                leftIndex++;

                // The overflowing number is valid again.
                if (
                    num === overFlowNum &&
                    count <= k
                ) {
                    break;
                }
            }

            const windowSize = rightIndex - leftIndex;

            longestGoodSubArray = Math.max(
                longestGoodSubArray,
                windowSize
            );
        }
    }

    return longestGoodSubArray;
}
```

---

## ⚖️ Why It Works

At every moment, the window represents a contiguous subarray.

### During expansion

We keep adding elements until:

```text
frequency[x] > k
```

This tells us the window has become invalid.

---

### During contraction

We remove elements from the left.

Because we remove elements in their original order, eventually the frequency of the overflowing number decreases back to:

```text
<= k
```

At that point the window is valid again.

---

### Why we never miss the answer

When the window becomes invalid, every window with the same right boundary and a smaller left boundary is also invalid.

Therefore, there is no reason to consider those windows.

We move `leftIndex` forward until the window becomes valid.

Then we continue expanding.

This allows both pointers to move only forward.

---

# ⏱️ Complexity Analysis

Let:

```text
n = nums.length
```

### Time

`rightIndex` moves from:

```text
0 → n
```

at most once.

`leftIndex` also moves from:

```text
0 → n
```

at most once.

Therefore:

```text
O(n + n)
```

which simplifies to:

```text
O(n)
```

The nested loops do **not** make this `O(n²)`.

This is the classic **amortized O(n)** property of sliding windows.

---

### Space

The frequency map can contain at most `n` distinct values.

```text
O(n)
```

### 4. Nested While Loops Can Still Be O(n)

This:

```ts
while (right < n) {
    while (...) {
        right++;
    }

    while (...) {
        left++;
    }
}
```

does **not** automatically mean:

```text
O(n²)
```

because both pointers only move forward.

Across the entire algorithm:

```text
right moves ≤ n times
left moves ≤ n times
```

Therefore:

```text
O(n)
```

| Pattern | Trigger Keywords | When to Use | When NOT to Use | Complexity | Notes |

| Expand → Contract Sliding Window | Longest/shortest subarray, contiguous, at most, frequency constraint | Window validity can be restored by moving left | Condition cannot be repaired by removing from the left | **O(n)** | Both pointers move only forward |
