# 🧩 Problem #1658 – Minimum Operations to Reduce X to Zero

**Difficulty:** Medium  
**Topics:** `Array`, `Sliding Window`, `Prefix`, `Two Pointers`    
**Link:** https://leetcode.com/problems/minimum-operations-to-reduce-x-to-zero/

---

## 📝 Problem Summary

Given an array `nums` and an integer `x`, in one operation we can remove either the leftmost or rightmost element and subtract its value from `x`.

Return the minimum number of operations needed to make `x` exactly `0`.

If it is impossible, return `-1`.

---

## 💡 Core Insight

The first instinct is to think about the elements we **remove**.

Every operation gives us two choices:

- remove from the left
- remove from the right

This naturally leads to recursion/DFS, but that creates an exponential number of possibilities.

The key observation is:

> If we remove elements whose sum is `x`, the elements that remain must form one contiguous subarray.

Let:

    total = sum(nums)

If the removed elements sum to `x`, then the remaining elements sum to:

    total - x

So instead of finding the minimum number of elements to **remove**, we can find the maximum number of elements to **keep**.

Then:

    minimum operations = n - maximum length of subarray with sum = total - x

Because all `nums[i]` are positive, a sliding window can find this longest subarray in `O(n)`.

---

## 🎯 Pattern Recognition

This problem initially looks like a:

    Prefix + Suffix / Recursion

problem because we can only remove elements from the two ends.

But there is a useful transformation:

    Remove prefix + suffix
              ↓
       Keep the middle
              ↓
    Remaining elements form
      one contiguous subarray

Then:

    Remove sum = x
    Total sum = total

Therefore:

    Keep sum = total - x

The problem becomes:

> Find the longest contiguous subarray whose sum is `total - x`.

This is a classic **positive numbers + exact subarray sum → sliding window** pattern.

The positivity of `nums[i]` is important.

Because every value is positive:

- if the current sum is too small → expand the window
- if the current sum is too large → shrink the window

## 🚀 Evolution of Thought Process

### Step 1 — My Initial DFS

The first solution directly followed the problem statement.

At every index, there are two choices:

    Remove left
    Remove right

So the recursion looks like:

    DFS
    ├── remove left
    │   ├── remove left
    │   └── remove right
    │
    └── remove right
        ├── remove left
        └── remove right

This explores a huge number of possible removal sequences.

The approach is conceptually correct, but it gives TLE because the number of possibilities grows exponentially.

---

### Step 2 — Hint Changed the Perspective

The LeetCode hint suggested binary search.

Instead of immediately following binary search, I noticed that the problem could be represented using a possible range of prefix/suffix removals.

My idea was to treat:

    suffix + prefix

as a conceptual circular range and use a sliding window to find the shortest range whose sum is `x`.

This gave an `O(n)` solution.

The important observation was:

> Since all values are positive, I can use a sliding window to find the required sum.

---

### Step 3 — Cleaner Formulation

Although the circular-window solution works, there is a simpler mathematical transformation.

Suppose:

    nums = [1, 1, 4, 2, 3]
    x = 5

Total:

    total = 11

If we remove:

    2 + 3 = 5

then the remaining array is:

    [1, 1, 4]

whose sum is:

    11 - 5 = 6

So instead of asking:

    "What is the shortest prefix + suffix whose sum is x?"

we can ask:

    "What is the longest contiguous subarray whose sum is total - x?"

For the example:

    target = total - x
           = 11 - 5
           = 6

The longest subarray with sum `6` is:

    [1, 1, 4]

Its length is `3`.

Therefore:

    operations = n - 3
               = 5 - 3
               = 2

## 🔍 Detailed Reasoning

Let:

    n = nums.length
    total = sum(nums)

We need to remove elements summing to:

    x

Therefore the elements left behind must sum to:

    total - x

Because we can only remove from the left and right, whatever remains must be contiguous.

For example:

    [a, b, c, d, e]

If we remove:

    a, b       from the left
    e          from the right

then the remaining elements are:

    [c, d]

So the remaining elements always form a contiguous subarray.

Now suppose that subarray has length `k`.

We keep `k` elements, so we remove:

    n - k

elements.

Therefore, to minimize the number of operations, we need to maximize `k`.

So:

    Find longest subarray with sum = total - x

Then:

    answer = n - longestSubarrayLength

## 🧩 Approach 1 — My Original DFS

### Idea

At every step, try both possible operations:

1. Remove the leftmost element.
2. Remove the rightmost element.

Return the minimum valid number of operations.

### Code

```ts

function minOperations(nums: number[], x: number): number {
    const n = nums.length;

    function DFS(
        firstIndex: number,
        lastIndex: number,
        total: number,
        operation: number
    ): number {
        if (lastIndex < firstIndex || total <= 0) {
            return total === 0 ? operation : -1;
        }

        const first = nums[firstIndex];
        const last = nums[lastIndex];

        const front = DFS(
            firstIndex + 1,
            lastIndex,
            total - first,
            operation + 1
        );

        const back = DFS(
            firstIndex,
            lastIndex - 1,
            total - last,
            operation + 1
        );

        if (front > -1 && back > -1) {
            return Math.min(front, back);
        } else if (front > -1) {
            return front;
        } else if (back > -1) {
            return back;
        }

        return -1;
    }

    return DFS(0, n - 1, x, 0);
}

```

### Complexity

**Time:** `O(2^n)`

At every operation we potentially branch into two recursive calls.

**Space:** `O(n)`

The maximum recursion depth is `n`.

### Result

Correct idea, but TLE because the search space is exponential.

## 🧩 Approach 2 — My Sliding Window Formulation

### Idea

Instead of directly finding the remaining subarray, I considered the elements being removed:

    suffix + prefix

I treated this possible removal range conceptually as a circular range and searched for the shortest window whose sum equals `x`.

Because all numbers are positive, a sliding window works.

This produces an `O(n)` solution.

### Important Observation

The pointers only move forward.

Even though there are nested `while` loops, this is not `O(n²)`.

The total movement is:

    left pointer  → O(n)
    right pointer → O(n)

Therefore:

    O(n) + O(n) = O(n)

### Complexity

**Time:** `O(n)`

**Space:** `O(1)`

### Tradeoff

The approach is valid, but the circular indexing and boundary calculations make the correctness harder to see.

The next formulation expresses the same underlying idea much more simply.

## 🧩 Approach 3 — Improved Sliding Window

### Idea

Transform the problem:

    Minimum removed
            ↓
    Maximum remaining

Calculate:

    target = total - x

Then find the longest contiguous subarray whose sum equals `target`.

Finally:

    answer = n - longestLength

### TypeScript

```ts

function minOperations(nums: number[], x: number): number {
    const n = nums.length;

    const total = nums.reduce((sum, num) => sum + num, 0);
    const target = total - x;

    // If target is negative, even removing the entire array
    // cannot reduce x to zero.
    if (target < 0) return -1;

    let left = 0;
    let sum = 0;
    let longestLength = -1;

    for (let right = 0; right < n; right++) {
        sum += nums[right];

        while (sum > target) {
            sum -= nums[left];
            left++;
        }

        if (sum === target) {
            longestLength = Math.max(
                longestLength,
                right - left + 1
            );
        }
    }

    return longestLength === -1
        ? -1
        : n - longestLength;
}

```

### Why `target === 0` works naturally

If:

    total - x = 0

then we are looking for the longest subarray with sum `0`.

But every `nums[i] > 0`.

Therefore, the only possible zero-sum subarray is the empty subarray.

Conceptually, this means:

    remove the entire array

and the answer is:

    n

In the implementation, this case is handled naturally by the sliding-window flow rather than requiring a separate special-case calculation.

This is similar to my original solution where I also allowed this case to be calculated as part of the flow rather than handling it separately.

---

## ⚖️ Correctness

Let the longest valid remaining subarray have length `k`.

Its sum is:

    total - x

Therefore the elements outside this subarray have sum:

    total - (total - x)
    = x

Those outside elements consist exactly of:

    prefix + suffix

So they can all be removed using:

    n - k

operations.

Any valid solution that uses `m` operations leaves:

    n - m

elements.

Those remaining elements form a contiguous subarray whose sum is:

    total - x

Therefore:

    n - m <= longestLength

which means:

    m >= n - longestLength

Our solution removes exactly:

    n - longestLength

elements.

Therefore this is the minimum possible number of operations.

---

## ⏱️ Complexity Analysis

**Time:** `O(n)`

The right pointer moves from left to right once.

The left pointer also moves from left to right at most `n` times.

Therefore the total pointer movement is:

    O(n) + O(n) = O(n)

**Space:** `O(1)`

Only a few variables are used.

## 🏆 Key Takeaways

1. A problem that asks what to **remove** may become easier if we think about what should **remain**.

2. Removing only from the two ends means the remaining elements form a **contiguous subarray**.

3. Therefore:

       remove sum = x

   becomes:

       remaining sum = total - x

4. Minimizing removed elements is equivalent to maximizing remaining elements:

       min operations
              ↓
       max subarray length

5. Positive numbers are what make the sliding-window approach possible.

6. Nested `while` loops do not automatically mean `O(n²)`. Count total pointer movement.

7. My circular sliding-window solution was valid, but the `total - x` transformation produces a simpler and easier-to-prove implementation.

8. When a hint suggests one technique such as binary search, don't assume it is the only valid route. The important part is understanding the property that makes the problem solvable.

## 📚 Pattern Learned

### "Remove From Ends → Keep Contiguous Subarray"

When a problem allows removing elements only from the beginning and/or end:

    [ prefix ][ remaining ][ suffix ]

The remaining portion is contiguous.

If the problem asks to optimize the number of removed elements, consider transforming it into an optimization over the remaining subarray.

For this problem:

    Minimize removed
            ↓
    Maximize remaining
            ↓
    Find longest subarray with target sum

With positive numbers:

    exact sum + longest subarray
            ↓
       Sliding Window
