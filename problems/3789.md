
# 🧩 Problem #3789 – Minimum Cost to Acquire Required Items

**Difficulty:** Medium  
**Topics:** `Greedy`, `Math`         
**Link:** https://leetcode.com/problems/minimum-cost-to-acquire-required-items/

---

## 📝 Problem Summary

We have three types of items:

- Type 1: Costs `cost1`, contributes 1 to requirement 1.
- Type 2: Costs `cost2`, contributes 1 to requirement 2.
- Type 3: Costs `costBoth`, contributes 1 to BOTH requirements.

We need to fulfil at least `need1` and `need2` at minimum cost.

The interesting part is that buying type 3 items can over-fulfil one requirement. This is allowed.

---

## 💡 Core Insight

Instead of deciding item by item, think about how many type 3 items we should purchase.

Let:

- `x` = number of type 3 items purchased.
- `need1 - x` = remaining type 1 requirement.
- `need2 - x` = remaining type 2 requirement.

Since requirements cannot become negative, the remaining requirements are:

`max(0, need1 - x)` and `max(0, need2 - x)`.

The total cost becomes:

<Quote start>
totalCost =
    x * costBoth
    + max(0, need1 - x) * cost1
    + max(0, need2 - x) * cost2
<Quote end>

We could try every possible value of x, but that is unnecessary.

The cost function is piecewise linear, so we only need to evaluate its important breakpoints.

---

## 🎯 Pattern Recognition

This problem initially looks like DP because every purchase gives us three choices.

However, there is no need to maintain DP states.

The key observation:

The total cost changes linearly in three regions:

1. Before the smaller requirement is fulfilled.
2. Between the smaller and larger requirements.
3. After both requirements are fulfilled.

A linear function achieves its minimum at an endpoint.

Therefore, we only need three candidates:

- `x = 0`
- `x = min(need1, need2)`
- `x = max(need1, need2)`

This reduces the problem to O(1).

## 🚀 Evolution of Thought Process

### Initial intuition

Initially, I thought this was a DP problem because at every purchase we have three choices:

- Buy type 1.
- Buy type 2.
- Buy type 3.

### First observation

A type 3 item contributes to both requirements.

Therefore, it can be beneficial when its cost is lower than purchasing the corresponding individual items.

### Initial mistake

I tried to make local decisions using:

`costBoth / 2`

This was incorrect because the value of a shared item depends on which requirements are still unfulfilled.

A shared item cannot be evaluated independently using half its price.

### Improved reasoning

Instead of making local decisions, consider three complete purchasing strategies:

1. Buy only shared items.
2. Buy shared items for the common requirement and individual items for the remaining requirement.
3. Buy everything individually.

The minimum among these three strategies gives the optimal answer.

---

## 🔍 Detailed Reasoning

Define:

`minNeed = min(need1, need2)`

`maxNeed = max(need1, need2)`

`maxNeedCost` = cost of the individual item corresponding to the larger requirement.

### Possibility 1 — Buy only type 3 items

Buy enough type 3 items to fulfil the larger requirement.

Even if this over-fulfils the smaller requirement, it is valid.

```ts
possibility1 = costBoth * maxNeed
```

### Possibility 2 — Buy type 3 for the common requirement

Buy `minNeed` type 3 items.

This fulfils the smaller requirement completely.

For the larger requirement, purchase the remaining individual items.

```ts
possibility2 =
    costBoth * minNeed
    + (maxNeed - minNeed) * maxNeedCost
```

### Possibility 3 — Buy individual items

Do not purchase any type 3 items.

Fulfil both requirements independently.

```ts
possibility3 =
    need1 * cost1
    + need2 * cost2
```

### Final answer

Return the minimum among all three possibilities.

```ts
answer = min(possibility1, possibility2, possibility3)
```

## 🧩 Approach 1 — My Greedy Solution

```ts
function minimumCost(
    cost1: number,
    cost2: number,
    costBoth: number,
    need1: number,
    need2: number
): number {
    const minNeed = Math.min(need1, need2);
    const maxNeed = Math.max(need1, need2);

    const maxNeedCost = need1 === maxNeed ? cost1 : cost2;

    const possibility1 = costBoth * maxNeed;

    const possibility2 =
        costBoth * minNeed +
        (maxNeed - minNeed) * maxNeedCost;

    const possibility3 =
        need1 * cost1 +
        need2 * cost2;

    return Math.min(
        possibility1,
        possibility2,
        possibility3
    );
}
```

### Complexity Analysis

**Time:** O(1)

Only a constant number of calculations and comparisons.

**Space:** O(1)

Only a constant number of variables are used.

## ⚖️ Correctness

Let `x` be the number of type 3 items purchased.

We never need more than `max(need1, need2)` shared items because buying additional items cannot reduce the cost.

The cost function is:

```ts
f(x) =
    x * costBoth
    + max(0, need1 - x) * cost1
    + max(0, need2 - x) * cost2
```

There are three intervals:

1. From 0 to minNeed, both individual requirements remain.
2. From minNeed to maxNeed, only the larger requirement remains.
3. Beyond maxNeed, additional shared items only increase the cost.

Within each of the first two intervals, the cost is linear.

Therefore, its minimum must occur at one of the interval endpoints.

The relevant endpoints are:

- 0
- minNeed
- maxNeed

Our algorithm evaluates all three candidates and returns their minimum.

Hence, the algorithm always finds the optimal cost.

---

## 🏆 Key Takeaways

1. Not every problem with multiple choices requires DP.
2. Avoid making local greedy decisions when the value of an action depends on the remaining requirements.
3. Look for a mathematical expression representing the total cost.
4. Piecewise linear functions can often be optimized by checking their breakpoints.
5. Over-fulfilling a requirement can be cheaper than fulfilling requirements exactly.

---

## 📚 Pattern Learned

**Greedy Optimization Using Piecewise Linear Functions**

When a problem asks for the minimum cost and the cost changes linearly across different regions, identify the breakpoints.

Instead of iterating through every possible choice, evaluate the endpoints of those regions.
