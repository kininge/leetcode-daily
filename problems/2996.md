# 🧩 Problem #2996 - Smallest Missing Integer Greater Than Sequential Prefix Sum

**Difficulty:** Easy  
**Topics:** `Array`, `Hash Map`, `Prefix`, `Simulation`  
**Link:** https://leetcode.com/problems/smallest-missing-integer-greater-than-sequential-prefix-sum/   

---

## 💡 Intuition

The problem looks confusing because it combines **two different tasks**.

### Task 1

Find the **longest sequential prefix**.

A prefix always starts at index `0`.

For example:

```text
[3,4,5,1,12,14,13]
 ↑─────↑
```

The longest sequential prefix is:

```text
[3,4,5]
```

because:

```text
3 → 4  ✅
4 → 5  ✅
5 → 1  ❌
```

Then calculate its sum:

```text
3 + 4 + 5 = 12
```

### Task 2

Starting from that sum, find the smallest number that does **not** exist anywhere in the original array.

```text
12 → exists
13 → exists
14 → exists
15 → missing
```

Therefore:

```text
answer = 15
```

## 🔍 Key Observation

There are **two different ranges** involved.

### Range 1 — Sequential Prefix

This always starts from:

```text
index = 0
```

and continues while:

```text
nums[i] = nums[i-1] + 1
```

The moment this condition fails, the sequential prefix ends permanently.

---

### Range 2 — Missing Number Search

After finding the sum, we search the **entire original array**.

For example:

```text
nums = [3,4,5,1,12,14,13]
```

Sequential prefix:

```text
[3,4,5]
```

Sum:

```text
12
```

Now search:

```text
12
13
14
15
```

We must check against the entire array, not just the prefix.

## ❌ Important Clarification

A later sequential section does **not** count.

For example:

```text
[1,2,3,8,9,10]
```

The sequence

```text
8,9,10
```

is sequential.

But the problem asks for the **longest sequential prefix**.

Therefore:

```text
Longest sequential prefix = [1,2,3]
```

not

```text
[8,9,10]
```

## ✅ Solution

```ts
function missingInteger(nums: number[]): number {
    const allNums = new Set<number>();

    allNums.add(nums[0]);

    let sum = nums[0];
    let isSequenceBroken = false;

    for (let i = 1; i < nums.length; i++) {
        if (
            !isSequenceBroken &&
            nums[i - 1] + 1 === nums[i]
        ) {
            sum += nums[i];
        } else {
            isSequenceBroken = true;
        }

        allNums.add(nums[i]);
    }

    // Find the smallest missing integer >= sum.
    while (allNums.has(sum)) {
        sum++;
    }

    return sum;
}
```

---

## ⚖️ Why It Works

The first loop simultaneously performs two jobs:

### 1. Find the sequential prefix sum

We only add `nums[i]` while the prefix remains sequential.

Once:

```text
nums[i] !== nums[i-1] + 1
```

we mark the sequence as broken.

---

### 2. Store every number

Regardless of whether the sequence has already broken:

```ts
allNums.add(nums[i]);
```

This is necessary because the final search considers the **entire array**.

---

### Final Search

Starting from `sum`:

```ts
while (allNums.has(sum)) {
    sum++;
}
```

The first number not present in the Set is exactly the smallest missing integer greater than or equal to the sequential prefix sum.

## ⏱ Complexity Analysis

Let:

```text

```

### Time

Building the Set and finding the prefix:

```text

```

The final search may move forward through values present in the array.

Since the array contains at most `n` unique values, the total work remains:

```text
O(n)
```

Overall:

```text
O(n)
```

---

### Space

HashSet stores all values:

```text
O(n)
```

Therefore:

```text
Space = O(n)
```

# 🔄 Alternative Approach — Sorting

Because the constraints are tiny, we could also sort the array.

For example:

```text
nums = [3,4,5,1,12,14,13]
```

Sort:

```text
[1,3,4,5,12,13,14]
```

We still need the original order to determine the sequential prefix, so we would have to calculate the prefix sum **before sorting**.

Then after sorting, we can find the first missing number.

For example:

```text
sum = 12

sorted = [1,3,4,5,12,13,14]
```

Check:

```text
12 → exists
13 → exists
14 → exists
15 → missing
```

Answer:

```text
15
```

### Complexity

Sorting:

```text
O(n log n)
```

Scanning:

```text
O(n)
```

Total:

```text
O(n log n)
```

This is worse than the HashSet solution.

# 🔄 Alternative Approach — Boolean Array

Because the constraints say:

```text
1 <= nums[i] <= 50
```

we could use a boolean array.

```ts
const seen = new Array(101).fill(false);
```

Mark:

```ts
seen[num] = true;
```

Then:

```ts
while (seen[sum]) {
    sum++;
}
```

### Complexity

Time:

```text
O(n)
```

Space:

```text
O(1)
```

because the array size is bounded by the constraints.

However, this solution depends on the small value constraint.

The `Set` solution is more general.

# ⚖️ HashSet vs Boolean Array

| Approach | Time | Space | Generality |
|----------|------|-------|------------|
| **HashSet** | O(n) | O(n) | ⭐ High |
| **Boolean Array** | O(n) | O(1) | Constraint-dependent |
| **Sorting** | O(n log n) | Depends on sort | General |

For this problem, I prefer the **HashSet** because it directly expresses the operation we need:

```text
"Does this number exist?"
```

## 🏆 Key Takeaways

### 1. Prefix always starts at index 0

```text
Prefix = nums[0...i]
```

Never start searching for a sequential sequence somewhere in the middle.

---

### 2. Sequence breaks permanently

For:

```text
[1,2,3,7,8]
```

the longest sequential prefix is:

```text
[1,2,3]
```

Even though:

```text
7,8
```

is also sequential.

---

### 3. The final search uses the entire array

Do not confuse:

```text
Sequential Prefix
```

with:

```text
Entire nums
```

The prefix determines the **starting value** of the search.

The entire array determines whether that value is **missing**.

## 🧭 Pattern Recognition Handbook

| Pattern | Trigger Keywords | When to Use | When NOT to Use | Complexity | Notes |
|----------|------------------|-------------|-----------------|------------|-------|
| Sequential Prefix Scan | Prefix, consecutive, `nums[i] = nums[i-1] + 1` | Need longest prefix satisfying local relation | Need a sequence starting anywhere | O(n) | Prefix always begins at index 0 |
| HashSet Membership | Missing, exists, present, duplicate | Need fast existence checks | Tiny fixed range where boolean array is simpler | O(1) average lookup | General-purpose membership structure |
| Boolean Frequency Array | Values bounded by small constant | Small numeric range | Large or unknown values | O(n), O(1) space | Constraint-dependent |
| Sorting + Scan | Missing gaps, ordered values | Sorting is already useful | Only membership checking is needed | O(n log n) | Usually unnecessary here |
