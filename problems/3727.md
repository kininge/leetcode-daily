
# 🧩 Problem #3727 – Maximum Alternating Sum of Squares

**Difficulty:** Medium  
**Topics:** `Greedy`, `Sorting`, `Arrays`  
**Link:** https://leetcode.com/problems/maximum-alternating-sum-of-squares/

---

## 📝 Problem Summary

Given an integer array `nums`, rearrange its elements in any order to maximize the alternating score:

score = arr[0]² - arr[1]² + arr[2]² - arr[3]² + ...

Return the maximum possible score.

The original signs of the numbers do not matter because every element is squared.

## 💡 Core Insight

**Sort by absolute magnitude in descending order. Pair the largest remaining square with the smallest remaining square.**

The largest squares should occupy positive positions, while the smallest squares should occupy negative positions.

For example:

nums = [1, 2, 3]

Sorted by absolute magnitude:

[3, 2, 1]

Maximum score:

3² - 1² + 2² = 9 - 1 + 4 = 12

Since squaring removes the original sign, sorting by `Math.abs()` is sufficient.

## 🎯 Pattern Recognition

This problem suggests a greedy strategy because:

- Rearrangement is allowed.
- Each element contributes either positively or negatively.
- Squaring makes the original sign irrelevant.
- Assigning a larger square to a positive position rather than a negative position always improves or preserves the score.

For two squared values where a² ≥ b²:

Assignment A: +a² - b²

Assignment B: +b² - a²

The difference is:

2(a² - b²) ≥ 0

Therefore, the larger square belongs in a positive position.

## 🚀 Evolution of Thought Process

### Step 1 — Understand the alternating signs

The score is:

+x² - y² + z² - w² + ...

Positive and negative positions have different contributions.

### Step 2 — Ignore the original signs

Since:

(-x)² = x²

We can compare elements by their absolute magnitudes.

### Step 3 — Sort by descending absolute magnitude

Place the largest values first so that the largest squares are assigned positive signs.

### Step 4 — Pair the extremes

Use two pointers:

- `l` points to the largest remaining magnitude.
- `r` points to the smallest remaining magnitude.

Add the square at `l` and subtract the square at `r`.

Move both pointers inward until all elements are processed.

### Step 5 — Handle the middle element

If both pointers meet, one element remains. Its square must be added because it occupies a positive position in the alternating arrangement.

## 🔍 Detailed Reasoning

### Approach 1 — Two Pointers (My Solution)

Sort the array by descending absolute magnitude.

For every pair:

1. Add the square of the left element.
2. Subtract the square of the right element.
3. Move `l` forward and `r` backward.

If `l === r`, add the remaining square once.

This works because the sorted elements can be rearranged into alternating positions such that the largest squares receive positive signs and the smallest squares receive negative signs.

### TypeScript Code

```ts
function maxAlternatingSum(nums: number[]): number {
    // The score depends on squares, so original signs do not matter.
    nums.sort((a, b) => Math.abs(b) - Math.abs(a));

    let l = 0;
    let r = nums.length - 1;
    let ans = 0;

    while (l <= r) {
        if (l === r) {
            ans += nums[l] * nums[l];
        } else {
            ans += nums[l] * nums[l] - nums[r] * nums[r];
        }

        l++;
        r--;
    }

    return ans;
}
```

### Approach 2 — Alternating Signs (Simplified Alternative)

After sorting, the two-pointer logic is unnecessary.

We can traverse the sorted array and add or subtract each square based on its index:

- Even index → add the square.
- Odd index → subtract the square.

The largest square is positive, the second largest is negative, and so on.

### TypeScript Code

```ts
function maxAlternatingSum(nums: number[]): number {
    nums.sort((a, b) => Math.abs(b) - Math.abs(a));

    let ans = 0;

    for (let i = 0; i < nums.length; i++) {
        const square = nums[i] * nums[i];

        ans += i % 2 === 0 ? square : -square;
    }

    return ans;
}
```

**Why is Approach 2 an improvement?**

It removes:

- Two pointer variables.
- The special case for the middle element.
- Separate handling of pairs.

The code directly represents the alternating signs in the problem statement.

Both approaches have the same asymptotic complexity. The second is simpler, but neither is asymptotically faster.

## 🧪 Dry Run

Input:

nums = [1, -1, 2, -2, 3, -3]

### Step 1 — Sort by absolute magnitude

[-3, 3, -2, 2, -1, 1]

### Step 2 — Assign alternating signs

| Index | Value | Square | Contribution | Running Score |
|---|---:|---:|---:|---:|
| 0 | -3 | 9 | +9 | 9 |
| 1 | 3 | 9 | -9 | 0 |
| 2 | -2 | 4 | +4 | 4 |
| 3 | 2 | 4 | -4 | 0 |
| 4 | -1 | 1 | +1 | 1 |
| 5 | 1 | 1 | -1 | 0 |

This particular ordering is not the best way to explain the maximum score because equal absolute magnitudes cancel each other out.

A better arrangement is:

[-3, -1, -2, 1, 3, 2]

Its score is:

9 - 1 + 4 - 1 + 9 - 4 = 16

Output: 16

The important lesson is that the positive positions receive the three largest squares, while the negative positions receive the three smallest squares. The signs of the original elements are irrelevant.

## ⚖️ Correctness

Let the squared values, sorted in descending order, be:

b₁ ≥ b₂ ≥ b₃ ≥ ... ≥ bₙ ≥ 0

There are ⌈n/2⌉ positive positions and ⌊n/2⌋ negative positions.

To maximize the score:

- Assign the largest ⌈n/2⌉ squared values to positive positions.
- Assign the smallest ⌊n/2⌋ squared values to negative positions.

If a larger square were assigned to a negative position and a smaller square to a positive position, swapping them would never decrease the score. The improvement would be twice their difference.

Therefore, the optimal score is the sum of the largest squared values minus the sum of the smallest squared values.

The two-pointer approach computes exactly this difference by pairing the largest and smallest remaining values. The alternating-sign approach computes the same result by index parity.

Hence, both approaches produce the maximum possible alternating score.

## ⏱️ Complexity Analysis

Let `n` be the length of `nums`.

**Time:** O(n log n)

- Sorting takes O(n log n).
- Traversing the array takes O(n).
- Sorting dominates the overall time complexity.

**Auxiliary Space:** O(log n) typically for JavaScript's in-place array sorting implementation, due to sorting internals. The additional variables used by either algorithm require O(1) space.

Both approaches have the same complexity.

## 🏆 Key Takeaways

1. **Look at the mathematical operation first.** Squaring makes negative and positive inputs equivalent in magnitude.
2. **Greedy reasoning needs justification.** The exchange argument shows why a larger square belongs in a positive position.
3. **Sorting plus greedy assignment** is a common pattern when elements can be freely rearranged.
4. **Two pointers are not always necessary.** If the sign of each contribution depends only on index parity, a single traversal may express the solution more clearly.
5. **Prefer multiplication for squaring.** `x * x` is clearer than `Math.pow(x, 2)` for integer squares.

## 📚 Pattern Learned

**Greedy + Sorting + Sign Assignment**

When elements can be rearranged and each element receives either a positive or negative contribution:

1. Determine what property controls the contribution.
2. Sort by that property.
3. Assign the largest values to positive positions and the smallest to negative positions.
4. Use an exchange argument to prove that swapping an incorrectly assigned pair cannot hurt the result.
