# 🧩 Problem #3498 – Reverse Degree of a String

**Difficulty:** Easy    
**Topics:** String     
**Link:** https://leetcode.com/problems/reverse-degree-of-a-string/  

---

## 📝 Problem Summary

Given a lowercase English string `s`, calculate its **reverse degree**.

For every character:

1. Find its position in the **reversed alphabet**:

   * `'a'` → `26`
   * `'b'` → `25`
   * ...
   * `'z'` → `1`
2. Multiply that value by the character's **1-indexed position** in the string.
3. Sum all products.

Return the resulting reverse degree.

### Example

For `s = "abc"`:

| Character | Reverse Alphabet Value | String Position | Product |
| --------- | ---------------------- | --------------- | ------- |
| `a`       | 26                     | 1               | 26      |
| `b`       | 25                     | 2               | 50      |
| `c`       | 24                     | 3               | 72      |

Total = `26 + 50 + 72 = 148`

---

## 💡 Core Insight

The important observation is that we don't need to actually create or reverse the alphabet.

For a character, its normal zero-based alphabet index is:

`characterCode - 'a'`

So its reversed alphabet value is:

`26 - normalIndex`

For example:

`'c' → 2`

Therefore:

`26 - 2 = 24`

So the complete contribution of a character at index `i` is:

`(i + 1) * (26 - (characterCode - 97))`

---

## 🎯 Pattern Recognition

This is a simple **character mapping + weighted sum** problem.

Whenever a problem asks you to:

* convert characters into numeric values,
* apply some transformation to those values,
* multiply by position,
* and accumulate a result,

a single-pass traversal is usually enough.

There is no need for:

* sorting
* hashing
* dynamic programming
* extra arrays
* nested loops

The entire answer can be calculated while traversing the string once.

## 🚀 Evolution of Thought Process

### Step 1 — Find the reversed alphabet value

The normal alphabet is:

`a = 1, b = 2, ..., z = 26`

The reversed alphabet is:

`a = 26, b = 25, ..., z = 1`

Using a zero-based index makes this particularly simple:

`a → 0`
`b → 1`
`c → 2`
`...`
`z → 25`

Therefore:

`reverseValue = 26 - zeroBasedIndex`

---

### Step 2 — Calculate the string position

The problem uses **1-indexed** positions.

JavaScript/TypeScript loops normally use zero-based indexes:

`0, 1, 2, ...`

Therefore the string position is:

`i + 1`

---

### Step 3 — Calculate each contribution

For every character:

`contribution = (i + 1) * reverseValue`

---

### Step 4 — Accumulate

Maintain a running `total` and add each contribution.

This gives an `O(n)` solution with `O(1)` extra space.

## 🔍 Detailed Reasoning

Your implementation uses:

```txt

const code = 26 - (s.charCodeAt(i) - 97);

```

Let's break it down.

### `s.charCodeAt(i)`

Returns the ASCII/Unicode code of the character.

For lowercase English letters:

`a = 97`

`b = 98`

`c = 99`

...

`z = 122`

### `s.charCodeAt(i) - 97`

Converts the character into a zero-based alphabet index.

For example:

`a → 97 - 97 = 0`

`b → 98 - 97 = 1`

`c → 99 - 97 = 2`

`z → 122 - 97 = 25`

### `26 - index`

Converts that zero-based index into the reversed alphabet value.

For example:

`a → 26 - 0 = 26`

`b → 26 - 1 = 25`

`c → 26 - 2 = 24`

`z → 26 - 25 = 1`

Then:

```txt

total += (i + 1) * code;

```

correctly applies the character's 1-indexed position.

## 🧩 Approach 1 — My Solution

Your approach directly converts each character into its reversed alphabet value and immediately adds its weighted contribution.

```ts

function reverseDegree(s: string): number {
  let total = 0;
  
  for (let i = 0; i < s.length; i++) {
      const code = 26 - (s.charCodeAt(i) - 97);
      total += (i + 1) * code;
  }
  
  return total;
}

```

### Why this works

For every character:

1. `s.charCodeAt(i) - 97` gets its zero-based alphabet position.
2. `26 - ...` converts it to the reversed alphabet value.
3. `(i + 1)` gives the 1-indexed string position.
4. Multiplication gives that character's contribution.
5. `total` accumulates all contributions.

Nothing extra is required.

---

## ⚖️ Correctness

For every character `s[i]`, let:

`x = s[i].charCodeAt(0) - 97`

Since `a` has index `0` and `z` has index `25`, `x` represents the character's zero-based alphabet position.

Its reversed alphabet position is therefore:

`26 - x`

The problem requires this value to be multiplied by the character's 1-indexed string position:

`i + 1`

So the contribution of `s[i]` is:

`(i + 1) * (26 - x)`

The algorithm adds exactly this contribution for every character in the string.

Therefore, after processing the entire string, `total` equals the required reverse degree.

---

## ⏱️ Complexity Analysis

**Time:** `O(n)`

We visit every character exactly once.

**Space:** `O(1)`

Only `total`, `i`, and `code` are stored. No data structure grows with the input size.

## 🏆 Key Takeaways

* Don't create the reversed alphabet when a mathematical mapping is enough.
* ASCII character codes can provide a simple alphabet index.
* Convert zero-based indexes to 1-based positions with `i + 1`.
* This problem is simply a **weighted accumulation over characters**.
* A single pass is sufficient.

### Small coding improvement

The `97` in your solution is technically correct, but it is a **magic number**.

A more self-documenting version could use:

```txt

const code = 26 - (s.charCodeAt(i) - 'a'.charCodeAt(0));

```

For LeetCode, your original `97` is completely acceptable. The important thing is understanding why it works rather than memorizing the number.

## 📚 Pattern Learned

### Character Mapping + Weighted Sum

General structure:

```ts

let result = 0;

for (let i = 0; i < input.length; i++) {
  const value = transform(input[i]);
  result += value * (i + 1);
}

return result;

```

This pattern appears in problems where each element contributes a value based on both:

* the element itself
* its position

Recognizing this lets you avoid unnecessary arrays or multiple passes.
