
# 🧩 Problem #3105 – Longest Strictly Increasing or Strictly Decreasing Subarray

**Difficulty:** Easy  
**Topics:** `Array`, `Sliding Window`        
**LeetCode:** https://leetcode.com/problems/longest-strictly-increasing-or-strictly-decreasing-subarray/

## Intuition

We need to find the length of the longest contiguous subarray that is either:

- **Strictly increasing:** Every element is greater than its previous element.
- **Strictly decreasing:** Every element is smaller than its previous element.

The important observation is that we only need to compare **adjacent elements** to determine whether the current subarray is still monotonic.

For any two adjacent elements, there are three possibilities:

| Condition | Direction | Meaning |
|---|---|---|
| `nums[i] > nums[i-1]` | `1` | Increasing |
| `nums[i] < nums[i-1]` | `-1` | Decreasing |
| `nums[i] === nums[i-1]` | `0` | Equal, breaks monotonicity |

We can track the current direction and the length of the current monotonic subarray.

Whenever the direction changes, we start a new subarray of length `2`, because the previous and current elements already form a valid monotonic subarray.

If two adjacent elements are equal, we reset the length to `1`, because strict monotonicity does not allow equal elements.

## Approach: One Pass with Direction Tracking

We maintain three variables:

- `maxLen`: Maximum monotonic subarray length found so far.
- `count`: Length of the current monotonic subarray.
- `direction`: Direction of the current subarray (`1`, `-1`, or `0`).

### Algorithm

1. Initialize `maxLen = 1`, `count = 1`, and `direction = 0`.
2. Traverse the array starting from index `1`.
3. Compare the current element with the previous element to determine `currentDirection`.
4. Based on the direction:
   - **Equal elements (`0`):** Reset `count = 1` and `direction = 0`.
   - **Same direction or no previous direction:** Increment `count` and update `direction`.
   - **Direction changed:** Reset `count = 2` and update `direction`.
5. Update `maxLen` after each iteration.
6. Return `maxLen`.

### Why reset count to 2 when direction changes?

Consider:

```txt
nums = [1, 4, 3, 2]

Increasing: [1, 4]       Length = 2
Decreasing:    [4, 3, 2] Length = 3
```

When we reach `3`, the direction changes from increasing to decreasing.

However, `[4, 3]` is already a valid decreasing subarray.

Therefore, we reset `count = 2`, not `1`.

### Why reset count to 1 for equal elements?

Consider:

```txt
nums = [1, 2, 2, 3]

[1, 2] → Increasing, length = 2
[2, 2] → Equal, breaks monotonicity
[2, 3] → Increasing, length = 2
```

Equal adjacent elements cannot belong to the same strictly monotonic subarray.

Therefore, we reset `count = 1` and `direction = 0`.

## Dry Run

**Input:**

```txt
nums = [1, 4, 3, 3, 2]
```

**Initial state:**

```txt
maxLen = 1
count = 1
direction = 0
```

| i | Comparison | currentDirection | count | direction | maxLen |
|---|---|---|---|---|---|
| 1 | 1 < 4 | 1 | 2 | 1 | 2 |
| 2 | 4 > 3 | -1 | 2 | -1 | 2 |
| 3 | 3 = 3 | 0 | 1 | 0 | 2 |
| 4 | 3 > 2 | -1 | 2 | -1 | 2 |

**Output:** `2`

The longest strictly monotonic subarrays have length `2`.

## Complexity Analysis

### Time Complexity: O(n)

We traverse the array exactly once.

Each iteration performs a constant number of comparisons and updates.

Therefore, the total time complexity is **O(n)**.

### Space Complexity: O(1)

We only use three variables:

- `maxLen`
- `count`
- `direction`

No additional data structures are required.

Therefore, the auxiliary space complexity is **O(1)**.

## Code (TypeScript)

```ts
function longestMonotonicSubarray(nums: number[]): number {
    let maxLen = 1;
    let count = 1;
    let direction = 0;

    for (let i = 1; i < nums.length; i++) {
        const currentDirection =
            nums[i] > nums[i - 1] ? 1 :
            nums[i] < nums[i - 1] ? -1 : 0;

        if (currentDirection === 0) {
            // Equal elements break strict monotonicity
            count = 1;
            direction = 0;
        } else if (
            direction === 0 ||
            direction === currentDirection
        ) {
            // Start or continue the current direction
            count++;
            direction = currentDirection;
        } else {
            // Direction changed: previous and current
            // elements form a new subarray of length 2
            count = 2;
            direction = currentDirection;
        }

        maxLen = Math.max(maxLen, count);
    }

    return maxLen;
}
```

## Key Takeaways

1. **Adjacent comparisons are sufficient:** We don't need to generate every possible subarray.

2. **Direction tracking simplifies the problem:** Represent increasing, decreasing, and equal comparisons using `1`, `-1`, and `0`.

3. **Direction changes preserve overlap:** When the direction changes, the previous and current elements form a new valid subarray of length `2`.

4. **Equal elements break strict monotonicity:** Reset the current length to `1`.

5. **Update the maximum during every iteration:** This avoids special handling for the last element.

6. **One-pass optimization:** The problem can be solved in O(n) time and O(1) auxiliary space.
