# 🧩 Problem #3016 - Minimum Number of Pushes to Type Word II

**Difficulty:** Medium.      
**Topics:** `Greedy`, `Hash Map`, `Sorting`.    
**Link:** https://leetcode.com/problems/minimum-number-of-pushes-to-type-word-ii/.    

---

# 💡 Intuition

Unlike **3014. Minimum Number of Pushes to Type Word I**, characters are **not distinct**.

Some letters appear many times while others appear only once.

Since every occurrence of a letter uses the same key mapping, assigning a frequently occurring letter to an expensive position increases the total cost significantly.

Therefore, the most frequent letters should occupy the **cheapest positions**.

# 🧠 Why Greedy Works (Exchange Argument)

Suppose two letters have frequencies

```text id="hdzhlt"
10

5
```

Suppose we assign

```text id="52d33n"
10 → cost 2

5 → cost 1
```

Total cost

```text id="wqucp7"
10 × 2 + 5 × 1

= 25
```

Now swap them.

```text id="g6bx3p"
10 → cost 1

5 → cost 2
```

New cost

```text id="v9b6t9"
10 × 1 + 5 × 2

= 20
```

The total cost becomes smaller.

Therefore,

placing a higher frequency letter in a more expensive position can never be optimal.

Repeating this argument proves that:

* highest frequencies should receive the smallest push counts,
* second highest frequencies receive the next cheapest positions,
* and so on.

# 🧠 Attempt 1 — Frequency Counting + Greedy (Accepted)

## Idea

1. Count the frequency of every character.
2. Sort frequencies in descending order.
3. Assign push costs:

   * indices `0...7` → 1 push
   * indices `8...15` → 2 pushes
   * indices `16...23` → 3 pushes
   * indices `24...25` → 4 pushes
4. Multiply each frequency by its assigned push count.

---

## Your Solution

```ts id="8v6cwh"
function minimumPushes(word: string): number {
    const laters = new Array(26).fill(0);

    // Count frequencies
    for (const char of word) {
        const index = char.charCodeAt(0) - 97;
        laters[index]++;
    }

    // Highest frequencies first
    laters.sort((a, b) => b - a);

    let count = 0;

    for (let i = 0; i < 26; i++) {
        if (laters[i] === 0) break;

        const clicks = Math.floor(i / 8) + 1;
        count += laters[i] * clicks;
    }

    return count;
}
```

# ✅ Why it Works

The keypad provides positions with increasing costs.

Every occurrence of a letter contributes equally to the total cost.

Assigning a high-frequency letter to an expensive position increases the total cost more than assigning a low-frequency letter there.

Therefore, the optimal strategy is:

1. Count character frequencies.
2. Sort them from highest to lowest.
3. Fill the cheapest available positions first.

No other assignment can produce a smaller total cost.

---

# ⚖️ Mathematical Insight

This problem minimizes the weighted sum

```text id="xgzbyw"
Σ (frequency × pushCost)
```

The minimum is achieved by pairing

* the **largest frequencies**
* with the **smallest push costs**.

This is an application of the **Rearrangement Inequality**, although knowing the theorem is not necessary to derive the greedy solution.

# 🏆 Key Takeaways

* Ignore the actual keypad layout and think in terms of **cost slots**.
* Frequency determines the importance (weight) of each letter.
* To minimize the weighted sum, assign the highest frequencies to the cheapest positions.
* Sorting only 26 frequencies is effectively constant time.
* Many greedy assignment problems can be justified using an **exchange argument**.

# 📚 Pattern Learned

| Pattern                         | Trigger Keywords                     | When to Use                                                        | When NOT to Use                                  | Complexity | Notes                                                                                   |
| ------------------------------- | ------------------------------------ | ------------------------------------------------------------------ | ------------------------------------------------ | ---------- | --------------------------------------------------------------------------------------- |
| **Greedy Assignment by Weight** | Frequency, weighted cost, assignment | Items have different importance and positions have different costs | Costs depend on previous choices or interactions | `O(n)`     | Pair the largest weights with the cheapest positions.                                   |
| **Exchange Argument**           | Greedy proof                         | Proving a greedy strategy                                          | Dynamic programming or graph dependencies        | —          | Show that swapping an expensive assignment with a cheaper one never increases the cost. |
| **Frequency Counting**          | Characters, lowercase letters        | Fixed alphabet problems                                            | Large or arbitrary alphabets (use a hash map)    | `O(n)`     | Count first, then reason about frequencies instead of individual characters.            |

# 🧭 Decision Handbook

| Situation                                | Recommended Approach                  | Reason                                      |
| ---------------------------------------- | ------------------------------------- | ------------------------------------------- |
| All items have equal weight              | Fill cheapest slots directly          | Every assignment has equal impact           |
| Items have different frequencies/weights | Sort by frequency and assign greedily | Larger weights should receive smaller costs |
| Fixed lowercase alphabet                 | Frequency array of size 26            | Faster and simpler than a hash map          |
