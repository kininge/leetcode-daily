# 🧩 Problem #3364 – Minimum Positive Sum Subarray

**Difficulty:** Easy  
**Topics:** `Array`, `Prefix Sum`    
**Link:** https://leetcode.com/problems/minimum-positive-sum-subarray/

---

## 📝 Problem Summary

Given an integer array `nums` and two integers `l` and `r`, find the minimum positive sum among all contiguous subarrays whose lengths are between `l` and `r` (inclusive).

Return `-1` if no valid positive-sum subarray exists.

## 💡 Core Insight

We need to calculate the sum of every subarray whose length belongs to `[l, r]`.

Calculating each subarray sum by iterating through its elements would be inefficient.

Instead, use **Prefix Sum**.

For a prefix sum array:

`prefix[i]` represents the sum of elements from index `0` to `i`.

The sum of a subarray `[start...end]` becomes:

```txt
sum = prefix[end] - prefix[start - 1]
```

When `start === 0`, the previous prefix sum is considered `0`.

This allows us to calculate any subarray sum in O(1).

## 🎯 Pattern Recognition

Look for Prefix Sum when:

- You need to calculate sums of contiguous subarrays.
- Multiple range-sum calculations are required.
- Recalculating the sum of each range would introduce unnecessary work.

The additional constraint on subarray length suggests iterating only over valid lengths rather than checking every possible range.

## 🚀 Evolution of Thought Process

1. **Brute Force:** Generate every possible subarray and calculate its sum.
2. **Observation:** We only care about subarrays with lengths between `l` and `r`.
3. **Optimization:** Use Prefix Sum to calculate each subarray sum in O(1).
4. **Final Approach:** Iterate through every possible ending index and check only the allowed subarray lengths.
5. **Early Termination:** Since all elements are integers, the smallest possible positive sum is `1`. Once found, no better answer exists.

## 🔍 Detailed Reasoning

### Step 1: Build Prefix Sum

Modify the input array itself to store prefix sums.

```txt
for (let i = 1; i < n; i++) {
    nums[i] += nums[i - 1];
}
```

Example:

Original array:

`[3, -2, 1, 4]`

Prefix sum:

`[3, 1, 2, 6]`

### Step 2: Iterate Through Ending Indices

Start from index `l - 1`, because an ending index smaller than that cannot contain a subarray of minimum length `l`.

### Step 3: Check Valid Subarray Lengths

For every ending index `i`, iterate through lengths from `l` to `r`.

The starting index is:

```txt
startIndex = i - length + 1
```

The sum is:

```txt
previousIndex = startIndex - 1

previousSum = previousIndex < 0
    ? 0
    : nums[previousIndex];

sum = nums[i] - previousSum;
```

### Step 4: Update Minimum Positive Sum

Only consider sums greater than zero.

Update `minSum` whenever a smaller positive sum is found.

### Step 5: Early Termination

Because all array elements are integers, every subarray sum is also an integer.

Therefore, the smallest possible positive sum is `1`.

Once we find `1`, there is no reason to continue searching.

```txt
if (minSum === 1) break;
```

## 🧪 Dry Run

**Input:**

`nums = [3, -2, 1, 4], l = 2, r = 3`

Prefix Sum:

`[3, 1, 2, 6]`

| Ending index | Length | Subarray | Sum | Minimum |
|---|---:|---|---:|---:|
| 1 | 2 | [3, -2] | 1 | 1 |
| 2 | 2 | [-2, 1] | -1 | 1 |
| 2 | 3 | [3, -2, 1] | 2 | 1 |
| 3 | 2 | [1, 4] | 5 | 1 |
| 3 | 3 | [-2, 1, 4] | 3 | 1 |

Since the minimum possible positive sum (`1`) is found, the algorithm can terminate early.

**Output:** `1`

## 🧩 Approach 1 — My Solution

**Idea:** Prefix Sum + Nested Loops.

- Modify the input array to store prefix sums.
- Iterate through every possible ending index.
- Check subarray lengths between `l` and `r`.
- Calculate each subarray sum in O(1).
- Track the minimum positive sum.
- Stop immediately when the answer becomes `1`.

### TypeScript Code

```ts
function minimumSumSubarray(
    nums: number[],
    l: number,
    r: number
): number {
    const n = nums.length;

    // Build prefix sum in-place.
    for (let i = 1; i < n; i++) {
        nums[i] += nums[i - 1];
    }

    let minSum = Infinity;
    let isSumUpdated = false;

    for (let i = l - 1; i < n; i++) {
        for (let j = l; j <= r; j++) {
            const lastIndex = i - j;

            const previousSum =
                lastIndex < 0 ? 0 : nums[lastIndex];

            const sum = nums[i] - previousSum;

            if (sum > 0) {
                minSum = Math.min(minSum, sum);
                isSumUpdated = true;
            }
        }

        // 1 is the smallest possible positive integer sum.
        if (minSum === 1) break;
    }

    return isSumUpdated ? minSum : -1;
}
```

## ⚖️ Correctness — Why It Works

1. Prefix Sum allows us to calculate any contiguous subarray sum in constant time.
2. The outer loop considers every possible ending index that can contain a valid subarray.
3. The inner loop checks every allowed length from `l` to `r`.
4. Therefore, every valid subarray is considered.
5. We update the answer only for positive sums, ensuring the result is always a valid candidate.
6. Since all values are integers, finding `1` guarantees the globally minimum possible positive sum.

If no positive sum is found, we return `-1`.

## ⏱️ Complexity Analysis

**Time:** O(n × (r - l + 1))

- Prefix Sum construction: O(n).
- Nested loops: O(n × (r - l + 1)).
- Early termination can improve practical execution time.

Worst case: O(n²), when `r - l + 1` is O(n).

**Space:** O(1)

The prefix sum is calculated by modifying the original input array. No additional data structure is required.

## 🏆 Key Takeaways

1. Prefix Sum makes range-sum calculations O(1).
2. Always use problem constraints to reduce unnecessary iterations.
3. Early termination is useful when a known lower bound for the answer is reached.
4. Integer constraints matter: the minimum positive integer is `1`.
5. An O(n²) solution is perfectly acceptable when `n <= 100`.

## 📚 Pattern Learned

**Prefix Sum + Constrained Brute Force**

Whenever a problem asks for subarray sums with specific length constraints:

1. Build prefix sums.
2. Enumerate valid ending indices.
3. Enumerate only allowed lengths.
4. Calculate sums in O(1).
5. Apply answer-specific optimizations when possible.
