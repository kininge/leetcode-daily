# 🧩 Problem #2124 – Check if All A's Appears Before All B's

**Difficulty:** Easy  
**Topics:** `String`          
**Link:** https://leetcode.com/problems/check-if-all-as-appears-before-all-bs/

---

## 📝 Problem Summary

Given a string `s` consisting only of `'a'` and `'b'`, return `true` if every `'a'` appears before every `'b'`.

Otherwise, return `false`.

### Examples

**Example 1**

```txt

Input: s = "aaabbb"
Output: true

```

All `a`s appear before all `b`s.

**Example 2**

```txt

Input: s = "abab"
Output: false

```

An `a` appears after a `b`, violating the required order.

**Example 3**

```txt

Input: s = "bbb"
Output: true

```

There are no `a`s, so the condition is satisfied.

---

## 💡 Core Insight

The string must follow this pattern:

```txt

aaaa...bbbb

```

Once we encounter the first `'b'`, we must never encounter an `'a'` afterward.

Therefore, we only need to track whether we have encountered a `'b'`.

If we encounter an `'a'` after that point, we can immediately return `false`.

---

## 🎯 Pattern Recognition

This problem is an example of **state tracking while traversing a string**.

We maintain a state representing whether we have crossed the boundary between the two valid groups.

```txt

State 1: Haven't encountered 'b' yet

State 2: Already encountered 'b'

```

The transition is one-way:

```txt

Haven't seen b
       |
       | encounter b
       v
   Seen b

```

Once we enter the second state, encountering an `'a'` means the string is invalid.

---

## 🚀 Evolution of Thought Process

### Step 1 — Understand the ordering requirement

We need all `a`s to appear before all `b`s.

Valid strings:

```txt

"a"
"aaaa"
"bbbb"
"aaabbb"
"ab"

```

Invalid strings:

```txt

"ba"
"aba"
"abba"
"bab"

```

### Step 2 — Identify the violation

Instead of checking whether every `a` appears before every `b`, we can look for the only possible violation:

> An `'a'` appearing after a `'b'`.

We don't need to compare positions or count both characters.

### Step 3 — Track whether we've seen a `b`

We use a variable:

```txt

let countB = 0;

```

When we encounter a `b`, we increment it.

When we encounter an `a`, we check whether `countB` is already greater than zero.

If it is, the ordering has been violated.

### Step 4 — Return early

The moment we discover an invalid ordering, we return `false`.

If the loop completes without finding a violation, the string is valid.

---

## 🔍 Detailed Reasoning

Our variable `countB` represents:

> The number of `b` characters encountered so far.

We only care whether this number is zero or non-zero.

### Case 1 — Encounter `'b'`

```txt

if (s[i] === 'b') countB++;

```

We have now entered the section of the string where only `b`s are allowed.

### Case 2 — Encounter `'a'`

```txt

if (s[i] === 'a' && countB) return false;

```

If `countB` is non-zero, it means a `b` appeared earlier.

Therefore, this `a` is appearing after a `b`, violating the requirement.

### Case 3 — Loop completes

If we never encountered an `a` after a `b`, the string follows the required ordering.

We return:

```txt

return true;

```

## 🧩 Approach 1 — My Solution

### Code

```ts

function checkString(s: string): boolean {
    let countB = 0;

    for (let i = 0; i < s.length; i++) {
        if (s[i] === 'b') countB++;

        if (s[i] === 'a' && countB) return false;
    }

    return true;
};

```

### Why it works

The variable `countB` tracks whether a `b` has appeared previously.

If an `a` appears while `countB > 0`, then the string contains a `b` before an `a`.

That directly violates the problem's condition.

If the loop completes, no violation occurred.

### Complexity

**Time:** O(n)

We traverse the string at most once. In the worst case, we examine all `n` characters.

**Space:** O(1)

We use only one integer variable, regardless of string length.

---

## 🧩 Approach 2 — Improved Readability Using Boolean State

Since we only care whether we have encountered a `b`, counting all `b`s is unnecessary.

We can use a boolean variable instead.

### Code

```ts

function checkString(s: string): boolean {
    let seenB = false;

    for (const char of s) {
        if (char === 'b') {
            seenB = true;
        } else if (seenB) {
            return false;
        }
    }

    return true;
}

```

### Explanation

`seenB` represents whether the string has entered the `b` section.

Initially:

```txt

seenB = false;

```

When we encounter a `b`:

```txt

seenB = true;

```

From that point onward, encountering an `a` means the string is invalid.

### Complexity

**Time:** O(n)

**Space:** O(1)

---

## ⚖️ Comparison of Approaches

| Criteria | Approach 1 — Counter | Approach 2 — Boolean |
|---|---|---|
| Core Idea | Count encountered `b`s | Track whether a `b` was encountered |
| Time | O(n) | O(n) |
| Space | O(1) | O(1) |
| Readability | Good | Slightly clearer |
| Tradeoff | Counts more information than needed | Directly represents the required state |

## 🏆 Key Takeaways

1. Sometimes the problem can be solved by identifying the **single condition that makes an answer invalid**.
2. Early returns avoid unnecessary work once the answer is known.
3. When only checking whether something has happened, a boolean may be more expressive than a counter.
4. State tracking is useful when a condition changes permanently during traversal.
5. The state transition in this problem is one-way:

   ```txt

   Haven't seen b → Seen b

   ```

   Returning to the previous state is not allowed.

---

## 📚 Pattern Learned

### State Tracking / One-Way State Transition

Useful when:

- A condition becomes permanently true after a certain event.
- Future elements must obey different rules depending on past elements.
- We can reject the input immediately when an invalid transition occurs.

Examples of similar reasoning:

- Checking whether a string follows a specific character ordering.
- Detecting whether a sequence violates a monotonic condition.
- Validating state transitions in a parser.
- Checking whether a prerequisite has already occurred before allowing another event.
