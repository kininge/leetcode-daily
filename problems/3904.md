# 🧩 Problem #3904 – Smallest Stable Index II

**Difficulty:** Medium   
**Topics:** `Array`, `Prefix`  
**Link:** https://leetcode.com/problems/smallest-stable-index-ii/   

---

## 📝 Problem Summary

For each index `i`, the instability score is:

```text
max(nums[0...i]) - min(nums[i...n-1])
```

An index is **stable** if its instability score is `<= k`.

Return the **smallest stable index**, or `-1` if no stable index exists.

---

## 💡 Core Insight

The instability score consists of two range queries:

```text
max(nums[0...i])       → prefix maximum
min(nums[i...n-1])     → suffix minimum
```

The key is to avoid recalculating these values for every index.

We can:

1. Precompute the minimum of every suffix.
2. Scan from left to right while maintaining the maximum of the prefix.
3. Check the instability score at each index.
4. Return immediately when the first stable index is found.

---

## 🎯 Pattern Recognition

When a problem contains expressions involving both:

```text
nums[0...i]
nums[i...n-1]
```

look for **prefix/suffix preprocessing**.

Here:

* The left part requires a prefix maximum.
* The right part requires a suffix minimum.

The prefix maximum can be maintained while scanning.

The suffix minimum is precomputed from right to left.

This converts repeated range calculations into linear work.

---

## 🚀 Evolution of Thought Process

### Brute Force

For every index `i`, calculate:

```text
max(nums[0...i])
min(nums[i...n-1])
```

independently.

That repeats a lot of work and can lead to `O(n²)` time.

### Observation

The suffix minimum has a useful relationship:

```text
minSuffix[i] = min(nums[i], minSuffix[i + 1])
```

So all suffix minimums can be calculated in one right-to-left pass.

At the same time, while scanning left to right:

```text
maxSoFar = max(maxSoFar, nums[i])
```

gives us:

```text
max(nums[0...i])
```

without needing another array.

### Final Approach

At every index:

```text
instability = maxSoFar - minSuffix[i]
```

If:

```text
instability <= k
```

return `i`.

Because we scan from left to right, the first valid index is automatically the **smallest stable index**.

---

## 🔍 Detailed Reasoning

### Step 1 — Build the suffix minimum array

Define:

```text
minSuffix[i] = min(nums[i...n-1])
```

For:

```text
nums = [5, 0, 1, 4]
```

we get:

```text
index       0  1  2  3
nums        5  0  1  4
minSuffix   0  0  1  4
```

We calculate this from right to left.

Starting with:

```text
minSuffix[3] = nums[3] = 4
```

Then:

```text
minSuffix[2] = min(nums[2], minSuffix[3])
             = min(1, 4)
             = 1
```

and so on.

### Step 2 — Maintain the prefix maximum

Now scan from left to right.

At index `i`:

```text
maxSoFar = max(nums[0...i])
```

For the example:

```text
i = 0 → maxSoFar = 5
i = 1 → maxSoFar = 5
i = 2 → maxSoFar = 5
i = 3 → maxSoFar = 5
```

### Step 3 — Check stability

At each index:

```text
diff = maxSoFar - minSuffix[i]
```

For:

```text
nums = [5, 0, 1, 4]
k = 3
```

we get:

```text
i = 0 → 5 - 0 = 5
i = 1 → 5 - 0 = 5
i = 2 → 5 - 1 = 4
i = 3 → 5 - 4 = 1
```

Only index `3` satisfies:

```text
diff <= 3
```

Therefore the answer is:

```text
3
```

## 🧩 Approach 1 — Prefix Maximum + Suffix Minimum

### Algorithm

1. Create `minSuffix`.
2. Set the last suffix minimum to `nums[n - 1]`.
3. Traverse right to left and calculate every suffix minimum.
4. Traverse left to right.
5. Maintain `maxSoFar`.
6. Calculate:

```text
maxSoFar - minSuffix[i]
```

7. Return the first index where the result is `<= k`.
8. If no index satisfies the condition, return `-1`.

### TypeScript

```ts
function firstStableIndex(nums: number[], k: number): number {
    const n = nums.length;

    const minSuffix = new Array(n);
    minSuffix[n - 1] = nums[n - 1];

    // Build suffix minimum.
    let minSoFar = nums[n - 1];

    for (let i = n - 2; i >= 0; i--) {
        minSoFar = Math.min(nums[i], minSoFar);
        minSuffix[i] = minSoFar;
    }

    // Find the first stable index.
    let maxSoFar = nums[0];

    for (let i = 0; i < n; i++) {
        maxSoFar = Math.max(maxSoFar, nums[i]);

        const diff = maxSoFar - minSuffix[i];

        if (diff <= k) {
            return i;
        }
    }

    return -1;
}
```

### Small Code-Quality Improvement

Your original code used:

```ts
let maxSofar = 0;
```

This works under the given constraint:

```text
0 <= nums[i]
```

But:

```ts
let maxSoFar = nums[0];
```

is conceptually cleaner because the running maximum should be initialized from the actual array rather than relying on the fact that all values are non-negative.

## ⚖️ Correctness

For every index `i`:

```text
maxSoFar = max(nums[0...i])
```

because `maxSoFar` is updated with every element from index `0` through `i`.

Also:

```text
minSuffix[i] = min(nums[i...n-1])
```

because the suffix minimum is calculated using:

```text
minSuffix[i] = min(nums[i], minSuffix[i + 1])
```

Therefore:

```text
maxSoFar - minSuffix[i]
```

is exactly the instability score defined by the problem.

Since indices are checked in increasing order, the first index satisfying:

```text
maxSoFar - minSuffix[i] <= k
```

is guaranteed to be the smallest stable index.

---

## ⏱️ Complexity Analysis

**Time:** `O(n)`

There are two sequential passes:

```text
Build suffix minimum → O(n)
Find answer          → O(n)

Total                 → O(n)
```

**Space:** `O(n)`

The `minSuffix` array stores one value for each index.

---

## 🏆 Key Takeaways

* Recognize expressions involving `[0...i]` and `[i...n-1]` as possible **prefix/suffix problems**.
* Precompute reusable suffix information instead of recalculating it.
* Maintain prefix information incrementally when possible.
* Two sequential `O(n)` loops are still **O(n)**.
* Since we need the **smallest** valid index, scanning left to right lets us return immediately.
* Don't force an optimization when the existing solution is already simple, correct, and optimal in time.

## 📚 Pattern Learned

### Prefix + Suffix Preprocessing

When a condition depends on both sides of an index:

```text
property(nums[0...i])
property(nums[i...n-1])
```

consider precomputing one side and maintaining the other incrementally.

This is a reusable pattern for:

* Prefix maximum/minimum
* Suffix maximum/minimum
* Prefix/suffix sums
* Split-point problems
* Array partition conditions
