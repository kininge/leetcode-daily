# 🧩 Problem #3471 -- Find the Largest Almost Missing Integer

**Difficulty:** Easy  
**Topics:** `Array`, `Sliding Window`, `Hash Map`   
**Link:** https://leetcode.com/problems/find-the-largest-almost-missing-integer/

---

## 📝 Problem Summary

You are given an integer array `nums` and an integer `k`.

An integer `x` is **almost missing** if `x` appears in **exactly one
subarray of size `k`**.

Return the **largest** almost missing integer.

If no such integer exists, return `-1`.

---

### Example

``` txt
nums = [3, 9, 2, 1, 7]
k = 3

Windows:

[3, 9, 2]
[9, 2, 1]
[2, 1, 7]
```

Window appearances:

``` txt
3 → 1 window
9 → 2 windows
2 → 3 windows
1 → 2 windows
7 → 1 window
```

Therefore:

``` txt
Almost missing values = 3, 7
Answer = 7
```

---

## 💡 Intuition

The first important distinction is:

``` txt
Frequency in nums
        ≠
Number of windows containing the value
```

For example, `1` occurs only once in:

``` txt
[3, 9, 2, 1, 7]
```

But it belongs to two windows:

``` txt
[9, 2, 1]
[2, 1, 7]
```

So `1` is **not** almost missing.

This naturally leads to a sliding-window solution where we count how
many windows contain each value.

---

## ⚠️ Important Correction to My Initial Observation

My initial thought was:

``` txt
"If a number appears in only 1 subarray,
it should be a corner element."
```

This is **not always true**.

Counterexample:

``` txt
nums = [1, 2, 3]
k = 3
```

There is only one window:

``` txt
[1, 2, 3]
```

So `2` is also almost missing even though it is not a corner element.

The missing condition is:

``` txt
1 < k < n
```

For this range of `k`, only the first and last positions can belong to
exactly one window.

So the corrected observation is:

``` txt
For 1 < k < n:

Exactly one containing window
        ↓
Position must be index 0 or n - 1
        ↓
The value must occur only once in nums
```

# 🛠 Approach 1 --- My Sliding Window Solution

## Idea

Maintain two maps:

### `window`

Stores the frequency of values inside the current window.

``` txt
window[value] = occurrences inside current window
```

### `frequency`

Stores how many windows contain each value.

``` txt
frequency[value] = number of windows containing value
```

For every window, we iterate over the distinct values in `window` and
increment their global window count.

Finally, the largest value with:

``` txt
frequency[value] === 1
```

is the answer.

---

## Why It Works

For every window, we record each value **once**, regardless of how many
times it occurs inside that window.

For example:

``` txt
window = [2, 2, 3]
```

We record:

``` txt
2 → appears in this window
3 → appears in this window
```

not:

``` txt
2 → +2
3 → +1
```

Therefore `frequency[x]` correctly represents the number of subarrays of
size `k` containing `x`.

---

## Code (TypeScript)

``` ts
function largestInteger(nums: number[], k: number): number {
    const n = nums.length;

    const frequency = new Map<number, number>();
    const window = new Map<number, number>();

    function noteEachWindowElements(): void {
        window.forEach((_, value) => {
            frequency.set(
                value,
                (frequency.get(value) ?? 0) + 1
            );
        });
    }

    // Build the first window.
    for (let i = 0; i < k; i++) {
        window.set(
            nums[i],
            (window.get(nums[i]) ?? 0) + 1
        );
    }

    noteEachWindowElements();

    // Slide the window.
    for (let i = k; i < n; i++) {
        const outgoing = nums[i - k];

        const outgoingCount = window.get(outgoing)! - 1;

        if (outgoingCount === 0) {
            window.delete(outgoing);
        } else {
            window.set(outgoing, outgoingCount);
        }

        const incoming = nums[i];

        window.set(
            incoming,
            (window.get(incoming) ?? 0) + 1
        );

        noteEachWindowElements();
    }

    // Find the largest value appearing in exactly one window.
    let answer = -1;

    frequency.forEach((count, value) => {
        if (count === 1) {
            answer = Math.max(answer, value);
        }
    });

    return answer;
}
```

---

## Complexity

There are:

``` txt
n - k + 1
```

windows.

For each window, we may iterate over up to `k` distinct values.

Therefore:

``` txt
Time Complexity:  O(nk)
Space Complexity: O(k + U)
```

where `U` is the number of distinct values.

Given:

``` txt
n <= 50
```

this is easily fast enough.

---

## Limitations

The solution is correct, but it processes every window even though this
particular problem has a stronger structural property.

It also originally used sorting to find the largest candidate.

That sorting is unnecessary because we only need:

``` ts
max(value where frequency[value] === 1)
```

Tracking `answer = Math.max(answer, value)` is simpler.

# 🚀 Approach 2 --- Endpoint / Position Coverage Observation

## Idea

Instead of asking:

``` txt
Which windows contain this value?
```

ask:

``` txt
How many windows can contain this position?
```

Consider:

``` txt
nums = [0, 1, 2, 3, 4, 5]
k = 3
```

The windows are:

``` txt
[0, 1, 2]
   [1, 2, 3]
      [2, 3, 4]
         [3, 4, 5]
```

Number of windows containing each index:

``` txt
index:    0  1  2  3  4  5
windows:  1  2  3  3  2  1
```

Only:

``` txt
index 0
index n - 1
```

belong to exactly one window.

Therefore, when:

``` txt
1 < k < n
```

only `nums[0]` and `nums[n - 1]` can be almost missing.

But there is one more condition:

The value must occur only once in the entire array.

For example:

``` txt
nums = [5, 2, 3, 4, 5]
```

Even though `5` is at the first position, it occurs again at the end.

So it appears in more than one window and cannot be almost missing.

---

## Edge Cases

### `k === 1`

Every position forms its own window:

``` txt
[nums[0]]
[nums[1]]
[nums[2]]
...
```

Therefore:

``` txt
value is almost missing
    ↕
value occurs exactly once in nums
```

---

### `k === n`

There is only one window:

``` txt
[nums[0], nums[1], ..., nums[n - 1]]
```

Therefore every distinct value is almost missing.

Return the maximum value.

---

### `1 < k < n`

Only the endpoints can be candidates.

Check:

``` txt
frequency[nums[0]] === 1
frequency[nums[n - 1]] === 1
```

Then return the larger valid value.

---

## Code (TypeScript)

``` ts
function largestInteger(nums: number[], k: number): number {
    const n = nums.length;

    const frequency = new Map<number, number>();

    // Count occurrences in the entire array.
    for (const num of nums) {
        frequency.set(
            num,
            (frequency.get(num) ?? 0) + 1
        );
    }

    // Only one window exists: the entire array.
    if (k === n) {
        return Math.max(...nums);
    }

    // Every position is its own window.
    if (k === 1) {
        let answer = -1;

        for (const [value, count] of frequency) {
            if (count === 1) {
                answer = Math.max(answer, value);
            }
        }

        return answer;
    }

    // 1 < k < n:
    // Only the first and last positions belong to exactly one window.
    let answer = -1;

    const first = nums[0];
    const last = nums[n - 1];

    if (frequency.get(first) === 1) {
        answer = Math.max(answer, first);
    }

    if (frequency.get(last) === 1) {
        answer = Math.max(answer, last);
    }

    return answer;
}
```

---

## Complexity

Counting the values takes one pass:

``` txt
O(n)
```

Checking the relevant candidates is constant work except for the
`k === 1` case, which may scan the frequency map:

``` txt
Time Complexity:  O(n)
Space Complexity: O(U)
```

where `U` is the number of distinct values.

---

## Why This Is Better

Approach 1 asks:

``` txt
What happens in every window?
```

Approach 2 asks:

``` txt
Which positions can possibly satisfy the condition?
```

That eliminates the need to process every window.

So:

``` txt
Approach 1
O(nk)
```

becomes:

``` txt
Approach 2
O(n)
```

More importantly, the optimization comes from **understanding the
structure of the problem**, not from using a more complicated data
structure.

## 🏆 Final Recommendation

My original solution is **correct** and is a good direct application of
the sliding-window pattern.

The better solution comes from a stronger observation:

> Don't immediately process every window. First ask how many windows can
> contain a particular position.

For:

``` txt
1 < k < n
```

only the two endpoints can belong to exactly one window.

Therefore the optimized solution only needs:

``` txt
Global frequency count
        ↓
Check nums[0]
        ↓
Check nums[n - 1]
        ↓
Return largest valid candidate
```

### Main Learning

The progression here is:

``` txt
Correct Solution
      ↓
Question the unnecessary work
      ↓
Change perspective
      ↓
Find structural property
      ↓
Simpler + faster solution
```

The important takeaway is not just:

> "Use the endpoint trick for LeetCode 3471."

It is:

> **When a problem talks about many fixed-size windows, ask how many
> windows can contain each position.**

That kind of perspective shift is what we want to get better at.
