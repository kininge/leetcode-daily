# 🧩 Problem #2091 – Removing Minimum and Maximum From Array

**Difficulty:** Medium  
**Topics:** `Array`, `Greedy`    
**Link:** https://leetcode.com/problems/removing-minimum-and-maximum-from-array/

---

## 📝 Problem Summary

You are given an array of distinct integers.

You need to remove both:

- The **minimum** element
- The **maximum** element

A deletion can only remove an element from:

- The **front**
- The **back**

Return the minimum number of deletions required to remove both elements.

---

### Example

```txt
nums = [2,10,7,5,4,1,8,6]
```

Minimum:

```txt
1 → index 5
```

Maximum:

```txt
10 → index 1
```

One optimal strategy is:

```txt
Remove 2 elements from front
Remove 3 elements from back
```

Total:

```txt
2 + 3 = 5
```

Answer:

```txt
5
```

---

## 💡 Intuition

The actual values of the elements are not important after we know where the minimum and maximum are.

The problem becomes:

```txt
Where are min and max?
        ↓
How many elements must I remove
from the front/back to reach them?
```

For an element at index `i` in an array of length `n`:

```txt
Remove from front = i + 1
Remove from back  = n - i
```

So the entire problem can be reduced to the **positions of min and max**.

---

## 🧠 Key Observation

Suppose:

```txt
minIndex = 5
maxIndex = 1
```

We only have four meaningful strategies.

### Strategy 1 — Remove both from the front

We need to reach whichever element is farther from the front.

```txt
max(minIndex + 1, maxIndex + 1)
```

---

### Strategy 2 — Remove both from the back

We need to reach whichever element is farther from the back.

```txt
max(n - minIndex, n - maxIndex)
```

---

### Strategy 3 — Remove min from front, max from back

Cost:

```txt
(minIndex + 1) + (n - maxIndex)
```

---

### Strategy 4 — Remove max from front, min from back

Cost:

```txt
(maxIndex + 1) + (n - minIndex)
```

The answer is simply the minimum of these four possibilities.

---

# 🚀 Approach 1 — Check the Four Deletion Strategies

## Idea

First scan the array and find:

```txt
minIndex
maxIndex
```

Then calculate how many deletions each strategy requires.

```txt
                    min
                     ↓
[ ------------------x--------- ]
  ← front deletions

                     x
                     ↑
                  back →
```

We don't need to simulate any deletion.

We only need to calculate the cost.

---

## Code (TypeScript)

```ts
function minimumDeletions(nums: number[]): number {
    const n = nums.length;

    let minIndex = 0;
    let maxIndex = 0;

    // Find positions of minimum and maximum.
    for (let i = 1; i < n; i++) {
        if (nums[i] < nums[minIndex]) {
            minIndex = i;
        }

        if (nums[i] > nums[maxIndex]) {
            maxIndex = i;
        }
    }

    // Number of deletions needed to reach each element
    // from the front or back.
    const minFront = minIndex + 1;
    const minBack = n - minIndex;

    const maxFront = maxIndex + 1;
    const maxBack = n - maxIndex;

    // Four possible strategies:
    //
    // 1. Both from front
    // 2. Both from back
    // 3. min from front + max from back
    // 4. max from front + min from back

    return Math.min(
        Math.max(minFront, maxFront),
        Math.max(minBack, maxBack),
        minFront + maxBack,
        maxFront + minBack
    );
}
```

---

## 🔍 Why These Four Cases Are Enough

There are only two elements we care about:

```txt
MIN
MAX
```

For each one, we can remove it from either side:

```txt
MIN → front OR back
MAX → front OR back
```

That gives:

```txt
MIN front + MAX front
MIN back  + MAX back
MIN front + MAX back
MIN back  + MAX front
```

The first two are the "same side" cases.

When removing both from the same side, we don't add their individual costs.

For example:

```txt
MIN at index 5
MAX at index 1
```

To remove both from the front, we only need to remove through index `5`.

So the cost is:

```txt
max(minFront, maxFront)
```

not:

```txt
minFront + maxFront
```

This is because the same deletions remove both elements.

## 🧪 Dry Run

Consider:

```txt
nums = [2,10,7,5,4,1,8,6]
```

Indices:

```txt
index:  0   1   2   3   4   5   6   7
value:  2  10   7   5   4   1   8   6
            ↑               ↑
           max             min
```

Therefore:

```txt
maxIndex = 1
minIndex = 5
n = 8
```

### Cost from front

For minimum:

```txt
minFront = 5 + 1 = 6
```

For maximum:

```txt
maxFront = 1 + 1 = 2
```

Both from front:

```txt
max(6, 2) = 6
```

---

### Cost from back

For minimum:

```txt
minBack = 8 - 5 = 3
```

For maximum:

```txt
maxBack = 8 - 1 = 7
```

Both from back:

```txt
max(3, 7) = 7
```

---

### Minimum from front + maximum from back

```txt
minFront + maxBack
= 6 + 7
= 13
```

Clearly terrible in this example.

---

### Maximum from front + minimum from back

```txt
maxFront + minBack
= 2 + 3
= 5
```

This corresponds to:

```txt
2 deletions from front
3 deletions from back
```

Therefore:

```txt
answer = 5
```

# 🚀 Approach 2 — Simplify Using Leftmost and Rightmost Positions

We can make the reasoning even cleaner.

Let:

```txt
left  = min(minIndex, maxIndex)
right = max(minIndex, maxIndex)
```

So:

```txt
left ---------------- right
 ↑                       ↑
one target             other target
```

Now the four strategies become easier to see.

---

### Strategy 1 — Both from front

We must remove everything through `right`.

```txt
cost = right + 1
```

---

### Strategy 2 — Both from back

We must remove everything from `right` to the end.

Actually, because `left` is the farther target from the back:

```txt
cost = n - left
```

---

### Strategy 3 — Left target from front + right target from back

```txt
cost = (left + 1) + (n - right)
```

---

### Strategy 4 — The opposite split

This would be:

```txt
(right + 1) + (n - left)
```

But this is never better than removing both from one side.

Why?

```txt
(right + 1) + (n - left)
```

already covers the entire region between the two targets twice in terms of the split.

So after sorting the indices, only **three strategies actually need to be checked**:

```txt
1. Both from front
2. Both from back
3. Left from front + right from back
```

---

## Code (TypeScript)

```ts
function minimumDeletions(nums: number[]): number {
    const n = nums.length;

    let minIndex = 0;
    let maxIndex = 0;

    for (let i = 1; i < n; i++) {
        if (nums[i] < nums[minIndex]) {
            minIndex = i;
        }

        if (nums[i] > nums[maxIndex]) {
            maxIndex = i;
        }
    }

    const left = Math.min(minIndex, maxIndex);
    const right = Math.max(minIndex, maxIndex);

    const bothFromFront = right + 1;
    const bothFromBack = n - left;
    const oneFromEachSide = (left + 1) + (n - right);

    return Math.min(
        bothFromFront,
        bothFromBack,
        oneFromEachSide
    );
}
```

---

## 🔍 Why Approach 2 Is Equivalent

Suppose:

```txt
left = 1
right = 5
```

Then:

### Both from front

```txt
[ x x x x x x ]
  ↑         ↑
 left      right

cost = 6
```

### Both from back

```txt
cost = n - left
```

### One from each side

```txt
front → left
back  → right
```

giving:

```txt
(left + 1) + (n - right)
```

There is no reason to use the opposite split:

```txt
right from front + left from back
```

because that removes more elements than simply removing both targets from one side.

---

## ⚖️ Correctness

Let:

```txt
left = min(minIndex, maxIndex)
right = max(minIndex, maxIndex)
```

Every valid solution must remove both target elements.

There are only three potentially optimal ways to do this:

### Case 1 — Both targets removed from the front

The farther target is at `right`.

Therefore:

```txt
cost = right + 1
```

### Case 2 — Both targets removed from the back

The farther target from the back is `left`.

Therefore:

```txt
cost = n - left
```

### Case 3 — Targets removed from opposite sides

Remove the left target from the front and the right target from the back:

```txt
cost = (left + 1) + (n - right)
```

The alternative assignment of sides is never better because it removes more elements.

Therefore the minimum of these three costs is the global minimum.

---

## ⏱️ Complexity Analysis

Let:

```txt
n = nums.length
```

### Finding min and max

We scan the array once:

```txt
O(n)
```

### Calculating strategies

Only a constant number of calculations:

```txt
O(1)
```

Therefore:

```txt
Time:  O(n)
Space: O(1)
```

## 🏆 Final Recommendation

Your original solution was already **algorithmically correct**.

The better version is mainly a reasoning simplification:

```txt
Find min/max positions
        ↓
left = smaller index
right = larger index
        ↓
┌───────────────────────────┐
│ both from front           │ → right + 1
│ both from back            │ → n - left
│ one from each side        │ → left + 1 + n - right
└───────────────────────────┘
        ↓
      minimum
```

The important lesson is:

> When two special elements are involved, first normalize their positions (`left` and `right`). This often exposes symmetry and eliminates redundant cases.

---

## 🏆 Key Takeaways

- When deletion is restricted to the **front/back**, think in terms of **indices and distances from the boundaries**.
- For an element at index `i`:
  - Front cost = `i + 1`
  - Back cost = `n - i`
- When two target elements are involved, sort their positions into:
  - `left`
  - `right`
- Removing both from one side requires reaching only the farther target.
- Removing one from each side can be cheaper when the targets are near opposite ends.
- Don't simulate deletions when only the number of deletions matters.

---

## 📚 Pattern Learned

### Pattern: Boundary Deletion / Index Cost Analysis

When operations can only remove elements from array boundaries:

```txt
Target index i
     ↓
front cost = i + 1
back cost  = n - i
```

For multiple target elements:

```txt
Find target positions
        ↓
Normalize positions
        ↓
Enumerate meaningful boundary strategies
        ↓
Take minimum
```

This is often much simpler than actually modifying the array.
