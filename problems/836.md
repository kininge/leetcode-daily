# 🧩 Problem #836 – Rectangle Overlap

**Difficulty:** Easy  
**Topics:** `Geometry`, `Math`    
**Link:** https://leetcode.com/problems/rectangle-overlap/

---

## 📝 Problem Summary

We are given two axis-aligned rectangles represented as:

[ x1, y1, x2, y2 ]

where:

- `(x1, y1)` is the bottom-left corner.
- `(x2, y2)` is the top-right corner.

We need to return `true` if the rectangles overlap with **positive area**.

Important:

- Touching at a corner → `false`
- Touching along an edge → `false`
- Actual overlap with positive area → `true`

---

## 💡 Core Insight

A rectangle can be viewed as two independent intervals:

- X-axis interval → `[x1, x2]`
- Y-axis interval → `[y1, y2]`

For two rectangles to have positive-area overlap:

1. Their X intervals must overlap with positive length.
2. Their Y intervals must overlap with positive length.

Therefore:

```txt
2D rectangle overlap
        ↓
X-axis overlap
        +
Y-axis overlap
        ↓
Positive-area intersection

```

Instead of calculating the intersection area, we can ask:

> **When are the rectangles definitely NOT overlapping?**

They are separated if one rectangle is:

- completely to the left
- completely to the right
- completely above
- completely below

If none of those conditions is true, they must overlap.

---

## 🎯 Pattern Recognition

Whenever you see an **axis-aligned rectangle** problem, think about its X and Y projections separately.

A rectangle is essentially:

```txt

Rectangle = X interval × Y interval

```

So a 2D overlap problem becomes two 1D interval problems.

This is a useful computational geometry pattern:

```txt

2D problem
    ↓
Break into dimensions
    ↓
Solve each dimension independently
    ↓
Combine the conditions

```

## 🚀 Evolution of Thought Process

### Step 1 — Think about the geometry

The first instinct might be to calculate the intersection rectangle and then calculate its area.

But that is unnecessary.

We only care whether the intersection has:

- positive width
- positive height

### Step 2 — Separate X and Y

For:

```txt

rec1 = [x11, y11, x12, y12]

```

the X interval is:

```txt

[x11, x12]

```

and the Y interval is:

```txt

[y11, y12]

```

Similarly, for:

```txt

rec2 = [x21, y21, x22, y22]

```

the X interval is:

```txt

[x21, x22]

```

and the Y interval is:

```txt

[y21, y22]

```

### Step 3 — Detect separation

Rectangle 2 is completely to the right of Rectangle 1 when:

```txt

x21 >= x12

```

Rectangle 2 is completely to the left when:

```txt

x22 <= x11

```

Rectangle 2 is completely below when:

```txt

y22 <= y11

```

Rectangle 2 is completely above when:

```txt

y21 >= y12

```

If any one of these is true, there is no positive-area overlap.

### Step 4 — Reverse the condition

Therefore:

```txt

overlap = NOT(separated)

```

That gives us the solution directly.

---

## 🔍 Detailed Reasoning

Let's define:

```txt

rec1 = [x11, y11, x12, y12]
rec2 = [x21, y21, x22, y22]

```

### Case 1 — Rectangle 2 is to the right

If:

```txt

x21 >= x12

```

then Rectangle 2 starts at or after Rectangle 1 ends.

There is no positive X overlap.

Example:

```txt

rec1 = [0, 0, 2, 2]
rec2 = [2, 0, 4, 2]

```

They touch at `x = 2`, but their intersection has zero width.

Therefore:

```txt

false

```

---

### Case 2 — Rectangle 2 is to the left

If:

```txt

x22 <= x11

```

then Rectangle 2 ends at or before Rectangle 1 starts.

There is no positive X overlap.

Therefore:

```txt

false

```

---

### Case 3 — Rectangle 2 is below

If:

```txt

y22 <= y11

```

then Rectangle 2 ends at or below Rectangle 1's bottom edge.

There is no positive Y overlap.

Therefore:

```txt

false

```

---

### Case 4 — Rectangle 2 is above

If:

```txt

y21 >= y12

```

then Rectangle 2 starts at or above Rectangle 1's top edge.

There is no positive Y overlap.

Therefore:

```txt

false

```

---

### Otherwise

If none of the four separation conditions is true:

- X intervals overlap with positive length.
- Y intervals overlap with positive length.

Therefore:

```txt

positive width × positive height = positive area

```

So the rectangles overlap.

## 🧩 Approach 1 — My Solution

### Idea

My solution checks all four ways the rectangles can be separated.

```txt

If Rectangle 2 is:
    right of Rectangle 1
OR  left of Rectangle 1
OR  below Rectangle 1
OR  above Rectangle 1

→ no overlap

Otherwise:

→ overlap

```

### TypeScript

```ts

function isRectangleOverlap(rec1: number[], rec2: number[]): boolean {
    const [x11, y11, x12, y12] = rec1;
    const [x21, y21, x22, y22] = rec2;

    if (
        x21 >= x12 ||
        x22 <= x11 ||
        y22 <= y11 ||
        y21 >= y12
    ) {
        return false;
    }

    return true;
}

```

### Why the inequalities are `>=` and `<=`

This is the important boundary detail.

Consider:

```txt

rec1 = [0, 0, 1, 1]
rec2 = [1, 0, 2, 1]

```

The rectangles touch along the edge:

```txt

x = 1

```

Here:

```txt

x21 === x12

```

The intersection has zero width, so the area is zero.

Our condition:

```txt

x21 >= x12

```

correctly returns `false`.

If we used `>` instead of `>=`, we would incorrectly classify edge-touching rectangles as overlapping.

## ⚖️ Correctness

The algorithm checks all possible ways for two axis-aligned rectangles to have zero intersection area.

They cannot overlap with positive area if one rectangle is completely:

1. Left of the other.
2. Right of the other.
3. Above the other.
4. Below the other.

Our conditions detect these cases:

```txt

x21 >= x12 → Rectangle 2 is right of Rectangle 1.

x22 <= x11 → Rectangle 2 is left of Rectangle 1.

y22 <= y11 → Rectangle 2 is below Rectangle 1.

y21 >= y12 → Rectangle 2 is above Rectangle 1.

```

If any condition is true, at least one dimension has zero overlap, so the intersection area is zero.

If none is true, both the X and Y intervals overlap with positive length.

Therefore the intersection has positive width and positive height, meaning the rectangles have positive area in common.

Thus the algorithm is correct.

## 🏆 Key Takeaways

1. **Axis-aligned geometry can often be decomposed into independent X and Y problems.**

2. A rectangle can be thought of as:

```txt

X interval × Y interval

```

3. Positive-area overlap requires:

```txt

Positive X overlap AND positive Y overlap

```

4. Sometimes it is easier to detect the opposite condition:

```txt

overlap = NOT(separated)

```

5. Boundary conditions matter.

Because touching does not count as overlap, equality must be included:

```txt

>=
<=

```

6. This is essentially an **interval overlap problem wearing a 2D rectangle costume.** 😄

## 📚 Pattern Learned

### Axis-Aligned Rectangle Intersection

For rectangles represented as:

```txt

[x1, y1, x2, y2]

```

think:

```txt

          X dimension
       [x1 -------- x2]

          Y dimension
       [y1 -------- y2]

```

Then:

```txt

Rectangle overlap
       ↓
X intervals overlap positively
       AND
Y intervals overlap positively

```

This pattern is useful in:

- Rectangle intersection
- Collision detection
- Bounding-box collision detection
- Grid geometry
- Computational geometry
- Scheduling/resource interval problems
