# 🧩 Problem #628 - Maximum Product of Three Numbers

**Difficulty:** Easy    
**Topics:** `Array`, `Greedy`, `Sorting`     
**Link:** https://leetcode.com/problems/maximum-product-of-three-numbers/     

---

## 💡 Intuition

At first glance, it seems reasonable to sort the array and multiply the three largest numbers.

However, negative numbers change the situation.

Since

```text
(-a) × (-b) = positive
```

two very small (negative) numbers can produce a large positive value.

Therefore, the maximum product can come from one of only two combinations:

1. The **three largest** numbers.
2. The **largest** number and the **two smallest** (most negative) numbers.

## 🔍 Key Observation

Only two candidate products need to be considered.

### Candidate 1

The three largest numbers.

```text
largest1 × largest2 × largest3
```

### Candidate 2

The largest positive number and the two smallest (most negative) numbers.

```text
largest1 × smallest1 × smallest2
```

No other combination can produce a larger product.

---

## 🧠 Attempt 1 — Sorting

### Idea

Sort the array in ascending order.

After sorting,

* the last three elements are the largest numbers.
* the first two elements are the smallest numbers.

Compute both possible products and return the larger one.

### Solution

```ts
function maximumProduct(nums: number[]): number {
    const n = nums.length;

    if (n === 3) return nums[0] * nums[1] * nums[2];

    nums.sort((a, b) => a - b);

    const option1 = nums[n - 3] * nums[n - 2] * nums[n - 1];
    const option2 = nums[0] * nums[1] * nums[n - 1];

    return Math.max(option1, option2);
}
```

### Complexity

```text
Time  : O(n log n)

Space : O(1)
```

---

## 🧠 Attempt 2 — Single Pass Tracking (Accepted)

### Idea

Sorting is unnecessary.

Only five numbers are ever needed:

* Largest
* Second largest
* Third largest
* Smallest
* Second smallest

Maintain these values while traversing the array once.

### Solution

```ts
function maximumProduct(nums: number[]): number {
    const n = nums.length;

    if (n === 3) return nums[0] * nums[1] * nums[2];

    let large1 = -1001;
    let large2 = -1001;
    let large3 = -1001;

    let small1 = 1001;
    let small2 = 1001;

    for (const num of nums) {

        if (num > large1) {
            large3 = large2;
            large2 = large1;
            large1 = num;
        } else if (num > large2) {
            large3 = large2;
            large2 = num;
        } else if (num > large3) {
            large3 = num;
        }

        if (num < small1) {
            small2 = small1;
            small1 = num;
        } else if (num < small2) {
            small2 = num;
        }
    }

    const option1 = large1 * large2 * large3;
    const option2 = large1 * small1 * small2;

    return Math.max(option1, option2);
}
```

### Complexity

```text
Time  : O(n)

Space : O(1)
```

## 🧠 Dry Run

Input

```text
nums = [-10, -10, 5, 2]
```

During traversal

| Value | Largest 3   | Smallest 2 |
| ----: | ----------- | ---------- |
|   -10 | -10         | -10        |
|   -10 | -10, -10    | -10, -10   |
|     5 | 5, -10, -10 | -10, -10   |
|     2 | 5, 2, -10   | -10, -10   |

Candidate 1

```text
5 × 2 × (-10) = -100
```

Candidate 2

```text
5 × (-10) × (-10) = 500
```

Answer

```text
500
```

## ✅ Why it Works

The product of three numbers is maximized in exactly two scenarios:

### Scenario 1

The array contains large positive numbers.

Using the three largest values produces the maximum product.

### Scenario 2

The array contains two very small negative numbers.

Their product becomes positive.

Multiplying that positive value by the largest positive number may exceed the product of the three largest numbers.

Since every other combination replaces one of these extreme values with a less favourable value, no other product can be larger.

Thus checking only these two candidates is sufficient.

## 🏆 Key Takeaways

* Products behave differently from sums because two negative numbers produce a positive.
* The maximum product depends only on the extreme values.
* Sorting is often a good first solution.
* Once you identify exactly which values matter, sorting can frequently be replaced with a single traversal.
* Always consider both the largest positive values and the smallest negative values in product problems.

| Pattern                   | Trigger Keywords                                             | When to Use                                    | When NOT to Use                           | Complexity   | Notes                                                                   |
| ------------------------- | ------------------------------------------------------------ | ---------------------------------------------- | ----------------------------------------- | ------------ | ----------------------------------------------------------------------- |
| **Track Extremes**        | Maximum product, negative numbers, largest/smallest elements | Only a few extreme values determine the answer | Need the complete sorted order            | `O(n)`       | Maintain the required largest and smallest values during one traversal. |
| **Sorting as a Baseline** | Maximum/minimum values, ordering                             | Quick and simple initial solution              | When only a few extreme values are needed | `O(n log n)` | Useful stepping stone before optimizing.                                |
