# 🧩 Problem #835 – Image Overlap

**Difficulty:** Medium   
**Topics:** `Array`, `Hash Map`    
**Link:** https://leetcode.com/problems/image-overlap/

---

## 📝 Problem Summary

We are given two `n x n` binary matrices representing images.

We can translate one image in any direction — left, right, up, or down — without rotating it.

After translating, we count how many positions contain `1` in both images.

Return the maximum possible overlap.

The important constraint is:

* Translation only.
* No rotation.
* `1`s moved outside the matrix disappear.

---

## 💡 Core Insight

Instead of actually translating the entire image for every possible position, think about the problem from the perspective of individual `1`s.

Suppose:

* A `1` in `img1` is at `(x1, y1)`
* A `1` in `img2` is at `(x2, y2)`

For these two cells to overlap, `img1` would need to be translated by:

`(x2 - x1, y2 - y1)`

So every pair of `1`s tells us:

> "This is the translation required to make these two cells overlap."

Now suppose the same translation occurs for many pairs.

That means all those pairs can overlap simultaneously under that same translation.

Therefore:

> **The maximum frequency of any translation vector is the maximum possible overlap.**

---

## 🎯 Pattern Recognition

When a problem involves:

* Moving/translation of points
* Matching positions after a transformation
* Finding the transformation that creates the most matches

Think about the **difference between coordinates**.

Instead of trying every transformation and checking the entire matrix:

`point in A → point in B`

and calculate:

`B - A`

Then count how frequently each transformation occurs.

This converts a geometric transformation problem into a frequency-counting problem.

## 🚀 Evolution of Thought Process

### Brute Force Thinking

One possible first thought is:

1. Translate `img1` in every possible direction.
2. Compare it against `img2`.
3. Count overlapping `1`s.
4. Keep the maximum.

There are `O(n²)` possible translations, and checking an entire `n x n` matrix for each translation costs `O(n²)`.

That gives:

`O(n⁴)`

This is actually acceptable for `n <= 30`.

But we can think more directly.

### Observation

We don't actually care about every `0`.

Only the positions containing `1` can contribute to the overlap.

So first extract the coordinates of all `1`s.

For every `1` in `img1` and every `1` in `img2`, calculate the translation required to make them overlap.

For example:

`img1: (1, 2)`
`img2: (3, 5)`

Required translation:

`(3 - 1, 5 - 2) = (2, 3)`

If another pair also requires `(2, 3)`, then both pairs overlap when we translate `img1` by `(2, 3)`.

So we simply count translation frequencies.

### Final Approach

1. Store coordinates of all `1`s in both images.
2. For every pair `A[i]` and `B[j]`:

   * Calculate `dx = B[j].x - A[i].x`
   * Calculate `dy = B[j].y - A[i].y`
3. Use `(dx, dy)` as a key in a frequency map.
4. The largest frequency is the answer.

---

## 🔍 Detailed Reasoning

Let:

`A = positions of 1s in img1`

`B = positions of 1s in img2`

Consider:

`A[i] = (x1, y1)`

and:

`B[j] = (x2, y2)`

If we translate `A[i]` to `B[j]`, then:

`x1 + dx = x2`

`y1 + dy = y2`

Therefore:

`dx = x2 - x1`

`dy = y2 - y1`

So every pair generates one translation vector:

`(dx, dy)`

### Why does frequency represent overlap?

Suppose the translation `(2, 1)` occurs 3 times.

That means there are 3 pairs of `1`s such that translating `img1` by `(2, 1)` makes each corresponding pair occupy the same position.

Because the translation is identical for all of them, those overlaps happen simultaneously.

Therefore:

`frequency[(2, 1)] = 3`

means an overlap of at least `3`.

The maximum-frequency translation gives the maximum overlap.

## 🧪 Dry Run

Consider a simplified example.

`img1` has `1`s at:

`A = [(0, 0), (1, 0), (1, 1)]`

`img2` has `1`s at:

`B = [(1, 1), (2, 1), (2, 2)]`

Now calculate translation vectors.

For:

`A[0] = (0, 0)`

against:

`B[0] = (1, 1)`

translation:

`(1, 1)`

Against `B[1] = (2, 1)`:

`(2, 1)`

Against `B[2] = (2, 2)`:

`(2, 2)`

Continue for the remaining points.

Notice that the translation `(1, 1)` occurs repeatedly.

That means translating `img1` by `(1, 1)` causes multiple `1`s to overlap with `img2`.

The answer is therefore the highest frequency among all translation vectors.

## 🧩 Approach 1 — My Solution

### Idea

Extract all coordinates containing `1`.

Then cross-match every `1` from `img1` with every `1` from `img2`.

For each pair, calculate:

`(target position) - (source position)`

and count that translation in a `Map`.

Finally, return the largest count.

### TypeScript

```ts
function largestOverlap(img1: number[][], img2: number[][]): number {
    const A: number[][] = [];
    const B: number[][] = [];
    const n = img1.length;

  // Store coordinates of all 1s.
  for (let i = 0; i < n; i++) {
      for (let j = 0; j < n; j++) {
          if (img1[i][j] === 1) A.push([i, j]);
          if (img2[i][j] === 1) B.push([i, j]);
      }
  }
  
  const store = new Map<string, number>();
  
  // Count how many pairs require each translation.
  for (let i = 0; i < A.length; i++) {
      for (let j = 0; j < B.length; j++) {
          const dx = B[j][0] - A[i][0];
          const dy = B[j][1] - A[i][1];
  
          const key = `${dx},${dy}`;
  
          store.set(key, (store.get(key) ?? 0) + 1);
      }
  }
  
  let maxCount = 0;
  
  for (const count of store.values()) {
      maxCount = Math.max(maxCount, count);
  }
  
  return maxCount;
}
```

### Complexity

Let:

* `a` = number of `1`s in `img1`
* `b` = number of `1`s in `img2`

Building the coordinate lists:

`O(n²)`

Comparing every pair:

`O(a × b)`

Therefore:

**Time:** `O(n² + a × b)`

Since:

`a <= n²`

and:

`b <= n²`

the worst case is:

**Time:** `O(n⁴)`

The map can contain up to `O(a × b)` distinct translation vectors.

**Space:** `O(a × b)`

Worst case:

**Space:** `O(n⁴)`

For `n <= 30`, this is easily manageable.

---

## ⚖️ Correctness

The key invariant is:

> Every pair of `1`s contributes exactly one translation vector that would make those two cells overlap.

For a source cell:

`(x1, y1)`

and target cell:

`(x2, y2)`

the only translation that makes them overlap is:

`(x2 - x1, y2 - y1)`

Therefore, if the same translation vector appears `k` times, there are `k` pairs of cells that overlap under that single translation.

Since every possible pair is considered, every possible overlap is represented by some translation vector.

Therefore, the translation vector with the highest frequency produces the maximum possible overlap.

So:

`maximum frequency = maximum overlap`

## ⚠️ Code Review Notes

### 1. The special edge case is unnecessary

The original solution contained:

```txt
const allCell = n * n;

if (A.length === allCell || B.length === allCell) {
  return Math.min(A.length, B.length);
}
```

This is **correct**, but unnecessary.

The translation-frequency algorithm already handles the all-`1` case naturally.

Removing it makes the solution simpler because there is no need to reason about a special case.

### 2. Complexity is better expressed using the number of `1`s

Instead of immediately thinking:

`O(n⁴)`

the more precise complexity is:

`O(n² + a × b)`

where `a` and `b` are the number of `1`s.

`O(n⁴)` is simply the worst case when both images contain `n²` ones.

This distinction is useful because sparse images can be significantly cheaper.

### 3. No actual translation is required

This is the biggest implementation improvement over a straightforward brute-force simulation.

We never:

* create a translated matrix
* move cells
* check matrix boundaries manually
* compare two complete matrices for every shift

The coordinate difference implicitly handles the translation.

## 🏆 Key Takeaways

1. **Don't simulate a transformation if you can reason about the transformation mathematically.**

2. When matching points after translation, calculate:

`target - source`

3. Identical coordinate differences represent the same transformation.

4. Frequency counting can turn a transformation problem into a simple `Map` problem.

5. Only the `1`s matter. The `0`s contain no information relevant to the overlap.

6. An apparently `O(n⁴)` solution can still be perfectly reasonable when the constraint is small (`n <= 30`).

7. Avoid unnecessary special cases when the general algorithm already handles them.

## 📚 Pattern Learned

### Coordinate Difference + Frequency Map

General pattern:

Given two sets of points `A` and `B`, find the translation that makes the maximum number of points coincide.

For every:

`a ∈ A`

and:

`b ∈ B`

calculate:

`translation = b - a`

Then:

`answer = maximum frequency of translation`

This pattern is useful for problems involving:

* Point translation
* Shape matching
* Maximum alignment
* Relative coordinates
* Detecting repeated geometric transformations

The reusable mental model is:

> **"Instead of moving everything, ask what movement would align this pair."**
