# 🧩 Problem #3483 – Unique 3-Digit Even Numbers

**Difficulty:** Easy  
**Topics:** `Array`, `Hash Map`, `Math`  
**Link:** https://leetcode.com/problems/unique-3-digit-even-numbers/

---

## 📝 Problem Summary

We are given an array of digits.

We need to count how many **distinct 3-digit even numbers** can be formed using the available digit copies.

Rules:

- Each copy of a digit can be used at most once in a number.
- The first digit cannot be `0`.
- The last digit must be even.
- Different index combinations can produce the same number, but that number should only be counted once.

Example:

```txt
digits = [2, 2, 0]
```

The valid numbers are:

```txt
202
220
```

So the answer is `2`.

---

## 💡 Core Insight

A valid 3-digit number has three positions:

```txt
[h][t][u]
```

where:

- `h` = hundreds digit
- `t` = tens digit
- `u` = units digit

There are two important restrictions:

1. `h !== 0`
2. `u` must be even

The other important detail is that **copies of digits matter**.

For example:

```txt
[2, 2, 0]
```

can produce `220` because there are two copies of `2`.

But:

```txt
[2, 3, 0]
```

cannot produce `220` because there is only one `2`.

---

# 🎯 Pattern Recognition

This problem looks like a permutation problem because we are forming a 3-digit number.

The first instinct is:

> Pick a digit for position 1, then position 2, then position 3.

That naturally leads to three nested loops.

However, there is another way to think about it:

> Instead of thinking about individual array indices, think about the **available quantity of each digit**.

Since there are only digits `0` through `9`, we can maintain a frequency table.

This gives us two useful approaches:

1. **Generate using indices and deduplicate with a Set**
2. **Count using digit frequencies without generating duplicate numbers**

---

# 🚀 Evolution of Thought Process

## Step 1 — Generate possible numbers

A 3-digit number requires three digits.

So we can choose:

```txt
i → hundreds
j → tens
k → units
```

We must make sure we don't reuse the same array index.

For example:

```txt
if (i === j) continue;
if (k === i || k === j) continue;
```

This handles the "each copy can only be used once" rule.

---

## Step 2 — Apply the number restrictions

The hundreds digit cannot be zero:

```txt
if (digits[i] === 0) continue;
```

The units digit must be even:

```txt
digits[k] % 2 === 0
```

---

## Step 3 — Handle duplicate numbers

Suppose:

```txt
digits = [2, 2, 2]
```

There are multiple index combinations that generate:

```txt
222
```

But the answer must be `1`.

So we store generated numbers in a `Set`.

This gives us our first approach.

---

# 🧩 Approach 1 — My Solution

## Idea

Enumerate every possible combination of **three different indices**.

For each combination:

1. Skip `0` as the first digit.
2. Don't reuse an index.
3. Require the third digit to be even.
4. Construct the number.
5. Add it to a `Set`.

The `Set` guarantees that the final count contains only distinct numbers.

---

## Detailed Reasoning

Suppose:

```txt
digits = [1, 2, 3, 4]
```

For every possible `i`:

- `i` represents the hundreds digit.

Then for every possible `j`:

- `j` represents the tens digit.

Then for every possible `k`:

- `k` represents the units digit.

We reject invalid choices.

For example:

```txt
i === j
```

means we are trying to use the same copy twice.

Similarly:

```txt
k === i || k === j
```

means the same copy is being reused.

Finally:

```txt
digits[k] % 2 !== 0
```

means the number would not be even.

After constructing the number, we insert it into the `Set`.

---

## Code

```ts
function totalNumbers(digits: number[]): number {
    const n = digits.length;

    const nums = new Set<number>();

    for (let i = 0; i < n; i++) {
        // 0 can't be the first digit
        if (digits[i] === 0) continue;

        const num = digits[i];

        // Second digit
        for (let j = 0; j < n; j++) {
            // Same copy can't be used again
            if (i === j) continue;

            let num2 = num * 10 + digits[j];

            // Third digit
            for (let k = 0; k < n; k++) {
                // Same copy can't be used again
                // Last digit must be even
                if (k === i || k === j || digits[k] % 2 !== 0) {
                    continue;
                }

                const num3 = num2 * 10 + digits[k];

                nums.add(num3);
            }
        }
    }

    return nums.size;
}
```

---

## Why the Set is necessary

Consider:

```txt
digits = [6, 6, 6]
```

The three copies have different indices:

```txt
index 0 → 6
index 1 → 6
index 2 → 6
```

Our loops can generate `666` using different index permutations.

But these are not different numbers.

The problem asks for **distinct numbers**, not distinct ways to construct them.

Therefore:

```txt
Set → removes duplicate numbers
```

This is exactly the right use of a `Set`.

---

## Complexity

There are three nested loops over `n` elements.

Therefore:

**Time:** O(n³)

Since:

```txt
n <= 10
```

this is at most around:

```txt
10 × 10 × 10 = 1000
```

iterations.

So this is extremely small.

The `Set` can contain at most all 3-digit numbers from `100` to `998`, so its size is bounded by a constant-sized domain.

**Space:** O(1) in practical terms, because the number of possible 3-digit numbers is bounded.

More formally, the Set stores at most 900 possible 3-digit numbers.

# 🧩 Approach 2 — Frequency / Combinatorial Counting

## Idea

Instead of iterating over **array indices**, we can iterate over the **digit values** `0` through `9`.

The key change is:

> We don't care which copy of a digit we use. We only care how many copies of that digit are available.

So first build:

```txt
count[d] = number of copies of digit d
```

For example:

```txt
digits = [2, 2, 0]

count[0] = 1
count[2] = 2
```

Now consider choosing:

```txt
hundreds = h
tens     = t
units    = u
```

We only need to check whether the frequency of each digit is sufficient.

---

## The Important Observation

Suppose we want:

```txt
220
```

The required digit counts are:

```txt
2 → 2 copies
0 → 1 copy
```

Since:

```txt
count[2] = 2
count[0] = 1
```

the number is possible.

We don't need to know **which index** provided the first `2` and which provided the second `2`.

That is the advantage of frequency counting.

---

## A Useful Counting View

There are five possible equality patterns among the three positions.

### Case 1 — All three digits are different

Example:

```txt
124
```

We need:

```txt
count[h] >= 1
count[t] >= 1
count[u] >= 1
```

and:

```txt
h != 0
h != t
h != u
t != u
u is even
```

---

### Case 2 — Hundreds and tens are equal

Example:

```txt
224
```

We need two copies of the hundreds digit:

```txt
count[h] >= 2
```

and:

```txt
h != 0
u is even
h != u
```

---

### Case 3 — Hundreds and units are equal

Example:

```txt
242
```

Now the repeated digit is also the units digit.

Since the units digit must be even:

```txt
h === u
h must be even
h != 0
```

and we need:

```txt
count[h] >= 2
```

---

### Case 4 — Tens and units are equal

Example:

```txt
244
```

We need:

```txt
count[u] >= 2
```

because the same even digit is used twice.

The hundreds digit must be non-zero and different from it.

---

### Case 5 — All three digits are equal

Example:

```txt
222
```

We need:

```txt
count[2] >= 3
```

and the digit must be even.

`000` does not count because it is not a 3-digit number.

---

## But There Is an Even Simpler Implementation

We don't actually need to write five separate cases.

Because there are only **10 possible digit values**, we can simply enumerate:

```txt
h = 0 ... 9
t = 0 ... 9
u = 0 ... 9
```

and check whether the selected three digits can be formed from the frequency table.

This is still a counting approach because:

- We iterate over digit values, not array indices.
- We never generate duplicate numbers.
- We don't need a `Set`.
- Frequency counts automatically handle repeated digits.

---

## Frequency Check

For a candidate:

```txt
h, t, u
```

we can temporarily consume one copy of each digit.

Conceptually:

```txt
count[h]--
count[t]--
count[u]--
```

But when digits are equal, we must ensure enough copies exist.

For example:

```txt
h = 2
t = 2
u = 0
```

requires:

```txt
count[2] >= 2
count[0] >= 1
```

A clean way is to calculate how many copies of each selected digit are required.

---

## Code

```ts
function totalNumbers(digits: number[]): number {
    const count = new Array<number>(10).fill(0);

    for (const digit of digits) {
        count[digit]++;
    }

    let answer = 0;

    for (let h = 1; h <= 9; h++) {
        if (count[h] === 0) continue;

        for (let t = 0; t <= 9; t++) {
            if (count[t] === 0) continue;

            for (let u = 0; u <= 8; u += 2) {
                if (count[u] === 0) continue;

                // How many copies of each digit are required?
                const required = new Array<number>(10).fill(0);

                required[h]++;
                required[t]++;
                required[u]++;

                let possible = true;

                for (let digit = 0; digit <= 9; digit++) {
                    if (required[digit] > count[digit]) {
                        possible = false;
                        break;
                    }
                }

                if (possible) {
                    answer++;
                }
            }
        }
    }

    return answer;
}
```

---

## Why This Does Not Need a Set

Consider:

```txt
digits = [6, 6, 6]
```

The loops over digit values consider:

```txt
h = 6
t = 6
u = 6
```

only once.

We never iterate over:

```txt
index 0
index 1
index 2
```

So there are no duplicate constructions of `666`.

The frequency table simply verifies:

```txt
required[6] = 3
count[6] = 3
```

Therefore `666` is counted exactly once.

---

## Improving the Frequency Approach

The previous implementation creates a `required` array for every candidate.

That is unnecessary.

We can directly check the three equality cases.

For a candidate `(h, t, u)`:

- If all three digits are different, each needs one copy.
- If two are equal, that digit needs two copies.
- If all three are equal, that digit needs three copies.

This can be checked directly.

---

## Cleaner Frequency-Based Implementation

```ts
function totalNumbers(digits: number[]): number {
    const count = new Array<number>(10).fill(0);

    for (const digit of digits) {
        count[digit]++;
    }

    let answer = 0;

    for (let h = 1; h <= 9; h++) {
        for (let t = 0; t <= 9; t++) {
            for (let u = 0; u <= 8; u += 2) {
                if (count[h] === 0 || count[t] === 0 || count[u] === 0) {
                    continue;
                }

                if (h === t && t === u) {
                    if (count[h] >= 3) {
                        answer++;
                    }
                } else if (h === t) {
                    if (count[h] >= 2) {
                        answer++;
                    }
                } else if (h === u) {
                    if (count[h] >= 2) {
                        answer++;
                    }
                } else if (t === u) {
                    if (count[t] >= 2) {
                        answer++;
                    }
                } else {
                    // All three digits are different.
                    answer++;
                }
            }
        }
    }

    return answer;
}
```

# ⚖️ Comparison of Approaches

| Criteria | Approach 1 — Index Enumeration | Approach 2 — Frequency Counting |
| --------- | ---------- | ---------- |
| Core Idea | Generate index permutations and deduplicate | Enumerate digit values and validate available frequencies |
| Duplicate Handling | `Set` | Frequency counts |
| Repeated Digits | Naturally handled by different indices | Explicitly handled through counts |
| Leading Zero | Check hundreds digit | Start `h` from `1` |
| Even Number | Check units digit | Iterate `u` over even digits |
| Time | O(n³) | O(10³) = O(1) |
| Space | O(1) bounded Set | O(10) |
| Code Simplicity | Very simple | Slightly more reasoning required |
| Main Advantage | Direct and intuitive | No duplicate generation and demonstrates frequency counting |

# 🔍 Detailed Reasoning

## Why Approach 1 is natural

The input is an array, and every copy matters.

Therefore, thinking in terms of indices is very natural:

```txt
index → digit copy
```

For example:

```txt
[2, 2, 0]

index 0 → first 2
index 1 → second 2
```

This makes the "use each copy once" rule easy.

The only additional problem is that different index combinations can create the same number.

The `Set` solves exactly that.

---

## Why Approach 2 is interesting

Approach 2 changes the mental model.

Instead of asking:

> Which array index should I use?

we ask:

> How many copies of each digit do I have?

That is often a powerful technique when:

- The values come from a small fixed domain.
- Duplicates matter.
- We care about the resulting values rather than the identities of individual elements.

Here the domain is especially small:

```txt
0 ... 9
```

So we can completely ignore the original array positions after building the frequency table.

---

# 🧠 Important Distinction: Combination vs Permutation

There is a subtle terminology point here.

A true mathematical **combination** normally ignores order.

For example:

```txt
{1, 2, 4}
```

would be one combination.

But this problem cares about order:

```txt
124
142
214
241
412
421
```

are different numbers.

So the problem fundamentally involves **arrangements/permutations**, not ordinary combinations.

The second approach is better described as:

> **Frequency-based counting over digit values**

rather than a pure mathematical combination formula.

It is still a counting approach, and it avoids generating index permutations.

# ⏱️ Complexity Analysis

## Approach 1

There are three loops over `n`:

```txt
O(n³)
```

With:

```txt
n <= 10
```

this is effectively constant-sized work.

**Time:** O(n³)  
**Space:** O(1) bounded by the number of possible 3-digit numbers.

---

## Approach 2

There are only 10 possible digit values.

We iterate over:

```txt
h = 1 ... 9
t = 0 ... 9
u = 0, 2, 4, 6, 8
```

So there are at most:

```txt
9 × 10 × 5 = 450
```

candidate numbers.

The frequency table has only 10 entries.

Therefore:

**Time:** O(10³) = O(1)  
**Space:** O(10) = O(1)

The important lesson is that this is not O(n³), because we are no longer looping over the input size. We are looping over a **fixed digit domain**.

# 🏆 Key Takeaways

1. When forming numbers, first identify which positions have restrictions.
   - Hundreds → cannot be `0`.
   - Units → must be even.

2. If the input contains duplicate values, distinguish between:
   - **copies/indices**
   - **distinct values**

3. A `Set` is useful when different constructions can produce the same final result.

4. Frequency counting can eliminate the need to reason about individual copies.

5. A small fixed value domain can turn an apparently input-sized problem into constant-sized enumeration.

6. Don't automatically call every three-loop solution O(n³). Always ask:
   > What is each loop iterating over?

7. "Combination" is not quite the correct mathematical term here because order matters. The second approach is better described as **frequency-based counting**.
