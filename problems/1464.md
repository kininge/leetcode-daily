# 🧩 Problem #1464 - Maximum Product of Two Elements in an Array

**Difficulty:** Easy   
**Topics:** `Array`, `Greedy`    
**Link:** https://leetcode.com/problems/maximum-product-of-two-elements-in-an-array/    

---

## 💡 Intuition

The expression to maximize is

```text
(nums[i] - 1) × (nums[j] - 1)
```

At first glance, it may seem different from simply finding the two largest numbers.

However, subtracting `1` from every element preserves their relative order.

Therefore, the two largest numbers in the original array remain the two largest after the transformation.

So the problem reduces to:

> Find the largest and second largest numbers.

## 🔍 Key Observation

Subtracting the same constant from every number does **not** change their ordering.

Example

```text
Original

9 7 5 2

↓

Subtract 1

8 6 4 1
```

The largest two values remain the largest two values.

Therefore, we only need to identify the two largest numbers.

---

## 🧠 Mathematical Insight

Let

```text
a ≥ b ≥ c
```

Compare

```text
(a - 1)(b - 1)
```

with

```text
(a - 1)(c - 1)
```

Subtract the two expressions:

```text
(a - 1)(b - 1) - (a - 1)(c - 1)

= (a - 1)[(b - 1) - (c - 1)]

= (a - 1)(b - c)
```

Since the constraints guarantee

```text
nums[i] ≥ 1
```

we have

```text
a - 1 ≥ 0
```

and because

```text
b ≥ c
```

we also have

```text
b - c ≥ 0
```

Therefore,

```text
(a - 1)(b - c) ≥ 0
```

which proves

```text
(a - 1)(b - 1) ≥ (a - 1)(c - 1)
```

So, if the first number is fixed, choosing a larger second number always gives an equal or larger product.

The same argument applies to the first number.

Hence, the optimal answer must use the two largest elements.

---

## 🧠 About Expanding the Formula

The expression can be expanded as

```text
(a - 1)(b - 1)

= ab - a - b + 1

= ab - (a + b) + 1
```

Although mathematically correct, this expansion does **not** simplify the problem because both

* `ab`
* `a + b`

change together.

The monotonicity argument is much cleaner and directly explains why the two largest numbers are optimal.

## 🧠 Attempt 1 — Brute Force

Generate every pair.

Compute

```text
(nums[i] - 1) × (nums[j] - 1)
```

Keep the maximum.

### Complexity

```text
Time  : O(n²)

Space : O(1)
```

---

## 🧠 Attempt 2 — Single Pass Tracking (Accepted)

### Idea

Maintain

* largest number
* second largest number

while scanning the array exactly once.

Finally compute

```text
(largest - 1) × (secondLargest - 1)
```

### Your Solution

```ts
function maxProduct(nums: number[]): number {
    let largestNum = 0;
    let secondLargestNum = 0;

    for (const num of nums) {
        if (num > largestNum) {
            secondLargestNum = largestNum;
            largestNum = num;
        } else if (num > secondLargestNum) {
            secondLargestNum = num;
        }
    }

    return (largestNum - 1) * (secondLargestNum - 1);
}
```

## 🧠 Dry Run

Input

```text
nums = [3, 4, 5, 2]
```

| Current | Largest | Second Largest |
| ------: | ------: | -------------: |
|       3 |       3 |              0 |
|       4 |       4 |              3 |
|       5 |       5 |              4 |
|       2 |       5 |              4 |

Answer

```text
(5 - 1) × (4 - 1)

= 4 × 3

= 12
```

---

## ✅ Why it Works

The transformation

```text
x → x - 1
```

is **monotonic increasing**.

That means

```text
if

a > b

then

a - 1 > b - 1
```

So the ordering of the numbers never changes.

Because all transformed values are non-negative (`nums[i] ≥ 1`),

the product is maximized by choosing the two largest transformed values, which correspond to the two largest original values.

Therefore, tracking the largest two numbers is sufficient.

## 🏆 Key Takeaways

* A monotonic transformation preserves the ordering of values.
* Subtracting the same constant from every element does not change which elements are the largest.
* If only the largest few values matter, maintain them during one traversal instead of sorting.
* Mathematical reasoning can often justify a greedy solution.
