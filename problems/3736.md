# 🧩 Problem #3736 – Minimum Moves to Equal Array Elements III

**Difficulty:** Easy  
**Topics:** `Array`, `Greedy`, `Math`  
**Link:** https://leetcode.com/problems/minimum-moves-to-equal-array-elements-iii/

---

## 📝 Problem Summary

We are given an integer array `nums`.

In one move, we can increase any single element by `1`.

We need to find the minimum number of moves required to make every element equal.

### Example

**Input:**
`nums = [2, 1, 3]`

**Output:**
`3`

**Explanation:**

- Increase `2` to `3`: 1 move.
- Increase `1` to `3`: 2 moves.
- The element `3` requires no moves.

Total moves = `1 + 2 + 0 = 3`.

---

## 💡 Core Insight

Since we can only increase elements, we cannot make every element equal to a value smaller than the current maximum.

Therefore, the optimal target is the maximum element already present in the array.

If `maxNum` is the maximum element, every element requires:

`maxNum - nums[i]`

moves to reach the target.

Thus:

`totalMoves = Σ(maxNum - nums[i])`

We can also simplify this mathematically:

`totalMoves = nums.length * maxNum - sum(nums)`

Both formulas calculate the same answer.

---

## 🎯 Pattern Recognition

This problem demonstrates two useful techniques:

1. **Greedy:** Choose the smallest possible target that every element can reach using only increments.
2. **Mathematical simplification:** Replace the sum of individual differences with the difference between the final and current sums.

Whenever an operation changes a value by exactly `1`, consider whether the total number of operations can be calculated using a difference between the desired final state and the initial state.

---

## 🚀 Evolution of Thought Process

### Step 1: Identify the target

We can only increase elements.

For example, with `[2, 1, 3]`, making every element equal to `2` is impossible because `3` cannot be decreased.

Therefore, the target must be at least `3`.

### Step 2: Choose the optimal target

Choosing a target greater than `3` would require additional increments.

Hence, the optimal target is the original maximum: `3`.

### Step 3: Calculate the moves

Approach 1 calculates the difference for each element individually.

Approach 2 observes that every increment increases the array's total sum by exactly `1`.

If the final sum is known, the difference between the final sum and the original sum gives the total number of increments.

---

## 🔍 Detailed Reasoning

Consider:

`nums = [2, 1, 3]`

The maximum element is `3`.

### Approach 1: Sum of Individual Differences

Calculate how much each element must increase:

| Element | Target | Required Moves |
|---------|--------|----------------|
| 2 | 3 | 3 - 2 = 1 |
| 1 | 3 | 3 - 1 = 2 |
| 3 | 3 | 3 - 3 = 0 |

Total moves:

`1 + 2 + 0 = 3`

### Approach 2: Difference Between Sums

The original sum is:

`2 + 1 + 3 = 6`

There are three elements, and each must eventually equal `3`.

Therefore, the final sum will be:

`3 * 3 = 9`

The total number of increments is:

`9 - 6 = 3`

Both approaches produce the same answer.

---

## 🧩 Approach 1 — Find Maximum and Sum Individual Differences

### Idea

1. Find the maximum element.
2. Iterate through the array again.
3. Calculate `maxNum - num` for every element.
4. Add all differences to get the total moves.

### TypeScript Code

```ts
function minMoves(nums: number[]): number {
    const n = nums.length;

    let largestNum = nums[0];

    for (let i = 1; i < n; i++) {
        largestNum = Math.max(largestNum, nums[i]);
    }

    let diff = 0;

    for (const num of nums) {
        diff += largestNum - num;
    }

    return diff;
}
```

### Complexity Analysis

**Time:** `O(n)`

- The first loop finds the maximum in O(n).
- The second loop calculates the differences in O(n).
- Total: O(n) + O(n) = O(n).

**Space:** `O(1)`

Only a constant number of variables are used. No additional data structure is required.

### Advantages

- Easy to understand.
- Directly follows the problem's definition.
- Clearly shows how many moves each element requires.

### Trade-offs

The array is traversed twice, even though the maximum and sum can be calculated in a single traversal.

---

## 🧩 Approach 2 — Maximum Possible Sum Minus Current Sum

### Idea

Instead of calculating every difference separately, calculate the total difference mathematically.

Let:

- `n` = number of elements.
- `largestNum` = maximum element.
- `totalSum` = sum of all original elements.

If every element becomes `largestNum`, the final sum will be:

`totalPossibleSum = n * largestNum`

Every increment adds exactly `1` to the total sum.

Therefore:

`totalMoves = totalPossibleSum - totalSum`

### TypeScript Code

```ts
function minMoves(nums: number[]): number {
    const n = nums.length;

    let largestNum = nums[0];
    let totalSum = nums[0];

    for (let i = 1; i < n; i++) {
        largestNum = Math.max(largestNum, nums[i]);
        totalSum += nums[i];
    }

    const totalPossibleSum = n * largestNum;

    return totalPossibleSum - totalSum;
}
```

### Complexity Analysis

**Time:** `O(n)`

The maximum and total sum are calculated during the same traversal.

**Space:** `O(1)`

Only a constant number of variables are used.

### Advantages

- Traverses the array only once.
- Avoids explicitly calculating every element's difference.
- Uses a simple mathematical formula.

### Trade-offs

The formula is slightly less intuitive at first. Understanding why the difference between the final and original sums equals the number of increments is important.

## 🧪 Dry Run

Input:

`nums = [4, 4, 5]`

### Approach 1

**First pass: Find the maximum**

- Start with `largestNum = 4`.
- Compare the second element: maximum remains `4`.
- Compare the third element: maximum becomes `5`.

**Second pass: Calculate differences**

| Element | Difference |
|---------|------------|
| 4 | 5 - 4 = 1 |
| 4 | 5 - 4 = 1 |
| 5 | 5 - 5 = 0 |

Total moves = `1 + 1 + 0 = 2`.

### Approach 2

**Initialize:**

- `largestNum = 4`
- `totalSum = 4`

**Process the remaining elements:**

| Index | Value | Largest Number | Total Sum |
|-------|-------|----------------|-----------|
| 1 | 4 | 4 | 8 |
| 2 | 5 | 5 | 13 |

The array length is `3`.

Final sum:

`3 * 5 = 15`

Total moves:

`15 - 13 = 2`

**Output:** `2`

## ⚖️ Correctness

### Why is the maximum the optimal target?

Let `M` be the maximum element in the original array.

Because we can only increase elements, the final common value cannot be smaller than `M`.

If we choose a target greater than `M`, every element would require at least as many increments, and the original maximum would require additional increments.

Therefore, choosing `M` minimizes the total number of moves.

### Why does Approach 1 work?

Every element `nums[i]` needs exactly `M - nums[i]` increments to reach `M`.

Adding these differences counts every required increment:

`totalMoves = Σ(M - nums[i])`

Hence, Approach 1 returns the minimum number of moves.

### Why does Approach 2 work?

Using the distributive property:

`Σ(M - nums[i]) = ΣM - Σnums[i]`

Since `M` appears once for each of the `n` elements:

`ΣM = n * M`

Therefore:

`totalMoves = n * M - sum(nums)`

This is exactly the formula used in Approach 2.

Thus, both approaches are correct and return the minimum number of moves.

## 🏆 Key Takeaways

1. **Understand the permitted operations.** When only increments are allowed, the target cannot be smaller than the current maximum.
2. **Choose the optimal target.** Increasing elements beyond the original maximum introduces unnecessary moves.
3. **Look for mathematical simplifications.** A sum of individual differences can sometimes be expressed as a difference between two sums.
4. **Avoid unnecessary passes.** When multiple pieces of information can be calculated in one traversal, consider combining them.
5. **Preserve readability.** The most optimized implementation is not automatically the best if its reasoning becomes unnecessarily complicated.

## 📚 Pattern Learned

### Greedy Target Selection + Mathematical Simplification

This pattern is useful when:

- All elements must reach a common value.
- Operations only increase values.
- Every increment changes the total sum by exactly one.
- The optimal target can be determined directly from the original array.

The key technique is to identify the optimal final state first, then calculate the total cost of reaching it.
