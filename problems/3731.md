# 🧩 Problem #3731 - Find Missing Elements

**Difficulty:** Easy    
**Topics:** `Hash Map`, `Array`    
**Link:** https://leetcode.com/problems/find-missing-elements/description   

---

## 💡 Intuition

The problem states that the array originally contained **every integer in a continuous range**, but some numbers are now missing.

The important observation is:

> The **smallest** and **largest** numbers are guaranteed to still exist.

Therefore, once we know:

- the smallest value
- the largest value

we know the complete range that should exist.

The remaining task is simply checking which numbers in that range are absent.

A `HashSet` makes these membership checks efficient.

## ✅ Solution (HashSet)

```ts
function findMissingElements(nums: number[]): number[] {
    let smallest = 100;
    let largest = 1;
    const existingNums = new Set();

    // O(n)
    for (const num of nums) {
        smallest = Math.min(smallest, num);
        largest = Math.max(largest, num);
        existingNums.add(num);
    }

    const missingNums = [];

    // O(R)
    for (let i = smallest; i <= largest; i++) {
        if (!existingNums.has(i)) {
            missingNums.push(i);
        }
    }

    return missingNums;
}
```

> **Small improvement:** Instead of initializing with constraint values (`100` and `1`), you can initialize both with `nums[0]`. This makes the solution independent of the constraints.

## ✅ Alternative Approach 1 — Boolean Frequency Array

Since

```text
1 <= nums[i] <= 100
```

we can use a fixed-size boolean array.

```text
seen[101]
```

Mark every existing number.

Then traverse

```text
[min ... max]
```

and collect numbers where

```text
seen[i] == false
```

### Complexity

Time

```text
O(n + R)
```

Space

```text
O(101) ≈ O(1)
```

### When to use

- Very small bounded values
- Known maximum value

### Drawback

Depends on the constraints.

If numbers become

```text
10^9
```

this approach no longer works.

---

## ✅ Alternative Approach 2 — Sorting

Sort the array first.

Example

```text
Before

[1,4,2,5]

↓

After

[1,2,4,5]
```

Now compare consecutive elements.

Whenever

```text
nums[i+1] - nums[i] > 1
```

all intermediate numbers are missing.

### Complexity

Sorting

```text
O(n log n)
```

Scanning

```text
O(n)
```

Total

```text
O(n log n)
```

### Why it is worse

Sorting is unnecessary because the problem only requires fast membership checking.

The HashSet solution achieves linear time.

---

## ⚖️ Why HashSet is Preferred

Sorting changes the order and costs

```text
O(n log n)
```

A HashSet allows

```text
Exists?
```

queries in

```text
O(1)
```

average time.

Thus the overall solution becomes

```text
O(n + R)
```

which is optimal.

| Pattern | Trigger Keywords | When to Use | When NOT to Use | Complexity | Notes |
|----------|------------------|-------------|-----------------|------------|-------|
| Hash Set + Range Traversal | Missing elements, unique values, continuous range | Need repeated membership queries | Very small fixed numeric range where boolean array is simpler | **O(n + R)** | Most general solution |
