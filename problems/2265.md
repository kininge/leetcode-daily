# 🧩 Problem #2265 – Count Nodes Equal to Average of Subtree

**Difficulty:** Medium  
**Topics:** `Tree`   
**Link:** https://leetcode.com/problems/count-nodes-equal-to-average-of-subtree/

---

## 📝 Problem Summary

Given the root of a binary tree, count how many nodes have a value equal to the **average of all values in their subtree**.

The subtree of a node includes:

- The node itself
- Every descendant of that node

The average is rounded down to the nearest integer.

For every node, we therefore need two pieces of information about its subtree:

1. Number of nodes
2. Sum of all node values

Once we know these two values, we can calculate:

```txt
average = subtreeSum / subtreeNodeCount
```

and check whether:

```txt
average === node.val
```

---

## 💡 Core Insight

The important observation is:

> To calculate the average of a node's subtree, we need the count and sum of its entire subtree.

But a subtree consists of:

```txt
current node + left subtree + right subtree
```

So instead of calculating the entire subtree repeatedly for every node, let each DFS call return the information its parent needs.

For every node, DFS returns:

```txt
[nodeCount, subtreeSum]
```

Then the current node can combine the information from its children:

```txt
totalCount = leftCount + rightCount + 1

totalSum = leftSum + rightSum + node.val
```

Now we can calculate the average for the current node.

This naturally leads to a **postorder DFS**:

```txt
Left subtree
→ Right subtree
→ Current node
```

The children must be processed first because their information is required to calculate the current node's subtree information.

---

## 🎯 Pattern Recognition

This problem is a classic example of:

**Postorder DFS + returning subtree information**

Whenever a tree problem asks something about the **entire subtree of every node**, ask:

> What information can the children calculate that the parent needs?

Here, the parent needs:

- Number of nodes in the child's subtree
- Sum of values in the child's subtree

So DFS can return exactly those two values.

A useful general pattern is:

```txt
DFS(child) → information about child's subtree

Combine child information → information about current subtree

Use current subtree information → solve current node

Return current subtree information → help parent
```

This pattern appears frequently in tree problems.

## 🚀 Evolution of Thought Process

### 1. Brute Force

One possible first thought is:

For every node:

1. Traverse its entire subtree.
2. Calculate the sum.
3. Calculate the number of nodes.
4. Calculate the average.
5. Check whether it equals the node value.

The problem is that subtree traversal gets repeated.

For example, when processing the root, we traverse almost the entire tree.

Then when processing one of its children, we traverse that child's subtree again.

So the same nodes are processed many times.

In the worst case, this can become **O(n²)**.

---

### 2. Observation

The subtree information calculated for a child does not change.

If we already know:

```txt
left subtree → count + sum

right subtree → count + sum
```

then we don't need to traverse those subtrees again.

We can simply combine their results.

---

### 3. Improvement

Let DFS return:

```txt
[count, sum]
```

For a node:

```txt
count = leftCount + rightCount + 1

sum = leftSum + rightSum + node.val
```

Then:

```txt
average = floor(sum / count)
```

If the average equals the current node's value, increment the answer.

Finally return `[count, sum]` to the parent.

---

### 4. Final Approach

Use a single postorder DFS.

For every node:

1. Get `[count, sum]` from the left subtree.
2. Get `[count, sum]` from the right subtree.
3. Add the current node.
4. Calculate the subtree average.
5. Update the answer if necessary.
6. Return the current subtree's `[count, sum]`.

Every node is processed once.

---

## 🔍 Detailed Reasoning

Consider:

```txt
        4
       / \
      8   5
     / \   \
    0   1   6
```

Start from the bottom because we need subtree information.

### Node 0

Its subtree contains only itself.

```txt
count = 1
sum = 0
average = 0 / 1 = 0
```

Since:

```txt
average === node.val
0 === 0
```

we count it.

Return:

```txt
[1, 0]
```

---

### Node 1

Similarly:

```txt
count = 1
sum = 1
average = 1 / 1 = 1
```

Count it.

Return:

```txt
[1, 1]
```

---

### Node 8

Its children returned:

```txt
left  = [1, 0]
right = [1, 1]
```

Add node 8:

```txt
count = 1 + 1 + 1 = 3
sum = 0 + 1 + 8 = 9

average = floor(9 / 3) = 3
```

Since:

```txt
3 !== 8
```

we do not count node 8.

Return:

```txt
[3, 9]
```

---

### Node 6

Leaf node:

```txt
count = 1
sum = 6
average = 6
```

Count it.

Return:

```txt
[1, 6]
```

---

### Node 5

Its right subtree returned:

```txt
[1, 6]
```

So:

```txt
count = 0 + 1 + 1 = 2
sum = 0 + 6 + 5 = 11

average = floor(11 / 2) = 5
```

Since:

```txt
5 === 5
```

count node 5.

Return:

```txt
[2, 11]
```

---

### Node 4

Now both children have provided their subtree information:

```txt
left  = [3, 9]
right = [2, 11]
```

Combine them:

```txt
count = 3 + 2 + 1 = 6
sum = 9 + 11 + 4 = 24

average = floor(24 / 6) = 4
```

Since:

```txt
4 === 4
```

count node 4.

The final answer is `5`.

## 🧩 Approach 1 — My Solution

### Idea

Use postorder DFS and return two values from every subtree:

```txt
[nodeCount, subtreeSum]
```

The current node combines the results from its children with its own value.

Then calculate the average and update the global count.

### TypeScript

```txt
function averageOfSubtree(root: TreeNode | null): number {
    let count = 0;

    function DFS(node: TreeNode | null): number[] {
        if (node === null) return [0, 0];

        const [leftCount, leftSum] = DFS(node.left);
        const [rightCount, rightSum] = DFS(node.right);

        const total = leftCount + rightCount + 1;
        const sum = leftSum + rightSum + node.val;

        const avg = Math.floor(sum / total);

        if (avg === node.val) {
            count++;
        }

        return [total, sum];
    }

    DFS(root);

    return count;
}
```

### Why the Base Case Works

For a null child, there are:

```txt
0 nodes
0 sum
```

So:

```txt
return [0, 0]
```

This makes combining the child results very clean.

For example, a leaf node receives:

```txt
left  = [0, 0]
right = [0, 0]
```

and calculates:

```txt
total = 0 + 0 + 1 = 1
sum = 0 + 0 + node.val = node.val
```

Exactly what we need.

## ⚖️ Correctness

For every node, DFS first completely processes its left and right subtrees.

Therefore, when processing the current node, we already know:

- The number of nodes in the left subtree
- The sum of values in the left subtree
- The number of nodes in the right subtree
- The sum of values in the right subtree

The current subtree consists of:

```txt
left subtree + current node + right subtree
```

Therefore:

```txt
subtreeCount = leftCount + rightCount + 1

subtreeSum = leftSum + rightSum + node.val
```

So the calculated average:

```txt
floor(subtreeSum / subtreeCount)
```

is exactly the average defined by the problem.

If this average equals `node.val`, the node satisfies the condition and is counted.

Since every node is processed exactly once, every qualifying node is counted exactly once.

Therefore the algorithm is correct.

## ⏱️ Complexity Analysis

Let `n` be the number of nodes.

### Time

**O(n)**

Each node is visited exactly once.

At each node, we perform constant-time work:

- Combine two child results
- Calculate the average
- Compare with `node.val`

Therefore:

```txt
O(n)
```

### Space

**O(h)**

where `h` is the height of the tree.

The recursive DFS uses the call stack.

For a balanced tree:

```txt
h = O(log n)
```

For a completely skewed tree:

```txt
h = O(n)
```

So the worst-case auxiliary space is:

```txt
O(n)
```

## 🏆 Key Takeaways

1. **Subtree problems often suggest postorder DFS.**

   If the current node depends on information about its descendants, process children first.

2. **Return useful information from DFS.**

   Instead of traversing a subtree repeatedly, calculate its information once and return it to the parent.

3. **Define exactly what DFS returns.**

   Here:

   ```txt
   DFS(node) → [number of nodes in subtree, sum of values in subtree]
   ```

4. **Combine child results to build parent results.**

   ```txt
   currentCount = leftCount + rightCount + 1

   currentSum = leftSum + rightSum + node.val
   ```

5. **Don't optimize unnecessarily.**

   Returning arrays creates small allocations, but with at most 1000 nodes this is completely fine. The important optimization is avoiding repeated subtree traversal.

6. **Recognize the reusable pattern.**

   ```txt
   Postorder DFS
   → gather child information
   → calculate current subtree information
   → solve current node
   → return information to parent
   ```

## 📚 Pattern Learned

### Postorder DFS with Subtree Aggregation

When a problem asks something about every node's subtree, look for an aggregate that can be calculated from the children.

Common examples include:

- Subtree sum
- Subtree size
- Maximum/minimum value
- Height
- Number of special nodes
- Balance information
- Custom DP state

The key question to ask is:

> "What information should my DFS return so that the parent can solve its own problem?"

For this problem, the answer is:

```txt
count + sum
```

That single observation turns a potentially repeated traversal into a clean `O(n)` solution.

## 🧠 Final Mental Model

When you see:

> "For every node, calculate something about its entire subtree..."

Don't immediately think:

```txt
"Traverse the subtree for every node."
```

Instead think:

```txt
"Can I calculate the subtree information once and pass it upward?"
```

If yes, **postorder DFS** is probably your friend.

For this problem:

```txt
Child subtree
    ↓
[count, sum]
    ↓
combine at parent
    ↓
[parentCount, parentSum]
    ↓
continue upward
```

That's the entire trick behind the `O(n)` solution.
