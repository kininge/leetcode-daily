# 🧩 Problem #1385 – Find the Distance Value Between Two Arrays

**Difficulty:** Easy  
**Topics:** `Array`, `Sorting`, `Binary Search`  
**Link:** https://leetcode.com/problems/find-the-distance-value-between-two-arrays/

---

## 📝 Problem Summary

Given two integer arrays `arr1` and `arr2`, and an integer `d`, return the number of elements in `arr1` for which there is no element in `arr2` satisfying:

`|arr1[i] - arr2[j]| <= d`

An element `x` from `arr1` contributes to the answer only if its distance from every element in `arr2` is strictly greater than `d`.

---

## 💡 Core Insight

For every element `x` in `arr1`, we need to determine whether:

`|x - y| > d` for every `y` in `arr2`.

Equivalently, there must be no element of `arr2` inside:

`[x - d, x + d]`

This interval observation is the foundation of the improved solution.

---

## 🎯 Pattern Recognition

The problem involves checking whether any element of one array falls within a specific range around an element of another array.

This suggests two approaches:

1. **Min/Max + Linear Search:** Use the minimum and maximum of `arr2` to eliminate unnecessary comparisons.
2. **Sorting + Binary Search:** Sort `arr2` and efficiently find whether an element exists inside the required interval.

---

## 🚀 Evolution of Thought Process

### Step 1 — Brute Force

For every element in `arr1`, compare it with every element in `arr2`.

If any absolute difference is less than or equal to `d`, that element doesn't contribute to the answer.

Complexity: `O(n * m)`.

### Step 2 — My Optimization: Minimum and Maximum

Instead of immediately scanning `arr2`, first calculate its minimum and maximum values.

For an element `x`:

- If `x >= max(arr2)`, the closest element is the maximum.
- If `x <= min(arr2)`, the closest element is the minimum.
- Otherwise, scan `arr2` to find the closest element.

This avoids unnecessary comparisons for elements outside the range of `arr2`.

However, elements inside the range may still require a complete scan.

Worst-case complexity remains `O(n * m)`.

### Step 3 — Improved Approach: Sorting + Binary Search

The key observation is that we don't need to calculate the actual minimum distance.

We only need to determine whether an element exists inside:

`[x - d, x + d]`

After sorting `arr2`, binary search can locate the first element greater than or equal to `x - d`.

If that element is less than or equal to `x + d`, a nearby element exists, so `x` should not be counted.

Otherwise, `x` contributes to the answer.

---

## 🔍 Detailed Reasoning

### Approach 1 — My Solution (Min/Max Optimization)

First, calculate:

- `smallest`: Minimum element in `arr2`.
- `largest`: Maximum element in `arr2`.

For every `num` in `arr1`:

1. Calculate its distance from the minimum and maximum.
2. If `num` is outside the range of `arr2`, the corresponding boundary gives the minimum possible distance.
3. Otherwise, scan `arr2` to find the minimum absolute difference.
4. If the minimum difference is greater than `d`, increment the answer.

**Important observation:**

When `num` is greater than or equal to the maximum, the maximum is the closest element in `arr2`.

When `num` is smaller than or equal to the minimum, the minimum is the closest element in `arr2`.

This is why those cases don't require a complete scan.

### Approach 2 — Improved Solution (Sorting + Binary Search)

For each `num` in `arr1`, calculate:

- `lowerBound = num - d`
- `upperBound = num + d`

We need to find whether `arr2` contains any element in this interval.

After sorting `arr2`, perform binary search to find the first element greater than or equal to `lowerBound`.

There are two possibilities:

**Case 1:** No such element exists.

The search position is equal to `arr2.length`.

No element can be inside the interval, so count `num`.

**Case 2:** An element exists.

Check the element at the returned position:

- If `arr2[position] <= upperBound`, an element exists inside the interval. Don't count `num`.
- Otherwise, no element exists inside the interval. Count `num`.

## 🧪 Dry Run

Input:

`arr1 = [4, 5, 8]`  
`arr2 = [10, 9, 1, 8]`  
`d = 2`

Sorted `arr2`:

`[1, 8, 9, 10]`

| num | Search interval | First element >= lower bound | Result |
|-----|-----------------|------------------------------|--------|
| 4 | [2, 6] | 8 | Count |
| 5 | [3, 7] | 8 | Count |
| 8 | [6, 10] | 8 | Don't count |

For `4`:

The first element greater than or equal to `2` is `8`.

Since `8 > 6`, there is no element inside `[2, 6]`.

Count it.

For `5`:

The first element greater than or equal to `3` is `8`.

Since `8 > 7`, there is no element inside `[3, 7]`.

Count it.

For `8`:

The first element greater than or equal to `6` is `8`.

Since `8 <= 10`, an element exists inside `[6, 10]`.

Don't count it.

**Answer: 2**

## 🧩 Approach 1 — My Solution

```ts
function findTheDistanceValue(
    arr1: number[],
    arr2: number[],
    d: number
): number {
    let largest = arr2[0];
    let smallest = arr2[0];

    // Find the minimum and maximum of arr2.
    for (let i = 1; i < arr2.length; i++) {
        largest = Math.max(largest, arr2[i]);
        smallest = Math.min(smallest, arr2[i]);
    }

    let count = 0;

    for (const num of arr1) {
        const upperDiff = Math.abs(num - largest);
        const lowerDiff = Math.abs(num - smallest);

        let diff = Math.min(upperDiff, lowerDiff);

        if (num >= largest) {
            diff = upperDiff;
        } else if (num <= smallest) {
            diff = lowerDiff;
        } else {
            if (diff > d) {
                for (let i = 0; i < arr2.length; i++) {
                    const currentDiff = Math.abs(num - arr2[i]);

                    diff = Math.min(diff, currentDiff);

                    if (diff <= d) break;
                }
            }
        }

        if (diff > d) {
            count++;
        }
    }

    return count;
}
```

### Complexity Analysis

Let:

- `n` = length of `arr1`
- `m` = length of `arr2`

**Time:** `O(m + n * m)` = `O(n * m)` worst case.

**Space:** `O(1)` auxiliary space.

The min/max optimization can reduce actual comparisons, but it does not improve the worst-case asymptotic complexity.

## 🧩 Approach 2 — Improved Solution

### Sorting + Binary Search

```ts
function findTheDistanceValue(
    arr1: number[],
    arr2: number[],
    d: number
): number {
    arr2.sort((a, b) => a - b);

    let count = 0;

    for (const num of arr1) {
        const lowerBound = num - d;
        const upperBound = num + d;

        let left = 0;
        let right = arr2.length;

        // Find the first element >= lowerBound.
        while (left < right) {
            const mid = left + Math.floor((right - left) / 2);

            if (arr2[mid] < lowerBound) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }

        // No element exists inside [lowerBound, upperBound].
        if (left === arr2.length || arr2[left] > upperBound) {
            count++;
        }
    }

    return count;
}
```

### Complexity Analysis

Let:

- `n` = length of `arr1`
- `m` = length of `arr2`

**Time:** `O(m log m + n log m)`

- Sorting `arr2`: `O(m log m)`
- Binary search for each element of `arr1`: `O(n log m)`

**Space:** `O(log m)` auxiliary space for sorting, depending on the JavaScript engine's sorting implementation.

## ⚖️ Correctness

### Approach 1

The minimum and maximum elements define the boundaries of `arr2`.

For values outside these boundaries, the closest element must be the corresponding boundary.

For values inside the boundaries, the solution scans all elements until it finds a distance less than or equal to `d`, or finishes the scan.

Therefore, an element is counted exactly when its minimum distance from `arr2` is greater than `d`.

### Approach 2

After sorting, binary search finds the first element greater than or equal to `num - d`.

If that element is less than or equal to `num + d`, it belongs to the forbidden interval.

If no such element exists, or the first qualifying element is greater than `num + d`, no element exists inside the interval.

Therefore, the element is counted exactly when every element in `arr2` has an absolute difference greater than `d`.

| Criteria | Approach 1 — My Solution | Approach 2 — Improved |
|----------|-------------------------|----------------------|

| Sorting Required | No | Yes |
| Best For | Small arrays and simple implementation | Larger arrays and efficient range checks |

## 🏆 Key Takeaways

1. Minimum and maximum values can help eliminate unnecessary comparisons.
2. Always look for opportunities to transform absolute-difference conditions into interval conditions.
3. Sorting makes range-based searching easier.
4. Binary search is useful when the question asks whether an element exists within a range.
5. Finding the first element greater than or equal to a target is a classic lower-bound binary search pattern.
6. An optimization that improves average performance does not necessarily improve worst-case complexity.
