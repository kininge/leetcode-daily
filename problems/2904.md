# 🧩 Problem #2904 – Shortest and Lexicographically Smallest Beautiful String

**Difficulty:** Medium  
**Topics:** `String`, `Sliding Window`, `Two Pointers`  
**Link:** https://leetcode.com/problems/shortest-and-lexicographically-smallest-beautiful-string/

---

## 📝 Problem Summary

You are given:

- A binary string `s`
- An integer `k`

A substring is called **beautiful** if it contains exactly `k` occurrences of `'1'`.

We need to:

1. Find the **shortest** beautiful substring.
2. If multiple beautiful substrings have the same shortest length, return the **lexicographically smallest** one.
3. If no beautiful substring exists, return `""`.

---

### Example

```txt
s = "1011"
k = 2
```

Possible beautiful substrings include:

```txt
"101"
"1011"
"11"
```

The shortest one is:

```txt
"11"
```

Therefore:

```txt
answer = "11"
```

---

## 💡 Intuition

The most important condition is:

```txt
number of 1s == k
```

This naturally suggests a **sliding window**.

We can use the mental model:

```txt
EXPAND
   ↓
condition becomes valid
   ↓
CONTRACT
   ↓
find the shortest valid window
   ↓
expand again
```

While expanding:

```txt
ones < k
```

so we continue adding characters.

Once:

```txt
ones == k
```

the window is beautiful.

Now we try to contract it from the left while keeping exactly `k` ones.

Every valid window is a candidate answer.

---

## 🧠 Key Observation

There are two important optimization criteria, in this order:

```txt
1. Shorter length is always better.
2. If lengths are equal, lexicographically smaller is better.
```

Therefore, when comparing a candidate `window` with the current answer:

```txt
if window.length < ans.length
```

the candidate wins.

If the lengths are equal:

```txt
window < ans
```

the lexicographically smaller candidate wins.

---

# 🛠 Approach 1 — Sliding Window

## Idea

Maintain:

```txt
left
right
ones
```

where `ones` is the number of `'1'` characters inside the current window.

### Expand

Move `right` forward until:

```txt
ones === k
```

Now the window is beautiful.

### Contract

Move `left` forward while the window still contains exactly `k` ones.

Leading zeroes can be removed freely.

But when the character at `left` is a `1`, removing it would produce:

```txt
ones = k - 1
```

which makes the window invalid.

So that is where we stop.

---

## Original Solution

Your original implementation follows exactly this idea:

```ts
function shortestBeautifulSubstring(s: string, k: number): string {
    let ans = '';
    let ones = 0;
    let left = 0;
    let right = 0;

    while (right < s.length) {

        // Expand window until condition becomes true
        while (right < s.length) {
            if (s[right] === '1') ones++;

            right++;

            if (ones === k) break;
        }

        // Contract while window is beautiful
        while (left < right) {
            const window = s.substring(left, right);

            if (ones === k) {
                if (ans === '') ans = window;
                if (window.length < ans.length) ans = window;
                if (window.length === ans.length && window < ans) {
                    ans = window;
                }
            }

            if (s[left] === '1') {
                if ((ones + 1) === k) break;
                else ones--;
            }

            left++;
        }
    }

    return ans;
}
```

---

## 🔍 What Is Correct in Your Solution?

Your most important observation is correct:

> Once the window contains exactly `k` ones, keep contracting it until removing the next character would make the number of ones smaller than `k`.

This part:

```ts
if (s[left] === '1') {
    if ((ones + 1) === k) break;
    else ones--;
}
```

is effectively detecting:

```txt
ones === k
AND
s[left] === '1'
```

because if the left character is `1`, removing it would change:

```txt
k → k - 1
```

So the current window cannot be contracted further.

---

## 🔧 Improvement to Your Approach

The main unnecessary work in your solution is this:

```ts
const window = s.substring(left, right);
```

You create a substring **on every contraction step**.

But many of those windows are not useful.

For example:

```txt
0001101
^
left
```

If we have already found a valid window and `left` points to a leading `0`, we don't need to create:

```txt
"0001101"
"001101"
"01101"
```

and compare all of them.

We can first remove all leading zeroes.

Then create **one candidate** when the window is minimal for that `right`.

---

## Improved Sliding Window

```ts
function shortestBeautifulSubstring(s: string, k: number): string {
    let left = 0;
    let ones = 0;
    let answer = '';

    for (let right = 0; right < s.length; right++) {
        if (s[right] === '1') {
            ones++;
        }

        // Window is not beautiful yet.
        if (ones < k) continue;

        // Remove unnecessary leading zeroes.
        while (s[left] === '0') {
            left++;
        }

        const candidate = s.substring(left, right + 1);

        if (
            answer === '' ||
            candidate.length < answer.length ||
            (candidate.length === answer.length && candidate < answer)
        ) {
            answer = candidate;
        }

        // Remove the first '1'.
        // The current window becomes invalid,
        // so the next valid window must contain a future '1'.
        ones--;
        left++;
    }

    return answer;
}
```

---

## Why This Improvement Works

Once:

```txt
ones === k
```

we remove all leading zeroes:

```txt
00011001
^^^
```

becomes:

```txt
11001
```

Those zeroes are unnecessary because removing them:

- does not change the number of `1`s
- makes the substring shorter

Therefore keeping them can never produce the shortest answer.

After removing the leading zeroes, we have the shortest beautiful substring ending at the current `right`.

Then we remove its first `1`:

```txt
11001
^
```

After removing that `1`:

```txt
1001
```

contains only `k - 1` ones.

Therefore the current window is no longer beautiful.

We then continue expanding `right` until another `1` restores:

```txt
ones === k
```

The next window will become valid when another `1` enters.

# 🚀 Approach 2 — Positions of `1`s

There is an even cleaner observation.

Instead of thinking about every character, think only about the positions of the `1`s.

Suppose:

```txt
s = "100011001"
```

The positions of `1`s are:

```txt
[0, 4, 5, 8]
```

For a beautiful substring containing exactly `k` ones, we need **k consecutive `1`s**.

For example, if:

```txt
k = 3
```

we have two groups:

```txt
[0, 4, 5]
[4, 5, 8]
```

The shortest substring containing the first group is:

```txt
s[0 ... 5] = "100011"
```

The shortest substring containing the second group is:

```txt
s[4 ... 8] = "11001"
```

Compare lengths:

```txt
"100011" → length 6
"11001"  → length 5
```

Therefore:

```txt
"11001"
```

is the shortest beautiful substring.

---

## Why `k` Consecutive `1`s Are Enough

Suppose the substring contains exactly `k` ones.

Those `k` ones must appear consecutively in the list of all `1` positions.

For example:

```txt
1 positions:

[2, 5, 6, 9, 12]
```

For:

```txt
k = 3
```

the possible groups are:

```txt
[2, 5, 6]
[5, 6, 9]
[6, 9, 12]
```

Each group gives the shortest substring that contains exactly those three `1`s.

So instead of checking every possible substring, we only need to examine these groups.

---

## Code (TypeScript)

```ts
function shortestBeautifulSubstring(s: string, k: number): string {
    const onePositions: number[] = [];

    for (let i = 0; i < s.length; i++) {
        if (s[i] === '1') {
            onePositions.push(i);
        }
    }

    if (onePositions.length < k) {
        return '';
    }

    let answer = '';

    for (let i = 0; i + k - 1 < onePositions.length; i++) {
        const start = onePositions[i];
        const end = onePositions[i + k - 1];

        const candidate = s.substring(start, end + 1);

        if (
            answer === '' ||
            candidate.length < answer.length ||
            (candidate.length === answer.length && candidate < answer)
        ) {
            answer = candidate;
        }
    }

    return answer;
}
```

## ⚖️ Correctness

For every candidate group of `k` consecutive `1`s:

- The substring starts at the first `1`.
- The substring ends at the `k`th `1`.
- Therefore it contains exactly `k` ones.
- Removing either boundary would remove one of those required `1`s.

So the candidate is the **shortest substring containing that particular group of `k` ones**.

By checking every group of `k` consecutive `1`s, we check every possible shortest beautiful substring.

Then we choose:

```txt
minimum length
        ↓
lexicographically smallest if tied
```

Therefore the returned candidate is exactly the required answer.

## 📊 Comparison of Approaches

| Criteria | 🛠 Approach 1 — Sliding Window | 🚀 Approach 2 — Positions of `1`s |
|---|---|---|
| Core Idea | Expand until `k` ones, then contract | Store positions of all `1`s and examine groups of `k` |
| Mental Model | `EXPAND → CONTRACT → EXPAND` | `1 positions → k consecutive ones → candidate` |
| Data Structure | Two pointers | Array of `1` positions |
| Handles shortest length | Yes | Yes |
| Handles lexicographic tie | Yes | Yes |
| Time Complexity | O(n) pointer movement + substring/comparison costs | O(n) to find positions + candidate processing |
| Space Complexity | O(1) auxiliary space | O(n) for `1` positions |
| Main Strength | Preserves sliding-window pattern | Cleaner mathematical observation |
| Main Weakness | Slightly more state management | Requires recognizing the `k` consecutive `1`s observation |
| Best Learning Value | Sliding-window contraction | Pattern recognition around significant elements |

## 🏆 Final Recommendation

Your original solution is **correct**, and the important thing is that your sliding-window reasoning is solid.

The improvement is mainly about avoiding unnecessary candidate construction during every contraction.

The second approach gives an even cleaner observation:

```txt
Exactly k ones
      ↓
k consecutive 1s in the positions array
      ↓
Shortest substring is between first and last 1
      ↓
Compare candidates
```

For learning, both approaches are valuable:

- **Approach 1** reinforces your sliding-window mental model.
- **Approach 2** teaches an important pattern: when only certain characters matter, consider compressing the input to the positions of those characters.

### Key Takeaways

- For a condition like **exactly `k` occurrences**, sliding window is a natural candidate.
- Leading zeroes do not contribute to the number of `1`s, so they can be removed when minimizing length.
- If a problem's condition depends heavily on one character, consider storing the positions of that character.
- `k` consecutive occurrences of the important character can represent the candidate windows.
- When optimizing multiple criteria, handle them in priority order:

```txt
1. Shortest length
2. Lexicographically smallest
```

For this problem:
