# 🧩 Problem #3090 - Maximum Length Substring With Two Occurrences

**Difficulty:** Easy  
**Topics:** `Sliding Window`, `Two Pointers`  
**Link:** https://leetcode.com/problems/maximum-length-substring-with-two-occurrences/   

---

## 💡 Intuition

We need to find the **maximum length substring** where every character appears at most **twice**.

The important words are:

```text
maximum length
substring
at most 2 occurrences
```

This strongly suggests a **sliding window**.

The mental model used here is:

```text
Expand window
      ↓
Condition fails
      ↓
Contract window
      ↓
Condition becomes valid
      ↓
Expand again
```

This is the same `expand → violate → contract → valid → expand` pattern.

# 🔍 What Does "Good Window" Mean?

For this problem, a window is valid if:

```text
frequency(character) <= 2
```

for **every character**.

For example:

```text
"bcbb"
```

has:

```text
b → 2
c → 1
```

Therefore it is valid.

But:

```text
"bcbbb"
```

has:

```text
b → 3 ❌
```

Therefore the window is invalid.

---

# 🧠 Core Idea

Maintain a window:

```text
[left ........ right]
```

and an array storing the frequency of each character.

Because the string contains only lowercase English letters, we can use:

```ts
const frequency = new Array(26).fill(0);
```

instead of a `Map`.

# 🚀 Evolution of Thought Process

## Brute Force

We could generate every substring:

```text
[0...0]
[0...1]
[0...2]
...

[1...1]
[1...2]
...
```

There are:

```text
O(n²)
```

substrings.

Checking the frequency of each substring would make this too expensive for a larger version of the problem.

---

## Sliding Window Observation

A substring is contiguous.

So instead of rebuilding every substring, maintain one window.

Start with:

```text
left = 0
right = 0
```

Then:

```text
EXPAND
```

by moving `right`.

If the window becomes invalid:

```text
frequency[character] > 2
```

then:

```text
CONTRACT
```

by moving `left`.

---

# 🧠 The Important Insight

When we add:

```text
s[right]
```

only that character's frequency changes.

Before expansion, the window was valid.

Therefore, after adding one character, the **only possible violation** is:

```text
frequency[s[right]] > 2
```

We don't need to scan all 26 characters to determine whether the window became invalid.

# 🧠 Your Preferred Sliding Window Structure

This problem fits exactly into:

```text
┌──────────────────────┐
│    EXPAND WINDOW     │
└──────────┬───────────┘
           ↓
     Condition valid?
       /          \
     YES           NO
      ↓             ↓
   Continue      CONTRACT
      ↑             ↓
      └──── VALID ──┘
```

Or simply:

```text
Expand until condition fails
              ↓
Contract until condition is right
              ↓
Expand again
```

This is the main pattern to remember.

# ✅ Solution

This implementation intentionally keeps the **expand → fail → contract** structure.

```ts
function maximumLengthSubstring(s: string): number {
    const n = s.length;

    let longestSubstring = 0;

    let left = 0;
    let right = 0;

    const frequency = new Array(26).fill(0);

    while (right < n) {
        let overflowChar = '';

        // -------------------------
        // EXPAND WINDOW
        // -------------------------
        while (right < n) {
            const index = s.charCodeAt(right) - 97;

            frequency[index]++;

            // Window became invalid.
            if (frequency[index] > 2) {
                overflowChar = s[right];
                break;
            }

            right++;

            const windowSize = right - left;

            longestSubstring = Math.max(
                longestSubstring,
                windowSize
            );
        }

        // -------------------------
        // CONTRACT WINDOW
        // -------------------------
        if (overflowChar !== '') {
            while (left < right) {
                const char = s[left];
                const index = char.charCodeAt(0) - 97;

                frequency[index]--;
                left++;

                // We removed the overflowing character.
                // Its frequency is now valid again.
                if (char === overflowChar) {
                    break;
                }
            }

            // overflowChar itself was already added
            // during expansion, so move right past it.
            right++;
        }
    }

    return longestSubstring;
}
```

---

# 🔎 Why `right++` Happens After Contraction

This is a subtle part of the implementation.

Suppose:

```text
s = "aaa"
```

and maximum frequency is `2`.

During expansion:

```text
right = 0 → add a
right = 1 → add a
right = 2 → add a
```

The third `a` causes:

```text
frequency[a] = 3
```

But this `a` has **already been added to the frequency array**.

So when we contract, we remove characters from the left until the overflowing character becomes valid.

After that, `right` still points at the overflowing character.

Therefore we move it forward:

```ts
right++;
```

This is why the control flow in this implementation looks slightly different from the more common:

```text
add right
while invalid:
    remove left
```

template.

---

# ⚖️ Why the Algorithm Is Correct

At the beginning of every expansion phase, the current window is valid.

We add characters until either:

```text
right == n
```

or:

```text
frequency[currentCharacter] > 2
```

If the window becomes invalid, we remove characters from the left.

Because we remove elements in their original order, eventually the overflowing character's frequency decreases back to:

```text
<= 2
```

At that point the window is valid again.

Then we continue expanding.

Therefore, every valid window considered by the algorithm satisfies:

```text
frequency(character) <= 2
```

for every character.

And we keep the maximum length among those valid windows.

# ⏱️ Complexity Analysis

Let:

```text
n = s.length
```

## Time

At first glance, there are nested loops:

```ts
while (right < n) {
    while (right < n) {
        ...
    }

    while (left < right) {
        ...
    }
}
```

This does **not** mean `O(n²)`.

Why?

Because both pointers only move forward.

### `right`

```text
0 → 1 → 2 → ... → n
```

At most `n` movements.

### `left`

```text
0 → 1 → 2 → ... → n
```

At most `n` movements.

Therefore:

```text
O(n + n)
```

which simplifies to:

```text
O(n)
```

This is the classic **amortized O(n)** sliding-window argument.

---

## Space

The frequency array contains exactly 26 entries:

```ts
new Array(26)
```

Therefore:

```text
O(26)
```

which is:

```text
O(1)
```

# 🆚 Why Use an Array Instead of a Map?

The constraints say:

```text
s consists of lowercase English letters
```

There are exactly:

```text
26
```

possible characters.

Therefore:

```ts
const frequency = new Array(26).fill(0);
```

is ideal.

Character → index:

```ts
const index = s.charCodeAt(i) - 97;
```

For example:

```text
'a' → 0
'b' → 1
'c' → 2
...
'z' → 25
```

So:

```text

```

stores the count.

# 🧭 Pattern Recognition Handbook

| Pattern | Trigger Keywords | When to Use | Complexity | Notes |
|---|---|---|---|---|
| **Expand → Contract Sliding Window** | Longest substring/subarray, at most `K`, frequency constraint | Validity can be restored by removing from left | **O(n)** | Both pointers only move forward |
| **Frequency Array** | Lowercase letters / bounded values | Value domain is small and fixed | **O(1)** space | Excellent for 26 lowercase letters |
| **Frequency Map** | Frequency/count constraints with arbitrary values | Values can be large or unknown | **O(n)** space | More general than an array |
| **Two Pointers** | Contiguous range / ordered movement | Two boundaries move monotonically | Usually **O(n)** | Sliding window is a specialized form |
