# 🧩 Problem #3069 – Distribute Elements Into Two Arrays I

**Difficulty:** Easy  
**Topics:** `Array`, `Simulation`  
**Link:** https://leetcode.com/problems/distribute-elements-into-two-arrays-i/

---

## 📝 Problem Summary

You are given a `1-indexed` array `nums`.

We need to distribute its elements into two arrays, `arr1` and `arr2`.

The first two elements are fixed:

```txt
arr1 = [nums[0]]
arr2 = [nums[1]]
```

For every remaining element:

- Compare the last element of `arr1` with the last element of `arr2`.
- If `arr1`'s last element is greater, append the current element to `arr1`.
- Otherwise, append it to `arr2`.

Finally, concatenate:

```txt
arr1 + arr2
```

and return the result.

---

### Example

```txt
nums = [5, 4, 3, 8]
```

Initial:

```txt
arr1 = [5]
arr2 = [4]
```

Process `3`:

```txt
5 > 4

arr1 = [5, 3]
arr2 = [4]
```

Process `8`:

```txt
3 > 4 → false

arr1 = [5, 3]
arr2 = [4, 8]
```

Final result:

```txt
[5, 3, 4, 8]
```

---

## 💡 Intuition

This problem is essentially a **simulation** problem.

There is no need to discover a special algorithm or optimize the decision process.

The problem already tells us exactly what to do:

```txt
Initialize two arrays
        ↓
Look at the last element of each
        ↓
Compare them
        ↓
Append current element
        ↓
Repeat
        ↓
Concatenate both arrays
```

The important detail is that we must compare the **current last elements**, not the first elements or the largest elements.

---

## 🧠 Key Observation

At every step, we only need:

```ts
arr1[arr1.length - 1]
arr2[arr2.length - 1]
```

Everything else inside the arrays is irrelevant for deciding where the next element goes.

So we can directly simulate the process using two arrays.

---

# 🛠 Approach 1 — Direct Simulation

## Idea

1. Put the first element into `arr1`.
2. Put the second element into `arr2`.
3. Start from index `2`.
4. Compare the last elements of both arrays.
5. Append the current element to the correct array.
6. Concatenate `arr1` and `arr2`.

---

## Code (TypeScript)

```ts
function resultArray(nums: number[]): number[] {
    const arr1: number[] = [];
    const arr2: number[] = [];

    arr1.push(nums[0]);
    arr2.push(nums[1]);

    for (let i = 2; i < nums.length; i++) {
        const arr1Last = arr1[arr1.length - 1];
        const arr2Last = arr2[arr2.length - 1];

        if (arr1Last > arr2Last) {
            arr1.push(nums[i]);
        } else {
            arr2.push(nums[i]);
        }
    }

    return [...arr1, ...arr2];
}
```

---

## 🧪 Dry Run

Consider:

```txt
nums = [2, 1, 3]
```

### Initial state

```txt
arr1 = [2]
arr2 = [1]
```

### Process `3`

Compare:

```txt
arr1 last = 2
arr2 last = 1

2 > 1 → true
```

Therefore:

```txt
arr1 = [2, 3]
arr2 = [1]
```

Concatenate:

```txt
[2, 3] + [1]

= [2, 3, 1]
```

---

## Why It Works

The algorithm follows the problem's rules exactly.

At every operation:

```txt
arr1Last > arr2Last
```

means the current element goes into `arr1`.

Otherwise, it goes into `arr2`.

Therefore after processing every element, both arrays contain exactly the elements they should contain.

Finally:

```ts
[...arr1, ...arr2]
```

produces the required result because the problem defines `result` as the concatenation of `arr1` followed by `arr2`.

---

## ⏱️ Complexity

Let:

```txt
n = nums.length
```

We process every element once:

```txt
Time: O(n)
```

The two arrays together contain all `n` elements:

```txt
Space: O(n)
```

The final spread operation also takes `O(n)` time, so the overall complexity remains:

```txt
Time:  O(n)
Space: O(n)
```

---

## 🏆 Final Recommendation

The direct simulation is the correct and preferred solution.

There is no meaningful need for:

- Sorting
- Hash Maps
- Stacks
- Queues
- Two pointers
- Greedy optimization
- Dynamic Programming

The problem explicitly describes a deterministic process, so the best approach is simply to **simulate that process cleanly**.

### Key Takeaways

- When the problem gives an explicit sequence of operations, first consider **simulation**.
- Only store the information required for the next decision.
- Here, we only need the **last element** of each array for comparison.
- Don't over-engineer an Easy problem when a direct `O(n)` simulation is already optimal.
