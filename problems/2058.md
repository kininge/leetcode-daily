# 🧩 Problem #2058 – Find the Minimum and Maximum Number of Nodes Between Critical Points

**Difficulty:** Medium  
**Topics:** `Linked List`  
**Link:** https://leetcode.com/problems/find-the-minimum-and-maximum-number-of-nodes-between-critical-points/

---

## 📝 Problem Summary

A node in a linked list is a **critical point** if it is either:

- A local maximum: greater than both its previous and next nodes.
- A local minimum: smaller than both its previous and next nodes.

The first and last nodes cannot be critical points because they don't have both a previous and next node.

We need to return:

```txt
[minDistance, maxDistance]
```

where:

- `minDistance` = minimum distance between any two critical points.
- `maxDistance` = maximum distance between any two critical points.

If there are fewer than two critical points:

```txt
[-1, -1]
```

---

### Example

```txt
nums = [5,3,1,2,5,1,2]
```

Critical points:

```txt
index 2 → local minimum
index 4 → local maximum
index 5 → local minimum
```

Distances:

```txt
2 → 4 = 2
4 → 5 = 1
2 → 5 = 3
```

Therefore:

```txt
minDistance = 1
maxDistance = 3
```

Answer:

```txt
[1, 3]
```

---

## 💡 Intuition

The first step is to identify the critical points while traversing the linked list.

For a node to be critical, we need three values:

```txt
previous → current → next
```

A critical point satisfies either:

```txt
previous < current > next
```

or:

```txt
previous > current < next
```

Once we know the indices of critical points, the distance calculation becomes an index problem.

---

## 🧠 Key Observation

Suppose the critical points are:

```txt
c1, c2, c3, c4
```

### Minimum distance

The minimum distance must occur between **adjacent critical points**:

```txt
c2 - c1
c3 - c2
c4 - c3
```

There is no need to compare non-adjacent points because:

```txt
c3 - c1 > c2 - c1
```

and similarly for other non-adjacent pairs.

So we only need to track the distance from the **previous critical point**.

---

### Maximum distance

The maximum distance is always between:

```txt
first critical point
        ↓
        ...
        ↓
last critical point
```

Therefore:

```txt
maxDistance = lastCritical - firstCritical
```

This means we don't need to store every critical point.

We only need:

```txt
firstCritical
previousCritical
minDistance
```

---

# 🛠 Approach 1 — Store All Critical Points

## Idea

The straightforward approach is:

1. Traverse the linked list.
2. Detect every critical point.
3. Store its index in an array.
4. Calculate:
   - Minimum distance between adjacent critical points.
   - Maximum distance between first and last critical points.

This was my **first solution**.

---

## Code (TypeScript)

```ts
function nodesBetweenCriticalPoints(
    head: ListNode | null
): number[] {
    const criticalPoints: number[] = [];

    let previousNodeVal: number | null = null;
    let node: ListNode | null = head;
    let index = 0;

    while (node && node.next) {
        const currentVal = node.val;

        if (previousNodeVal !== null) {
            const nextVal = node.next.val;

            const isLocalMax =
                previousNodeVal < currentVal &&
                currentVal > nextVal;

            const isLocalMin =
                previousNodeVal > currentVal &&
                currentVal < nextVal;

            if (isLocalMax || isLocalMin) {
                criticalPoints.push(index);
            }
        }

        previousNodeVal = currentVal;
        node = node.next;
        index++;
    }

    const n = criticalPoints.length;

    if (n < 2) {
        return [-1, -1];
    }

    const maxDistance =
        criticalPoints[n - 1] - criticalPoints[0];

    let minDistance = maxDistance;

    for (let i = 1; i < n; i++) {
        const distance =
            criticalPoints[i] - criticalPoints[i - 1];

        minDistance = Math.min(
            minDistance,
            distance
        );
    }

    return [minDistance, maxDistance];
}
```

---

## ⏱️ Complexity

Let:

```txt
n = number of nodes
c = number of critical points
```

Linked-list traversal:

```txt
O(n)
```

Processing the critical-point array:

```txt
O(c)
```

Since:

```txt
c <= n
```

overall:

```txt
Time: O(n)
Space: O(c)
```

---

## 🔧 Improvement

The first solution stores:

```txt
[c1, c2, c3, c4, ...]
```

But do we really need all of them?

For minimum distance, we only need:

```txt
previous critical point
current critical point
```

For maximum distance, we only need:

```txt
first critical point
last critical point
```

Therefore we can process the answer while traversing the linked list.

This removes the need for the `criticalPoints` array.

# 🚀 Approach 2 — One Pass With Constant Extra Space

## Idea

Maintain three pieces of state:

```txt
firstCritical
previousCritical
minDistance
```

Whenever we discover a critical point at index `i`:

### First critical point

If this is the first one:

```txt
firstCritical = i
previousCritical = i
```

### Every later critical point

Calculate:

```txt
i - previousCritical
```

and update:

```txt
minDistance
```

Then:

```txt
previousCritical = i
```

At the end:

```txt
maxDistance =
    previousCritical - firstCritical
```

because `previousCritical` is now the last critical point.

---

## Code (TypeScript)

```ts
function nodesBetweenCriticalPoints(
    head: ListNode | null
): number[] {
    let previousNode: ListNode | null = null;
    let current: ListNode | null = head;

    let index = 0;

    let firstCritical = -1;
    let previousCritical = -1;
    let minDistance = Infinity;

    while (current && current.next) {
        if (previousNode !== null) {
            const prev = previousNode.val;
            const curr = current.val;
            const next = current.next.val;

            const isCritical =
                (curr > prev && curr > next) ||
                (curr < prev && curr < next);

            if (isCritical) {
                if (firstCritical === -1) {
                    firstCritical = index;
                } else {
                    const distance =
                        index - previousCritical;

                    minDistance = Math.min(
                        minDistance,
                        distance
                    );
                }

                previousCritical = index;
            }
        }

        previousNode = current;
        current = current.next;
        index++;
    }

    // Fewer than two critical points.
    if (
        firstCritical === -1 ||
        firstCritical === previousCritical
    ) {
        return [-1, -1];
    }

    const maxDistance =
        previousCritical - firstCritical;

    return [minDistance, maxDistance];
}
```

```txt
[5,3,1,2,5,1,2]
```

Indexes:

```txt
index:  0  1  2  3  4  5  6
value:  5  3  1  2  5  1  2
```

### Index 2

```txt
3 > 1 < 2
```

Critical point.

Set:

```txt
firstCritical = 2
previousCritical = 2
```

---

### Index 4

```txt
2 < 5 > 1
```

Critical point.

Distance from previous critical point:

```txt
4 - 2 = 2
```

Update:

```txt
minDistance = 2
previousCritical = 4
```

### Index 5

```txt
5 > 1 < 2
```

Critical point.

Distance:

```txt
5 - 4 = 1
```

Update:

```txt
minDistance = 1
```



## ⚠️ Small Bug / Coding Practice From My Solution

My original code used:

```ts
if (previousNodeVal)
```

This works under the current constraints because:

```txt
Node.val >= 1
```

But it is better to write:

```ts
if (previousNodeVal !== null)
```

Why?

Because in JavaScript/TypeScript:

```txt
0
```

is falsy.

If the problem allowed node values of `0`, then:

```ts
if (previousNodeVal)
```

could incorrectly skip valid comparisons.

So the safer rule is:

```txt
Checking whether a value exists
        ↓
Use an explicit null/undefined check
```

rather than relying on truthiness.

## Why Approach 2 Is Better

Approach 1 remembers every critical point:

```txt
[c1, c2, c3, c4, ...]
```

Approach 2 compresses this information into only:

```txt
first critical
previous critical
minimum distance
```

That's enough to calculate the complete answer.

This is a useful optimization pattern:

```txt
Store everything
      ↓
Ask what information the final answer actually needs
      ↓
Keep only that information
      ↓
Process in one pass
```

## 🏆 Final Recommendation

The **one-pass constant-space solution** is the better implementation.

The key observation is:

```txt
Minimum distance
    ↓
Only adjacent critical points matter

Maximum distance
    ↓
Only first and last critical points matter
```

Therefore there is no reason to store every critical point.

The final state is only:

```txt
firstCritical
previousCritical
minDistance
```

and the answer can be produced in a single traversal.

---

## 🏆 Key Takeaways

- A critical point requires both a previous and next node.
- Local maximum:

```txt
previous < current > next
```

- Local minimum:

```txt
previous > current < next
```

- Minimum distance only needs **adjacent critical points**.
- Maximum distance only needs the **first and last critical points**.
- If the answer can be derived from a small amount of running state, don't store the entire history.
- This is a useful **state compression / streaming** pattern.
- Be careful with JavaScript truthiness; use `!== null` when `0` could be a valid value.

---

## 📚 Pattern Learned

### Pattern: Streaming State Compression

When processing a sequence, first ask:

> "Do I really need to store every previous result?"

If the final answer only requires:

```txt
first
previous
current
running answer
```

then process everything in one pass with:

```txt
O(1) extra space
```

For this problem:

```txt
All critical points
       ↓
Only keep:
first critical
previous critical
minimum distance
       ↓
O(n) time + O(1) space
```
