# 🧩 Problem #1352 – Product of the Last K Numbers

**Difficulty:** Medium  
**Topics:** `Design`, `Prefix`, `Array`, `Math`  
**Link:** https://leetcode.com/problems/product-of-the-last-k-numbers/

---

## 📝 Problem Summary

Design a data structure that supports two operations:

- `add(num)` — append an integer to the stream.
- `getProduct(k)` — return the product of the last `k` integers.

The follow-up asks us to implement both operations in **O(1)** time.

---

## 💡 Core Insight

Instead of storing the original numbers and multiplying the last `k` numbers every time, we can maintain a **running product**.

Similar to Prefix Sum:

\[
prefixSum[i] = prefixSum[i-1] + nums[i]
\]

We can maintain a Prefix Product:

\[
prefixProduct[i] = prefixProduct[i-1] \times nums[i]
\]

Then, the product of a range can be obtained using division.

\[
\boxed{
Product(l,r)=\frac{prefixProduct[r]}{prefixProduct[l-1]}
}
\]

This allows us to calculate the product of the last `k` numbers in O(1).

### The zero problem

Multiplication by zero destroys the cumulative product:

```text
Numbers:        3, 0, 2, 5, 4
Prefix Product: 3, 0, 0, 0, 0
```

We cannot use division when the denominator is zero.

Instead, we restart our cumulative product whenever we encounter zero.

```text
Numbers:        3, 0, 2, 5, 4
Prefix Product: 3, 0, 2, 10, 40
```

The zero acts as a boundary separating independent product segments.

---

## 🎯 Pattern Recognition

This problem resembles Prefix Sum problems because:

- We maintain an accumulated value while processing the stream.
- A range query is calculated using two accumulated values.
- We avoid traversing the range for every query.

However, instead of subtraction, we use division.

| Prefix Sum | Prefix Product |
|---|---|
| Accumulate using addition | Accumulate using multiplication |
| Range sum = `prefix[r] - prefix[l-1]` | Range product = `prefix[r] / prefix[l-1]` |
| Zero doesn't break the calculation | Zero breaks division |
| No special handling required | Reset cumulative product after zero |

## 🚀 Evolution of Thought Process

### Approach 1 — My February 14, 2025 Solution

Initially, I stored all numbers and multiplied the last `k` elements whenever `getProduct(k)` was called.

```typescript
class ProductOfNumbers {
    constructor() {
        this.nums = [];
    }

    add(num) {
        this.nums.push(num);
    }

    getProduct(k) {
        let prod = 1;

        for (let i = 1; i <= k; i++) {
            const index = this.nums.length - i;

            if (index < 0) break;

            prod *= this.nums[index];

            if (prod === 0) break;
        }

        return prod;
    }
}
```

### Why this works

We traverse backwards from the most recently added number and multiply until we have processed `k` elements.

If we encounter zero, the product is already zero, so we can stop early.

### Complexity

- `add(num)` → O(1)
- `getProduct(k)` → O(k)
- Space → O(n)

The problem is that repeated queries can repeatedly traverse the same numbers.

---

### Approach 2 — My First Improvement

I introduced `lastZeroIndex` to avoid unnecessary multiplication when the requested range contained zero.

However, I was still traversing the numbers individually to calculate the product.

```typescript
class ProductOfNumbers {
    private nums: number[];
    private lastZeroIndex: number;

    constructor() {
        this.nums = [];
        this.lastZeroIndex = -1;
    }

    add(num: number): void {
        this.nums.push(num);

        if (num === 0) {
            this.lastZeroIndex = 1;
        } else {
            if (this.lastZeroIndex !== -1) {
                this.lastZeroIndex += 1;
            }
        }
    }

    getProduct(k: number): number {
        if (this.lastZeroIndex !== -1 &&
            this.lastZeroIndex <= k) {
            return 0;
        }

        const n = this.nums.length;
        let product = this.nums[n - 1];

        for (let i = n - 2; i >= n - k; i--) {
            product *= this.nums[i];
        }

        return product;
    }
}
```

### Improvement

I could detect when a zero existed in the requested range and immediately return zero.

### Remaining problem

Even when the range didn't contain zero, I was still multiplying `k` numbers.

Therefore:

\[
getProduct(k)=O(k)
\]

I needed to eliminate the loop.

### Approach 3 — Prefix Product (Final Solution)

Instead of storing the original number, store the cumulative product of the current non-zero segment.

For example:

```text
add(3)
add(2)
add(5)
add(4)
```

The array becomes:

```text
Numbers:        3, 2, 5, 4
Prefix Product: 3, 6, 30, 120
```

Now consider:

```text
getProduct(2)
```

The last two numbers are `5` and `4`.

Instead of multiplying:

```text
5 × 4
```

We calculate:

```text
120 / 6 = 20
```

Where:

- `120` = product including the last `k` numbers.
- `6` = product excluding the last `k` numbers.

---

## 🔍 Detailed Reasoning

### 1. Included Product

The last element of the array represents the cumulative product up to the current position.

```typescript
const includedProduct = this.nums[n - 1];
```

It represents:

\[
a_1 \times a_2 \times \cdots \times a_n
\]

---

### 2. Excluded Product

To obtain the product of the last `k` numbers, we need to remove the product of all preceding numbers.

```typescript
const excludedProduct = this.nums[n - k - 1];
```

It represents:

\[
a_1 \times a_2 \times \cdots \times a_{n-k}
\]

---

### 3. Divide Them

\[
\boxed{
ProductLastK =
\frac{includedProduct}{excludedProduct}
}
\]

The earlier elements cancel mathematically.

## 🧠 Zero Handling

We maintain:

```typescript
private zeroIndex: number;
```

Despite the name, this variable represents the **distance from the current end of the stream to the most recent zero**, rather than the actual array index.

### Example

```text
add(3)
add(0)
add(2)
add(5)
add(4)
```

The distance evolves:

| Operation | Distance from last zero |
|---|---:|
| `add(3)` | -1 |
| `add(0)` | 1 |
| `add(2)` | 2 |
| `add(5)` | 3 |
| `add(4)` | 4 |

For a query of size `k`:

```typescript
if (zeroIndex !== -1 && zeroIndex <= k) {
    return 0;
}
```

If the distance to the most recent zero is less than or equal to `k`, then the requested range includes that zero.

Otherwise, the requested range is entirely within the current non-zero segment.

## 🧩 Final Solution — TypeScript

```typescript
class ProductOfNumbers {
    private nums: number[];
    private zeroIndex: number;

    constructor() {
        this.nums = [];
        this.zeroIndex = -1;
    }

    add(num: number): void {
        if (num === 0) {
            this.nums.push(0);
            this.zeroIndex = 1;
        } else {
            // Carry forward the cumulative product.
            const n = this.nums.length;
            const lastProduct = n === 0 ? 1 : this.nums[n - 1];

            if (lastProduct === 0) {
                this.nums.push(num);
            } else {
                this.nums.push(lastProduct * num);
            }

            if (this.zeroIndex !== -1) {
                this.zeroIndex += 1;
            }
        }
    }

    getProduct(k: number): number {
        // The requested range contains the most recent zero.
        if (this.zeroIndex !== -1 && this.zeroIndex <= k) {
            return 0;
        }

        const n = this.nums.length;

        const includedProduct = this.nums[n - 1];
        const excludedProduct = this.nums[n - k - 1];

        // The query includes the entire current product segment.
        if (n === k) {
            return includedProduct;
        }

        // The excluded prefix belongs to a previous zero-separated segment.
        if (excludedProduct === 0) {
            return includedProduct;
        }

        return includedProduct / excludedProduct;
    }
}
```

---

## ⚖️ Correctness

### Case 1 — The Requested Range Contains Zero

If the most recent zero is within the last `k` numbers, then the requested product must be zero.

The `zeroIndex <= k` condition detects this and returns zero immediately.

### Case 2 — The Requested Range Does Not Contain Zero

All numbers in the requested range belong to the current non-zero segment.

Let:

\[
P_n = a_1a_2\cdots a_n
\]

and:

\[
P_{n-k}=a_1a_2\cdots a_{n-k}
\]

Then:

\[
\frac{P_n}{P_{n-k}}
=
\frac{a_1a_2\cdots a_n}
{a_1a_2\cdots a_{n-k}}
\]

The common prefix cancels:

\[
\boxed{
a_{n-k+1}a_{n-k+2}\cdots a_n
}
\]

Therefore, the algorithm returns the correct product.

## ⏱️ Complexity Analysis

### `add(num)`

- Array append: O(1) amortized.
- Cumulative product calculation: O(1).
- Zero-distance update: O(1).

**Time: O(1) amortized**

### `getProduct(k)`

- Zero check: O(1).
- Array access: O(1).
- Division: O(1).

**Time: O(1)**

### Space

We store one cumulative product per stream element.

**Space: O(n)**

## 🏆 Key Takeaways

1. Prefix Sum is not the only prefix technique. Prefix Product can also solve range queries.
2. A range product can be calculated using division of cumulative products.
3. Zero is special because it destroys the ability to divide cumulative products.
4. We can restart the cumulative product after every zero instead of resetting the entire data structure.
5. The most recent zero acts as a boundary between independent segments.
6. A query can be answered in O(1) by checking whether it crosses the zero boundary and then dividing two cumulative products.
7. The important optimization was not avoiding multiplication—it was **precomputing the multiplication so the query doesn't need to perform it again**.

## 📚 Pattern Learned

**Prefix Product + Segment Reset**

Use this pattern when:

- You need repeated range-product queries.
- The stream supports appending elements.
- Multiplication is invertible for non-zero elements.
- Zero requires special handling.
