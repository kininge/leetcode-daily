# 🧩 Problem #3310 - Remove Methods From Project

**Difficulty:** Medium  
**Topics:** `Graph`, `Depth First Search`.  
**Link:** https://leetcode.com/problems/remove-methods-from-project/description.  

---

## 💡 Intuition

At first glance, it feels like a **Union Find** problem because we need to identify all methods related to the buggy method.

However, the key phrase is:

> Method `a` **invokes** method `b`.

This is a **directed relationship**.

The problem is asking for **all methods reachable from `k`**, not all methods in the same connected component.

Therefore, Union Find is **not** appropriate because it ignores edge directions.

Instead:

1. Perform a DFS from the buggy method `k`.
2. Mark every reachable method as **suspicious**.
3. Verify whether any method **outside** the suspicious set invokes a suspicious method.
4. If such an invocation exists, **nothing can be removed**.
5. Otherwise, remove the entire suspicious group.

# 🔍 Key Observation

The problem **does not** ask

```text
Can this suspicious node be removed?
```

Instead it asks

```text
Can the entire suspicious group be removed?
```

This is an **all-or-nothing** condition.

If **one** outside method invokes **any** suspicious method,

then **none** of the suspicious methods may be removed.

# ✅ Solution

```ts
function remainingMethods(n: number, k: number, invocations: number[][]): number[] {
    const graph = new Array(n).fill(null);

    // Build adjacency list
    for (const [from, to] of invocations) {
        if (graph[from]) {
            graph[from].push(to);
        } else {
            graph[from] = [to];
        }
    }

    const suspicious = new Set<number>();

    function DFS(node: number): void {
        if (suspicious.has(node)) return;

        suspicious.add(node);

        const children = graph[node] ?? [];

        for (const child of children) {
            DFS(child);
        }
    }

    DFS(k);

    // Check whether an outside method invokes
    // any suspicious method.
    let hasOutsideInvocation = false;

    for (const [from, to] of invocations) {
        if (!suspicious.has(from) && suspicious.has(to)) {
            hasOutsideInvocation = true;
            break;
        }
    }

    const remaining: number[] = [];

    for (let i = 0; i < n; i++) {
        if (hasOutsideInvocation) {
            remaining.push(i);
        } else if (!suspicious.has(i)) {
            remaining.push(i);
        }
    }

    return remaining;
}
```

---

# ⚖️ Why It Works

DFS guarantees that every method

```text
reachable from k
```

is marked suspicious.

The only remaining requirement is

```text
No outside method

↓

invokes

↓

a suspicious method.
```

Scanning every edge verifies exactly this condition.

If any violating edge exists,

removing the suspicious group would leave a dangling invocation,

so nothing may be removed.

Otherwise,

the entire suspicious group can safely be removed.

# 🏆 Key Takeaways

✅ "Invokes" immediately implies a **directed graph**.

✅ Reachability problems are solved using **DFS/BFS**, not Union Find.

✅ Sometimes we first discover a group, then validate whether the group satisfies a global condition.

✅ The removal condition applies to the **entire suspicious group**, not to individual methods.

# 📚 Pattern Learned

## Reachable Set + Boundary Validation

Whenever a problem asks:

- Find every reachable node
- Form a group
- Remove/accept the group only if no forbidden edges cross its boundary

Think

```text
DFS / BFS

↓

Reachable Set

↓

Validate Boundary

↓

Accept or Reject Entire Group
```

# 🧭 Pattern Recognition Handbook

| Pattern | Trigger Keywords | When to Use | When NOT to Use | Complexity | Notes |
|----------|------------------|-------------|-----------------|------------|-------|
| DFS / BFS Reachability | Reachable, invokes, dependencies, directed graph | Need all nodes reachable from a source | Connectivity without direction | **O(V+E)** | Standard graph traversal |
| Reachable Set + Boundary Validation | Remove group, dependency graph, outside references | Discover a group first, then validate incoming/outgoing edges | Independent per-node decisions | **O(V+E)** | Useful in dependency analysis |
| Union Find | Connected component, undirected graph | Connectivity queries in undirected graphs | Directed reachability | **O(α(n))** per operation | Ignores edge direction |
