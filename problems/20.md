# 🧩 Problem #20 – Valid Parentheses

**Difficulty:** Easy
**Topics:** String, Stack
**Link:** https://leetcode.com/problems/valid-parentheses/

---

## 📝 Problem Summary

Given a string containing only `()`, `{}`, and `[]`, determine whether the brackets are valid.

A valid string must satisfy:

1. Every opening bracket has a matching closing bracket.
2. Brackets must close in the correct order.
3. A closing bracket must correspond to the most recently opened unmatched bracket.

Examples:

* `()` → `true`
* `()[]{}` → `true`
* `(]` → `false`
* `([])` → `true`
* `([)]` → `false`

---

## 💡 Core Insight

The important part of this problem is **not just counting brackets**.

We need to remember the **order in which opening brackets appeared**.

For example:

`([)]`

The counts are balanced:

* `(` has one opening and one closing
* `[` has one opening and one closing

But the string is invalid because `)` tries to close `(` while `[` is still open.

So we need to remember:

> **Which opening bracket was opened most recently?**

This is exactly the behavior of a **Stack (LIFO)**.

* Opening bracket → push it
* Closing bracket → compare it with the top of the stack
* If it matches → pop
* If it doesn't match → invalid

---

## 🎯 Pattern Recognition

Whenever a problem says something like:

> "The most recently opened thing must be closed first."

Think:

**LIFO → Stack**

Parentheses are a classic example.

For:

`{[()]}`

The opening order is:

`{ → [ → (`

The closing order must therefore be:

`) → ] → }`

That's exactly what a stack gives us.

## 🚀 Evolution of Thought Process

### Attempt 1 — Counters

Today's attempted approach used three counters:

* `bracket1` for `()`
* `bracket2` for `{}`
* `bracket3` for `[]`

The idea was:

> If every counter ends at zero, all brackets are balanced.

This works for simple cases such as:

`([{}])`

But it misses an important requirement: **ordering**.

Consider:

`([)]`

Counters eventually become:

`(` → `bracket1 = 1`

`[` → `bracket3 = 1`

`)` → `bracket1 = 0`

`]` → `bracket3 = 0`

So the counters say everything is balanced.

But the string is invalid.

Why?

When we encountered `)`, the most recently opened bracket was `[`, not `(`.

The counters have no way to remember that.

---

### Another counterexample

Consider:

`) (`

The counters end at zero:

`bracket1 = 0`

But the string is obviously invalid because the first character is a closing bracket.

Again, counts alone are insufficient.

---

### Attempt 2 — Stack

The old solution naturally preserves the missing information.

The stack remembers the sequence of currently unmatched opening brackets.

For:

`([)]`

Stack evolution:

`(` → `[(`

`[` → `[(`

`)` → top is `[`, but `)` expects `(` → invalid

This is exactly the information the counter solution lost.

---

## 🔍 Detailed Reasoning

For every character:

### 1. Opening bracket

If the character is:

`(`, `[`, or `{`

push it onto the stack.

Example:

`([`

Stack:

`[ (, [ ]`

---

### 2. Closing bracket

If the character is:

`)`, `]`, or `}`

look at the top of the stack.

The closing bracket must match the most recently opened bracket.

For example:

`(` → `)`

or:

`[` → `]`

or:

`{` → `}`

If it matches, remove the opening bracket with `pop()`.

If it doesn't match, the string is invalid.

---

### 3. Final check

After processing the complete string:

If the stack is empty:

`stack.length === 0`

then every opening bracket was successfully matched.

Otherwise, some opening brackets were never closed.

---

## 🧪 Dry Run

Input:

`"([])"`

Start:

`stack = []`

### Character: `(`

Opening bracket → push.

`stack = [(]`

### Character: `[`

Opening bracket → push.

`stack = [(, []`

### Character: `]`

Top is `[`.

`[` matches `]` → pop.

`stack = [(]`

### Character: `)`

Top is `(`.

`(` matches `)` → pop.

`stack = []`

End:

`stack.length === 0`

Result:

`true`

---

### Invalid example

Input:

`"([)]"`

### `(`

`stack = [(]`

### `[`

`stack = [(, []`

### `)`

Top is `[`.

But `)` requires `(`.

Mismatch → invalid.

This is the critical reason a stack is required.

## 🧩 Approach 1 — My Solution

Your original solution:

```ts
function isValid(s: string): boolean {
    const stack = [];
    for(const b of s){
        let topOfStack = "";
        if(stack.length > 0) { 
            topOfStack = stack[stack.length-1];
        }

    if(b === ")" && topOfStack === "(") stack.pop();
    else if(b === "]" && topOfStack === "[") stack.pop();
    else if(b === "}" && topOfStack === "{") stack.pop();
    else stack.push(b);
}

return stack.length === 0;

}; 
```

### Why it works

The important behavior is:

```text
Opening bracket → push
Matching closing bracket → pop
Invalid closing bracket → eventually leaves an unmatched bracket
```

The stack's top represents the **most recently opened unmatched bracket**.

Therefore, the stack directly models the nesting requirement.

### One subtle detail

Your code does not explicitly return `false` when a closing bracket doesn't match.

Instead, it executes:

`else stack.push(b)`

For example:

`([)]`

When `)` is encountered while `[` is on top:

* `)` does not match `(`
* `)` does not match `]`
* `)` does not match `}`

So your code pushes `)` onto the stack.

That eventually makes the stack non-empty, causing:

`return stack.length === 0`

to return `false`.

So **your implementation is correct**, even though the invalid case is detected indirectly.

---

## ⚖️ Correctness

The key invariant is:

> At every point in the iteration, the stack contains the opening brackets that have been encountered but have not yet been correctly closed, in their original nesting order.

When a closing bracket appears, it can only be valid if it matches the stack's top.

Therefore:

* Matching pair → remove the opening bracket.
* Wrong closing bracket → it cannot correctly close the current top.
* Remaining stack at the end → some brackets were never closed.

If the stack is empty at the end, all brackets were matched in the correct order.

---

## ⏱️ Complexity Analysis

**Time:** O(n)

Each character is processed once.

Each bracket is pushed at most once and popped at most once.

Therefore total work is linear.

**Space:** O(n)

In the worst case, the string contains only opening brackets:

`"((((((("`

The stack can contain all `n` characters.

---

## 🏆 Key Takeaways

1. **Balanced counts are not enough when ordering matters.**
2. `([)]` is the classic counterexample to a counter-based solution.
3. If the **most recently opened item must be handled first**, think **Stack / LIFO**.
4. For parentheses:

   * opening → push
   * closing → check top + pop
5. Your old stack solution is conceptually correct.
6. The counter approach was not merely missing an edge case — it was missing the **information required by the problem**.
7. The stack itself stores the nesting structure, which is why it fits the problem naturally.

## 📚 Pattern Learned

### Stack for Nested Structures

Whenever you see:

* Parentheses
* Nested expressions
* Matching opening/closing symbols
* Undo behavior
* "Most recent unfinished item must be handled first"

consider a **Stack**.

The reusable mental model is:

> **Open → remember it.
> Close → validate against the most recently remembered item.**
